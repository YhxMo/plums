# 安装交稿检查页面

[页面契约](PAGES.md) · [SDK 作者入口](SDK-AUTHORING.md) · [接入证据](../evidence/INDEPENDENT-PAGES-2026-10-16.md)

交稿检查用于粘贴自己的文本、查看字数和格式提示，再手动核对交稿清单。它由两份可信 ESM 扩展组成，通过工作台公开的页面服务接入，不加入默认启用集合。

## 从普通入口安装

从源码执行 `npm run dev` 或 `npm run build`，四份 `extensions/examples/local-*.js` 会作为同源静态资源提供。当前普通 release 包也包含这四份资源，仍须从普通安装入口启用。

1. 应用菜单 → 扩展管理，启用 `ui.workbench-board`，确认其隔离状态读写权限。
2. 点击“安装扩展”，填写 ID `example.local-text-node` 和模块路径 `/examples/local-text-node.js`，加载后启用。
3. 同样安装并启用 `example.local-proof-pages`，模块路径为 `/examples/local-proof-pages.js`。
4. 返回工作区，从工作台页面导航打开“交稿检查”。

两份扩展自身无需平台权限；页面扩展依赖 `text-workbench.pages@1` 与 `example.local-text.node@1`。反序启用会等待依赖；依赖齐备后自动激活。辅助文件 `local-proof-ui.js` 和 `local-proof-types.js` 不单独安装。扩展自己的 DOM、交互、文本模型与节点服务均保留在扩展层。

## 检查文本与清单

点击“填入检查示例”，得到 16 个 Unicode 码点、10 个非空白码点、3 个非空行、2 段；第 2 行有行尾空白，第 2、4 行有待补标记。计数包含原始换行，按码点计算，不是字素簇或词数；行界限支持 CRLF、CR、LF。输入最多 64,000 个 UTF-16 代码单元，发现列表最多显示前 60 条并报告总数。

检查提示包含行尾空白、TODO/TBD/“待补”和相邻重复非空行。三项人工清单在文本改变后重置。文本始终按纯文本显示，不执行 HTML，也不调用网络。

文本与勾选只在节点扩展的当前激活周期保留。切换页面和单独重启页面容器可保留；停用节点提供者、重建其生命周期或重启应用后清空。本例不读写工作台业务数据，也不使用平台持久化。

## 验证动态页面和冲突

每页的实验操作可登记三份共享 `local-proof-review` 路由的贡献：

| 添加顺序或操作 | 可见获胜贡献 |
| --- | --- |
| 添加 Z（0） | `example.local-proof.z` |
| 再添加 A（0） | `example.local-proof.a`，同级按 ID 排序 |
| 再添加高优先级（10） | `example.local-proof.priority` |
| 在当前页移除当前贡献 | 先回退 A，再回退 Z |
| 移除最后一份额外贡献 | 路由消失，工作台回退并保留缺失偏好提示 |

反序添加 A/Z 仍由 A 获胜。主页面 `local-proof` 一直可用，可重新添加额外贡献。工作台负责展示导航和冲突诊断；扩展只调用公开页面服务的 `register` 及返回的移除函数。

“刷新节点清理计数”读取节点扩展自己的诊断。仅本例的一个页面挂载时，稳定状态应为活跃节点 1、订阅 1；切到其他工作台页面再返回，挂载和清理累计增加，活跃值保持 1。浏览器回归还保留旧按钮引用，验证离页后其监听已释放。

## 停用、恢复与失败

停用节点提供者会使页面容器等待依赖，移除其全部页面，工作台其他页面与管理入口仍可用。重新启用节点提供者后，只重新登记主页面，并建立空白文本会话。停用工作台会使页面容器等待其页面服务，外壳回退到可用布局。

“保存当前组合”可保存启用意图；重载时工作台权限仍需确认，动态额外页不会自动重新登记。已保存路由缺失时保留偏好并回退；显式选择主页面后才能替换偏好。

重复添加进入扩展自有串行队列。登记失败显示错误；移除失败锁住后续操作，保留失败，停止时不盲目重试失败句柄。节点树在 mount 内完成嵌套；按钮动态增减的是整页贡献，不在已结束的 scope 上继续挂载。

本例的独立接入、浏览器与故障替身结果见接入证据。Mac/Android 最终普通包的嵌套、动态页面及恢复见 [交付证据](../evidence/M2-NATIVE-DELIVERY-2026-10-16.md)；模拟器系统输入与 WebView 自动化分别记录，真机和其他平台仍待验。
