## 推荐修改

### 1. macOS 使用一体化顶栏

- 保留系统红绿灯与原生窗口行为，让内容延伸至标题栏区域；红绿灯、品牌和应用操作在同一顶部表面内排布，移除重复的可见窗口标题。
- 为红绿灯预留安全区域，空白区域可拖动窗口，按钮和菜单保持正常点击。保留关闭、最小化、缩放、双击标题区域及全屏行为。
- 顶部表面跟随应用深浅模式；核对首次启动、手动切换、窗口失焦和全屏进出，修复实际复现的外观错位。
- macOS 窗口配置独立处理，浏览器和 Android 继续采用各自顶部安全区域规则。技术实现先用当前 Tauri 版本的标题栏配置与窗口 API 做最小原生验证，再定具体配置。

### 2. 回退提示说明原因，并允许关闭

- 提示使用可读名称，例如“文本工作台暂不可用，已切换至 Agent 界面”；原始 ID 留在详情中。确实没有可用界面时，说明“暂无可用界面”，展示宿主恢复入口。
- 按实际状态解释“扩展未启用、依赖未就绪、需要重新授权、模块加载失败、界面挂载失败”；证据不足时保留“原因待检查”，避免把所有情况写成权限问题。
- 提供“查看原因”和关闭按钮；查看原因进入扩展管理并定位相关扩展及依赖。界面设置中保留当前状态和更改偏好的入口。
- 关闭只隐藏本次异常提示，不写入新的界面偏好，不授予权限。相同异常在当前运行期间不因普通重渲染反复出现；恢复后再次失效或原因改变时重新提示；下次冷启动仍未恢复时允许再次提示一次。
- 原界面恢复可用后沿用保存偏好；主动选择其他界面并成功保存后，才替换偏好。保存失败保留原值并给出失败反馈。
- 使用隔离配置重现“保存旧界面偏好后冷启动”和“保存组合后授权未恢复”，核对与截图相符的状态链；不靠清空配置消除提示。

### 3. 扩展管理改为独立页面

- 推荐在当前窗口内设置宿主级全页“扩展管理”，占用顶栏下的完整内容区；进入后业务区从视觉和键盘导航中隐藏。页面具有自己的标题、返回操作、安装与组合操作、扩展列表和详情。
- 现有“应用菜单→扩展管理”、空态“查看扩展”、公开 `ctx.shell.open` 入口均进入同一页；诊断入口进入该页的诊断区域。
- 仅打开管理页不卸载工作区、不停用扩展、不改变业务界面偏好；业务作用域与任务按原有规则继续。返回时恢复原页面、草稿、滚动与合理焦点；用户主动停用当前界面时，返回实际可用的回退界面。
- 安装、启停、配置、卸载保留数据、授权、文档选择、组合保存和故障诊断继续使用现有契约。启用界面扩展后在管理页显示结果，由“返回工作区”进入新界面。
- 桌面使用完整页面宽度；手机采用单列页面与详情返回。宿主管理始终可达，业务浮层不得遮挡它，隐藏的业务控件不得接受焦点。

## 视觉方向与审阅节点

沿用已批准的中性深浅色和橙色品牌，重点调整结构与信息层级。计划通过后，先用 ui-ux-pro-max 完成简要设计，再用 imagegen 生成三种可比较的关键屏；使用相同扩展数据、异常状态与屏幕尺寸，不能只更换颜色。

| 方向 | 布局 | 字体与配色表达 | 信息密度与取舍 |
| --- | --- | --- | --- |
| A · 清单与详情页（推荐） | 全页紧凑清单；点击扩展进入独立详情，返回保留清单位置；顶部统一窗口栏 | 沿用系统无衬线13–14px正文，标题适度放大；中性表面、橙色主操作 | 中等偏紧凑，易扫读10个以上扩展；完整详情多一次进入操作 |
| B · 分组卡片 | 运行中、待处理、已停用分组，桌面双列卡片、手机单列；详情在页面内展开 | 系统字体14px正文、较强标题层级；白底与浅灰分组面、少量橙色强调 | 较宽松、状态直观；列表变长，跨扩展比较较慢 |
| C · 状态总览与表格 | 顶部简洁状态总览，下方宽表格展示名称、状态、能力和操作；窄屏转换为字段列表 | 系统字体13–14px，ID与版本等元数据用等宽字体；低对比表面、状态文字配标记 | 较紧凑，便于维护与比较；技术信息更重，需控制首屏负担 |

三种方向均包含一体化 macOS 顶栏、独立管理页和可关闭提示。视觉审阅采用桌面1180×820、手机375×812；深浅外观和关键异常状态在选定方向后补齐。**先交用户选择、组合或调整，再细化组件、令牌和交互状态并开始实现。**

## 可证伪验收与失败测试

| 验收项 | 必须观察到的行为 | 失败判据／验证方式 |
| --- | --- | --- |
| 一体化窗口 | 真实 Mac 打包窗口顶部只有一套视觉栏；红绿灯不遮挡品牌、菜单或正文；拖动与系统窗口操作正常 | 深浅模式、失焦、冷启动、全屏进出出现独立色带、重叠、点击失效或不可拖动，任一即失败；保留原生关键屏和操作记录 |
| 原因与无界面恢复 | 未启用、授权等待、依赖缺失、加载/挂载失败可区分；无可用界面时仍能进入管理 | 统一假报权限、没有界面却声称已回退、恢复入口不可达，即失败；隔离状态及受控失败回归 |
| 关闭与偏好 | 点关闭后当前提示消失，相同异常不反复弹回；保存偏好与业务数据不变；新异常仍可见，恢复后原偏好重新可用 | 普通状态更新又弹回、关闭改变布局或授予权限、新问题被永久屏蔽，即失败；浏览器回归与冷启动验证 |
| 独立管理页 | 桌面与手机均使用完整内容区，所有原入口可达；业务详情浮层不会挡住管理，Tab 不进入隐藏业务 | 工作区仍被压成侧栏布局、隐藏内容可操作、浮层遮挡管理，即失败；375／768／1180／1440px实际渲染与指针／键盘回归 |
| 返回与生命周期 | 从 Agent 草稿、工作台编辑和独立页面进入管理，再返回保留上下文；打开管理不触发卸载或取消；启停仍遵循原契约 | 草稿/滚动丢失、订阅泄漏、任务被管理导航取消、返回已移除控件无后备焦点，即失败；复用生命周期覆盖并补缺失路径 |
| 原管理能力 | 安装、授权取消、启停、配置、卸载、组合保存和文档选择仍按原语义运行，停用当前界面能回退 | 管理页重构改变授权、数据保留或保存失败处理，即失败；复用既有应用流程、组合、文档与工作台回归 |
| 两端普通包 | 同源 Mac app 与 Android APK完成受影响路径；Android 系统栏、返回和安装/授权模态正常 | 仅浏览器通过或仅构建成功不能关闭本项；模拟器结果按单配置说明 |
