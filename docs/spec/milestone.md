## 第 2 级：群聊

先写执行计划，经所有者确认后再动手。计划按 [total.md 第 2 级](total.md#2-群聊)的顺序拆项，每项写清内容与完成条件，退出条件以 total.md 为准：

1. 整合包（`.plums` 改为整合包加角色卡，扩展管理按整合包分组；扩展再多时加搜索）。
2. 读取服务实际返回的用量，作为花费上限的依据。
3. 用户资料（名字与头像）与按发言者显示消息，一对一会话随之改版。
4. 群聊：多参与者会话、可替换的发言规则、群会话层执行的花费上限。

写计划前先定 total.md 列出的前置决定：消息送达与“某个 Agent 正在回复”分开、会话成员与记忆作用域、`chat@1` 的 `reply` 带会话 id。仍未定、需要所有者参与的：预算设置在界面上的位置、右侧栏放什么。

每项单独提交，先补失败测试；每项完成后审查维护成本、解耦与规范，结论写进该项最后一个提交的说明。新契约只传可复制的数据、调用一律异步（[贯穿约束](total.md#贯穿约束不堵死不当门槛)）。
