## 已批准的主要决策

以下 D1–D6 由项目维护者于 2026-10-16 批准，作为本阶段实施依据；后续如需变更范围，须重新审阅并记录。

| 决策 | 推荐方案与理由 | 可选择的调整 |
| --- | --- | --- |
| D1 验证场景 | 保留现有 Agent 会话界面作对照，新增由扩展提供的本地文本处理工作台：编辑处理项→执行／取消→结果列表与详情→再编辑。复用现有 `text.transform@1` 真实服务，避免模型、网络和新业务平台分散对 UI 可替换性的验证 | 可改选其他非聊天交互；仍须有实际输入、操作、结果和失败路径 |
| D2 替换边界 | 扩展拥有工作区整体布局、业务顶栏／侧栏、页面、导航和操作流程；宿主保留管理、授权、诊断及无可用界面时的恢复入口，并公开可调用的入口契约。原生窗口标题栏和系统栏继续由平台适配负责 | 可先做较小原型，但缩小后的结果只关闭对应子项，不能宣布完整交互替换完成 |
| D3 契约与组合 | 先核对现有 `ctx.view`、版本服务、视图树与导航助手，按真实缺口补通用机制。第二位作者通过第一位作者公开的界面契约贡献页面或面板，并至少验证一次嵌套组合和运行中停用；冻结基线后接入方无需修改内核或外壳 | 若接入确实需要改内核，记录原基线失败，修订通用契约并重新冻结，保留原失败结论 |
| D4 视觉与主题 | 默认界面保留白／中性灰主体和橙色识别，优先做好字号、留白、导航和操作层级；两份颜色主题保留为 SDK 开发样板，暂停新增配色及将它们作为推荐体验交付 | 是否继续向使用者展示主题样板、是否另做配色重设计，由审阅决定；本次不删除代码或改默认外观 |
| D5 验收与交付 | 以浏览器、Mac 打包应用、Android API36 ARM64 模拟器分别验证完整路径；将旧集成的未验项合并进最终候选验收。候选通过后才更新普通 release，旧包保持可恢复 | 可先补完旧候选的技术验收，单独记录结果；旧候选完成也不关闭本阶段交互／视觉验收 |
| D6 执行顺序 | 先交互与视觉方案，再契约与实现，再独立作者接入和两端普通包验收。先审阅关键屏和流程，可在昂贵的原生回归前发现体验方向问题 | 可先授权范围有限的交互原型，再决定完整实现；原型范围和退出条件随授权收紧 |

## 验收范围与保留条件

本阶段覆盖 A3/A5/A6/A7/A12 的指定两端主路径。265单元与15项Rust/既有检查按未变实现和输入复用，最终92浏览器及普通构建重新执行；不将不同版本测试数量拼成未执行的全套结果。独立审查未重演原生操作。

Android系统输入通过实际DocumentsUI/IME与ADB输入层注入，和WebView DOM自动化分别记录。工作台IME展开可输入/滚动到动作；首触收起IME未执行，按新布局再次触控后执行保存。真机、其他配置/WebView、完整辅助技术和其他平台仍待验。

[退出清单](../M2-EXIT-CHECKLIST.md)中的生产凭据/网络、兼容与废弃政策、升级事务、崩溃恢复、iOS最小风险实验及正式分发门槛继续有效。本阶段完成不表示稳定SDK、五端支持或M2整体退出。
