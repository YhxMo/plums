## 目标与验证思路

用**两种明显不同的交互方式**证明本体没有把交互形态写死：

- **界面甲（已有）**：`ui.agents` 提供的 Agent 会话界面——左侧列表、中间消息时间线、右侧详情，输入是聊天输入框。
- **界面乙（新增）**：由另一个扩展提供的**本地文本处理工作台**——左侧处理项列表、中间编辑与执行、下方结果列表、右侧结果详情，输入是表单字段与操作按钮，**没有消息时间线，也没有聊天输入框**。

界面乙复用已存在的真实公开服务 `text.transform@1`（`transform.upper` / `transform.reverse` 提供），不引入模型、网络或新业务平台。这样验证的焦点只在“UI 能不能被替换”，不被业务复杂度干扰。

两个界面共用同一套公开契约：视图注册 `ctx.view`、服务消费 `ctx.use`、状态与取消、导航选择 `resolveNavigation`。本体不认识“工作台”这个业务概念。

## 两种体验的页面关系

### 界面甲：Agent 会话（已有，作为对照）

```text
顶栏（宿主）│ 业务导航与页面（扩展 ui.agents）
           ├─ 列表页：我的 Agent / 全部 Agent / 特别关注
           ├─ 会话页：消息时间线 + 底部输入框
           └─ 详情层：角色说明 / 能力 / 会话 / 来源（桌面侧栏，手机模态）
```

主要操作：选择 Agent → 在输入框输入 → 发送 → 查看回复 → 打开详情。返回路径：手机从会话返回列表；详情关闭回到发起控件。

### 界面乙：文本处理工作台（新增）

```text
顶栏（宿主）│ 业务导航与页面（扩展 ui.workbench-board）
           ├─ 处理项页：全部处理项 / 已保存 / 失败（列表 + 新建）
           ├─ 编辑页：名称、输入文本、选择转换服务 → 执行 / 取消
           ├─ 结果区：本次与历史结果列表（每项含服务、时间、状态）
           └─ 结果详情：完整输入、完整输出、所用服务与来源
```

主要操作：新建或选择处理项 → 编辑输入文本 → 选择转换服务 → **执行** → 在结果列表查看 → 打开结果详情 → 可**再编辑**（回到编辑页，草稿保留）。

与聊天界面的关键差异（构成“明显不同”）：

- 没有消息时间线，也没有“发送给某人”的概念；操作是**执行 / 取消**，不是发送。
- 页面由**处理项 → 编辑 → 结果**三段构成，导航是列表与详情的关系，不是对话滚动。
- 输入是带标签的表单字段，不是单条消息输入框。
- 状态呈现为**未执行 / 执行中 / 已保存 / 失败 / 不确定**，不是“对方正在输入”。

## 关键操作路径与返回路径

| 路径       | 桌面（≥1024px）                                  | 手机（<768px）                          | 返回路径                               |
| ---------- | ------------------------------------------------ | --------------------------------------- | -------------------------------------- |
| 选择界面   | 宿主设置“界面与外观”中列出已启用界面，选中即切换 | 同（设置浮层全宽）                      | 关闭设置回到原界面                     |
| 新建处理项 | 左上“新建”按钮 → 编辑页替换右侧内容              | 列表页点“新建” → 进入编辑页（列表隐藏） | “返回”回到列表；未保存内容作为草稿保留 |
| 执行与取消 | 编辑页底部“执行”；执行中变为“取消”               | 同                                      | 取消回到编辑态，输入与已保存结果保留   |
| 查看结果   | 结果列表点击某项 → 右侧详情                      | 结果列表点击 → 详情模态（全屏浮层）     | 关闭详情回到结果列表，焦点回到所点项   |
| 再编辑     | 详情右上角“再编辑”                               | 详情底部“再编辑”                        | 进入编辑页并带入该项输入               |
| 停用扩展   | 宿主扩展管理 → 停用 → 该界面不可用               | 同                                      | 自动回退到可用界面并说明原因           |

## 宿主与扩展的边界

| 区域                                   | 归属      | 说明                                                           |
| -------------------------------------- | --------- | -------------------------------------------------------------- |
| 窗口标题栏、系统栏、明暗模式同步       | 宿主/平台 | 扩展不控制原生窗口颜色；仅跟随明暗                             |
| 顶栏品牌、平台状态、外观切换、应用菜单 | 宿主      | 公开契约不提供移除宿主管理或伪造授权的入口；菜单内含**扩展管理、应用设置、诊断、关于** |
| 界面选择入口（哪个扩展提供主界面）     | 宿主      | 用公开视图契约列出，不用业务特例                               |
| 授权确认、能力授予与撤销               | 宿主      | 扩展可请求，不能自造成功结果                                   |
| 业务导航、页面、输入、结果呈现         | 扩展      | 工作台的处理项、执行、结果列表与详情全部归扩展                 |
| 业务状态与持久化                       | 扩展      | 处理项与结果归扩展自己的状态作用域，不写入内核业务字段         |
| 无可用界面时的恢复入口                 | 宿主      | 挂载失败或全部停用时，宿主展示可操作的恢复入口                 |

硬边界（违反即判失败）：扩展界面不得依赖 `agents`、`role-settings` 等特定入口的硬编码；不得通过私有回调打开扩展管理；增加页面或面板不得要求内核新增业务槽位。

## 契约缺口（实现前必须补齐）

以下缺口来自对现有 [`modules/sdk`](../../../modules/sdk)、[`modules/extension-host`](../../../modules/extension-host) 与 [`src/App.tsx`](../../../src/App.tsx) 的核对，是**实现前核对的缺口**；本步通过可选页面助手与公开宿主入口补齐基本路径，独立作者和原生包覆盖仍分别验收：

1. **动态页面与路由**：现有 `ctx.view` 一次挂载一个视图，外壳按 `selected` 选择；工作台的“处理项 / 编辑 / 结果详情”是**同一视图内的页面切换**，需要页面标识、切换与默认页面规则。现有 `resolveNavigation` 是纯函数，只做贡献之间的确定性选择，不提供普通应用里的路由注册、历史与持久化。
2. **导航注册与持久化**：需要扩展声明自己的业务页面（ID、标题、默认页），扩展拥有业务导航，宿主只保存页面偏好并供冷启动恢复；未知页面或扩展缺失时保留原数据并给出可用入口。
3. **宿主管理入口的公开化**：`src/App.tsx` 目前通过私有回调打开扩展管理，且偏好 `agents` / `role-settings` 等特定视图 ID。需改为：任何界面扩展都能通过**公开入口契约**触发扩展管理、授权与设置，不认识特定业务 ID。
4. **动态贡献增减**：`mountViewTree` 是固定树，挂载完成后不能用同一 scope 动态挂载；运行中新增/移除页面或面板需要明确策略（登记、重挂载边界、清理归属）。
5. **输入与焦点归属**：页面切换时键盘监听、焦点、滚动位置由谁保存与恢复；手机模态详情关闭后焦点必须回到发起项。
6. **在途任务归属**：切换界面或页面时，正在执行的转换任务属于哪个作用域；本方案规定**切换前先取消并等待未提交操作结束**，已保存结果保留，不承诺后台继续执行。

以上每一项都要先写**能暴露缺口的失败用例**，再实现；不能先改内核再补测试。

## 关键屏清单（供审阅）

桌面 1440×900 与手机 375×812 各一套，深浅两种外观：

1. 工作台·列表页（空态：无处理项）
2. 工作台·列表页（有处理项：含已保存、失败、执行中）
3. 工作台·编辑页（未执行 / 执行中 / 已保存 / 失败 / 不确定）
4. 工作台·结果详情（桌面侧栏、手机模态）
5. 宿主设置·界面与外观（两个界面可切换）
6. 停用工作台扩展后的回退屏

每屏必须能区分：默认、选中、禁用、错误、焦点五种状态；长文本、超长名称、服务缺失时的呈现要有明确规则（截断而非溢出，禁用的原因可见）。

## 状态规则（工作台界面）

| 状态     | 触发                             | 界面呈现                                     | 可执行操作               |
| -------- | -------------------------------- | -------------------------------------------- | ------------------------ |
| 空闲     | 新建或已保存后未执行             | “执行”可用                                   | 执行、编辑、删除         |
| 执行中   | 调用 `text.transform` 期间       | 进度提示，“取消”可用，输入区只读             | 取消                     |
| 已保存   | 收到成功写入回执                 | 结果区出现新条目，显示所用服务               | 查看详情、再编辑         |
| 失败     | 转换抛出异常且**证明未提交**     | 错误说明可见，保留输入与草稿                 | 重试、编辑               |
| 不确定   | 写入结果未确认（`outcome` 未知） | 明确提示“结果未确认”，不谎报成功也不谎报失败 | 读取实际状态、停用后重开 |
| 服务缺失 | `text.transform` 提供者不可用    | 按现有必需依赖语义暂停工作台，外壳说明缺失原因并保留管理入口               | 前往扩展管理             |

规则沿用现有失败语义：成功回执胜出；`AbortError` 或 `not-committed` 视为未提交；其他异常按结果未确认处理。

## 视觉与输入要求

- 沿用已审阅通过的内置视觉基线：浅色白底／深色中性碳黑，品牌橙只用于主操作与关键状态；桌面紧凑排版，移动端保持至少 44 CSS px 触控目标。
- 主操作（执行）在编辑页必须是最显眼的控件；同级不得出现三个以上等权重大按钮。
- 长输入文本、超长处理项名称、超长输出必须有截断与滚动规则，不得溢出或遮挡操作。
- 键盘：Tab 顺序覆盖列表 → 编辑字段 → 执行 → 结果；焦点环可见；手机键盘弹起时输入区与“执行”仍可达。
- 触控：列表项、执行/取消、结果项均满足触控尺寸；详情关闭后焦点回到发起项。
