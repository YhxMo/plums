# 整体实现计划

[文档导航](../README.md) · [当前阶段](milestone.md) · [验收矩阵](../ACCEPTANCE.md) · [架构](../ARCHITECTURE.md)

更新日期：2026-10-26。本文只维护当前有效的产品定位、路线阶梯、约束与退出条件；执行状态见当前阶段，已交付版本与验证范围见[交付入口](../../evidence/RESULTS.md)。

## 定位

**用扩展拼出来、能像联系人一样相处的 Agent。** 用户把 Agent 当作通讯录里的人：一对一聊天、拉进群聊、让它独立做事，也能让别人加它为好友。Agent 由可替换的扩展组成（模型、记忆、发言规则、角色卡、界面……），同一套机制也承接今天没想到的用法。

可自定义是做法，把 Agent 当人是产品。路线按用户能做到什么排成阶梯，每一级都可单独交付；新能力一律做成可替换的扩展，这本身就是对扩展机制的检验。

## 目标与不变量

Plums 是可由扩展组合的通用应用本体。未预设的服务、界面、业务和扩展点应主要通过新增或组合扩展接入；默认功能与外部扩展使用相同公开契约。

- 内核承担生命周期、依赖、注册释放、平台能力、权限、凭据作用域、状态与资源契约；业务循环、模型协议、记忆、发言规则、角色卡解析与协作流程归扩展。
- UI 可替换整体布局、导航、页面和交互；停用或替换失败后，管理和恢复入口仍可达。
- 注册、任务、数据和取消有明确所有者；清理失败与未知写入回执保留真实状态，不假报成功。
- 评价接入、替换、恢复与演进成本，不以文件数、测试数或内置功能数衡量开放性。
- 角色卡先帮助人理解用途与限制，也兼作群聊与好友的名片；卡片声明不是身份验证、真实能力或操作授权。

## 平台范围：先做好 Mac 应用本体

当前唯一交付目标是 **macOS arm64**。当前版本仍是 debug 原型，未声明稳定 SDK。

- Android 冻结：Kotlin 插件、生成工程脚本、启动图标与构建文档已移出主线，恢复该平台时从 Git 历史取回并统一处理漂移；Rust 与前端中按平台编译的 Android 分支保留。0.2.0 模拟器包不随 Mac 改动重验，不声明与开发源码同源。
- iOS、Windows、Linux 尚未开始，不预先增加兼容层。通用契约不得固化 Mac 专属业务假设。
- 启动其他平台时逐平台验收（打包资源、ESM、桥接、授权、输入、离线、前后台、系统回收与资源预算）；一个平台的结果不代表另一个。
- 计划在 GitHub 发布源码与 Mac 包。许可证见 LICENSE；首次公开分发前核对第三方许可证与通知。Developer ID 与公证方式由发布决定；没有公证的下载包须提供真实可用的首次打开说明。

## 路线阶梯

每一级是一个可交付的版本，退出条件在 Mac 打包应用上以实际操作验证。下一级开工前单独写计划；前一级的契约要为后面留出位置，但不提前实现。

| 级 | 用户能做到什么 | 需要的公开契约（均由扩展实现） | 对应场景 |
| --- | --- | --- | --- |
| 1 认识你的联系人（Mac 第一版） | 和一个 Agent 一对一聊天，它跨会话记得你 | 模型连接、`memory@1` 基本版；数据从一开始记录发言者，记忆作用域分用户、Agent、联系人三层 | A5–A8、A10 |
| 2 群聊 | 把几个 Agent 拉进一个群，它们按各自性格合作、闲聊或辩论，也可以点名或禁言；一键装上一组扩展 | 整合包；多参与者会话，成员不区分真人与 Agent；发言规则由可替换扩展决定；群级花费上限；每个 Agent 只用自己的模型与记忆；角色卡作为名片 | A13，本机的 A14 |
| 3 工具与独立工作 | Agent 用工具做事，定时或被触发后自己做，主动发来消息 | 工具契约与有后果操作的确认；无界面运行的任务、执行条件、暂停、取消与重启恢复；主动消息进入会话并计未读 | A4 |
| 4 共用的 Agent | 别人按 id 加你的 Agent 为好友；真人与 Agent 混合的群；Agent 记得每个人并按明确要求转达 | id（`名字@服务器`）、好友、消息送达、服务器托管、按联系人隔离的记忆与转达；服务器连接与托管由扩展提供 | A10 扩展到服务器 |

### 1 认识你的联系人

当前任务拆分只在[当前阶段](milestone.md)维护。

- **退出条件**：最终 Mac 候选上，一对一会话完成一次获授权的真实模型调用；`memory@1` 基本版让 Agent 跨会话记住用户告诉它的事，用户能查看和删除。安装、替换、停用/卸载、一次不兼容升级被拒绝、迁移失败保留数据都有完整路径；未授权零发送，秘密不进入 WebView 回执或日志。一个没读过实现的空白会话作为作者，只凭公开文档与样板写出一个使用凭据绑定的连接器，导入最终候选并完成一次获授权的真实调用；卡点与文档缺口按 A2 记录。这是 AI 作者对文档的检验，不冒充独立人类作者验收；连接器同时作为第 2 级“不同作者的 Agent”的模型来源。Mac 键盘、触控板与中文输入法可用；许可证、安装/升级/回退说明与已知限制（含 VoiceOver 未验收）齐备；独立退出审查完成。
- **失败判据**：只能用私有 API、覆盖坏数据、升级丢失数据、清理假成功；用浏览器代替打包应用；跟随重定向或自动重试 unknown；一个 Agent 的记忆进入另一个 Agent 的上下文。

### 2 群聊

Agent 按角色卡里的性格像真人一样参与：合作完成任务、闲聊、讨论或辩论，也能被点名或禁言。本级只做本机的“你和多个 Agent”，但成员、点名与禁言的契约不区分真人与 Agent，第 4 级接上服务器后真人直接进群。按顺序：

1. **整合包**：可单独定义的一组扩展，点开能看到包含哪些。整合包有总开关，也能单独开关其中的扩展；扩展只装一份，仍被别的整合包或 Agent 使用时不关闭，卸载整合包时保留共用扩展并说明保留了哪些。整合包可带扩展的非敏感设置，从不带密钥。`.plums` 即整合包加一张角色卡，两者共用一种格式；群聊所需的扩展作为第一个整合包。界面上“扩展包”一词届时让给整合包，单个扩展的 zip 改称“扩展文件”。
2. **实际用量**：读取服务响应中实际的 token 用量（含缓存命中），不凭请求参数推断；花费上限以此为准。
3. **群聊**：Agent 可以自主发言，花费默认保守：每条新消息先用一次短调用判断谁要接话，只有要说的才生成回复；人说一句后 Agent 之间最多来回约 6 条，人再开口才重新计数；每个群有每日预算，用量在群里可见并可暂停；冷却、禁言、只在点名时发言是群设置。上限由群会话这一层执行，发言规则扩展不能越过。预算显示金额，取不到价格时显示 token 数。

- **退出条件**：不同作者的 Agent 在同一个群里按所选发言规则回复，连续发言与花费不超出群的上限；某个 Agent 失败或取消时能归属到它，不阻塞其他参与者；用户能暂停、移出参与者或接管。用户只看角色卡就能判断每个 Agent 的用途和限制（A13 先定义理解任务和通过阈值）。
- **失败判据**：内核写死某种发言循环；发言规则能绕过花费上限；单 Agent 的全局状态串扰；迟到的回复串到别的轮次；用户看不出谁在做什么。
- **前置决定**：一对一会话现在等回复成功后才把用户消息和回复一起保存（停止即撤回）。群聊先把“消息已送达”与“某个 Agent 正在生成回复”分开：消息先保存，回复是归属到某个参与者的任务，失败、取消与重启只影响该任务；同时定下会话成员与记忆作用域，并让 `chat@1` 的 `reply` 带上会话 id（服务商按会话路由与缓存，OpenCode Go 不带会话头即拒绝，见[作者检验](../../evidence/CONNECTOR-AUTHOR-2026-10-26.md)）；凭据请求是否允许按请求变化的非秘密头，等有普通服务需要再定。`agents.local` 已把消息写入规则（`sessions.ts`）与在途回复（`replies.ts`）分成两层，改语义时在这两层上进行，不在 Store 上叠加；顺带拆分超过 400 行的 `store.ts`，外壳导航（`Workbench`）为群列表改成由契约登记，不另做一次重构。

### 3 工具与独立工作

Agent 能做什么只取决于角色卡、扩展与记忆。先在一对一会话里让 Agent 使用工具，再让它不开界面地定时或被触发运行。内核只定工具的登记、调用与交回结果，有后果的操作先经用户确认（可按 Agent 与工具设为总是允许），轮数与花费沿用第 2 级的上限；MCP、文件、网页、远程服务器都是提供工具的扩展。

- **前置**：原生层能识别发起调用的扩展，启动本机程序一类能力只给声明了相应权限的扩展。这不等于隔离，市场门槛见[支持范围](#支持范围与未决项)。
- **退出条件**：Agent 在一对一会话里使用至少一个第三方扩展提供的工具，有后果的操作经确认；Agent 在声明的条件下（定时、事件）不打开界面也能工作；暂停、取消、重启后的状态可以解释；应用退出或系统回收后不显示仍在运行；未确认的外部副作用不自动重试。
- **前置验证**：扩展组合能否在无界面环境中按相同语义运行（第 4 级托管也依赖这一点）。

### 4 共用的 Agent

面向的用法包括：把自己做的角色给别人用、自己的分身或代理、服务型 Agent，以及朋友之间的 Agent 互加好友、一同进群。

- **退出条件**：两个人分别加同一个 Agent 为好友并与它对话，各自的记忆互不进入对方的上下文，由结构保证并有回归；只有明确要求转达的内容才跨人传递；主人默认只看到联系人列表和转达给自己的内容；对方离线时消息可送达。可见范围、托管位置与运营者、记忆保留方式写在角色卡上，加好友前可见。
- **前置决定**：id 格式与协议、是否联邦、托管服务器上的密钥保管与运营者可见范围、官方是否提供托管。官方服务器只负责 id、好友与送达；托管先由自建服务器扩展提供。决定时按以下取舍：
  - **契约先于后端**：内核与公开契约只有 Plums 自己的服务器连接契约；Supabase 一类托管后端、自写服务或联邦协议都只是某个服务器扩展的实现，更换后端、自建与联邦不改契约。
  - **送达与托管分开**：id、好友与离线送达是存储加推送，托管后端提供的数据库、账号、实时订阅与行级权限适合做原型。托管 Agent 要长时间运行扩展组合、调用模型并定时触发，依赖第 3 级的无界面运行时；函数计算的时长上限与运行环境无法保证相同语义，需要单独的运行时。
  - **协议候选**：Matrix 自带 `@名字:服务器` 形式的 id、联邦、离线送达、真人与机器人同在的房间和端到端加密，与本级需求重合较多；与“托管后端 + 自定协议”比较维护量、自建门槛和隐私保证后再定。
  - **运营者可见范围**：行级权限只隔离用户之间，运营者仍能读到对话和按联系人的记忆。要么端到端加密，要么在角色卡上写明运营者与保留方式；不把行级权限说成对运营者的隐私保证。
  - **自建门槛与可达性**：自建服务器扩展面向普通用户，所需服务数量与部署步骤计入取舍；官方或托管服务须在主要用户所在网络实测可达，不默认海外云区域可用。
  - **小范围试验**：先在本机用两个独立数据目录的实例跑通 id、好友与送达；邀请他人时用托管后端的免费额度，或经隧道开放本机服务，Agent 仍在主人设备上运行。只有要求主人离线也能回复时才需要常开主机，且以第 3 级无界面运行时为前提。试验只用测试账号与假数据，事先告知参与者运营者能看到什么；放在独立分支，不进主线，也不占用第 1 级的工作。

### 语音

与群聊同期或之后做，作为一种新的消息类型：用户发语音消息、Agent 用自己的嗓音回复（嗓音写在角色卡里），以及实时通话。语音输入不单独做，macOS 自带听写。听、说与通话都由扩展提供，内核只提供麦克风、播放与音频附件等平台能力及其权限。实时通话是单独的通话模式，文字聊天仍整条送达；通话同样受花费上限约束。

## 贯穿约束：不堵死、不当门槛

以下目标保持开放，新设计不得堵死它们，但不作为任何一级的退出条件：

- **整体 UI 替换与非聊天体验**（A3、A12）：页面、导航、主题与视图契约继续维护；新功能不得把聊天布局写进内核。
- **外部独立作者与未预设需求**（A1、A2）：作者文档与样板随契约更新；有外部作者时按 A2 记录原失败与通用缺口，补内核后不把新基线称为原基线通过。所有者试用不冒充独立作者验收。
- **其他平台**（A11）：见[平台范围](#平台范围先做好-mac-应用本体)。
- **扩展机制演进**（A9）：每一级只承诺已写明的安装、升级与迁移路径；破坏性变更不静默沿用原契约版本，其余兼容与废弃政策等真实作者和旧扩展出现后再定。SDK 在第 2 级的契约经过群聊检验后再考虑稳定版本。
- **可移入隔离环境**：从群聊起，新契约只传可复制的数据、调用一律异步，日后把扩展移到隔离环境运行时不必推翻契约。

## 支持范围与未决项

长期进程模型、资源预算、SDK 支持窗口与远程包管理仍需实际使用证据。远程 A2A 由后续扩展提供，不预定特定协议。

**扩展市场门槛：** 当前可信 ESM 与宿主共享 WebView，权限 UI 不构成安全沙箱。原生调用者鉴权提前到第 3 级工具之前；面向无法审查代码的普通用户开放市场前，还必须完成按扩展隔离执行、包格式、来源签名与完整性校验，以及安装/更新时的权限变化披露。

## 后续加固

以下项目仍未完成，在对应需求或发布范围变化时评估，不用现有请求库设置推断其成立：

- 直连目标的 DNS 公网地址固定与私网/回环拒绝。
- OS 证书验证器独立执行 OCSP/CRL/根获取时的联网边界；reqwest 的代理、DNS、超时策略不代表该路径。
- 显式代理的 CONNECT/DNS/失败语义；当前只保存代理配置，不经代理发送。
- 授权世代与原生进程世代的失效矩阵、受控 CA 与回执丢失/桥接挂起夹具。
- 全局并发、脱敏诊断保留政策，以及响应中原始令牌的拒绝交付。
