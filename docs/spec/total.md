# 整体实现计划

## 目标与不变量

Plums 是可由扩展组合的通用应用本体。未预设的服务、界面、业务和扩展点应主要通过新增或组合扩展接入；默认功能与外部扩展使用相同公开契约。

- 内核承担生命周期、依赖、注册释放、平台能力、权限、凭据作用域、状态与资源契约；业务循环、模型协议、角色卡解析与协作流程归扩展。
- UI 可替换整体布局、导航、页面和交互；停用或替换失败后，管理和恢复入口仍可达。
- 注册、任务、数据和取消有明确所有者；清理失败与未知写入回执保留真实状态，不假报成功。
- 评价接入、替换、恢复与演进成本，不以文件数、测试数或内置功能数衡量开放性。
- 角色卡先帮助人理解用途与限制；卡片声明不是身份验证、真实能力或操作授权。

## 平台范围：先做好 Mac 应用本体

当前唯一交付目标是 **macOS arm64**。当前版本仍是 debug 原型，未声明稳定 SDK。

- Android 代码和 0.2.0 模拟器包冻结保留；不随 Mac 改动重验，不声明与开发源码同源。恢复该平台时统一处理漂移。
- iOS、Windows、Linux 尚未开始，不预先增加兼容层。通用契约不得固化 Mac 专属业务假设。
- Mac 第一版交付且明确决定启动其他平台后，才逐平台验收。Android 真机与配置、iOS 资源/ESM/桥接/存储/生命周期最小实验是跨平台支持与稳定声明的前置条件，不阻塞仅限 Mac 的声明。
- 计划在 GitHub 发布源码与 Mac 包。项目采用 MIT；首次公开分发前核对第三方许可证与通知。Developer ID 与公证方式由发布决定；没有公证的下载包须提供真实可用的首次打开说明。

## 当前基础与缺口

已实现的契约由子系统文档维护，不在路线中复制参数和测试数字：

| 能力 | 当前基础 | 下一步 |
| --- | --- | --- |
| 生命周期与依赖 | 可信本地 ESM、精确版本、必需/可选依赖、多提供者、所有权与清理失败锁存 | 用作者反例验证安装、替换、卸载与有限升级路径 |
| 状态与组合 | 每个所属者一个 SQLite 库；修订检查、每片 1 MiB、原子批量写与可搜索记录、坏数据保留、显式单跳迁移/恢复、组合及授权自动保存 | 验证中断与兼容政策 |
| UI 与作者入口 | 公开视图、页面、导航、主题及非聊天开发样板 | 独立作者组合主路径；Mac 中文输入法、键盘与辅助技术 |
| 平台与凭据 | 原生秘密注入、固定 HTTPS 目标、发送确认、受限传输与公开网络读取 | 当前文件存储后的真实模型路径、传输未决边界与分发验收 |

## M2 子门禁

当前任务拆分只在[当前阶段](milestone.md)维护。各子门禁的通过必须有对应源码、平台和实际操作依据。

| 门禁 | 退出条件 | 失败判据 |
| --- | --- | --- |
| M2.1 契约闭合 | A1/A5/A6/A7/A9 及 A4 前台事件子集：安装、替换、停用/卸载、一次兼容/不兼容升级、迁移失败和写入中断；容量不足明确拒绝，坏数据保留 | 只能用私有 API、覆盖坏数据、升级丢失数据、清理假成功 |
| M2.2 作者与 UI 开放 | 独立作者仅凭公开入口接入非聊天体验，组合另一作者贡献；冲突、保存、重启、缺失与停用恢复可用，管理始终可达 | 仅能换色或加按钮、必须私改内核、停用后不可操作或贡献残留 |
| M2.3 平台能力 | A8/A10 的正常公开路径：原生秘密读取/注入、目标限制、授权、超时/超限/取消、未授权零发送；最终 Mac 候选有一次获授权的非流式真实调用 | 假平台代替真实路径、秘密进入 WebView 回执/日志、跟随重定向、unknown 自动重试或信任边界失真 |
| M2.4 Mac 第一版 | 以上门禁、Mac 键盘/触控板/中文输入法/VoiceOver、核心稳定与实验边界、兼容/废弃/迁移验证、许可证与安装/升级/回退说明、独立退出审查 | 用浏览器或其他平台代替实机、兼容只写承诺、遗漏分发义务、把 Mac 结论写成跨平台稳定 |

M2 不要求无限版本兼容、无中断热更新、多进程事务或完整远程包管理；已经承诺的首批安装、升级和恢复路径必须可用，未支持操作明确拒绝并保留数据。

## M3：未知需求与逐平台验收

- 固定宿主、SDK 与公开文档后，由未参与内核实现的项目外作者提出未知需求，完成安装、使用、诊断、替换/停用和复现。记录维护者帮助与通用契约缺口；内部执行者或所有者试用不替代独立作者反馈。
- 根据反例扩展提供者选择政策、长期存储/索引、文件或 OS 能力；不为抽象完整性预建机制。
- 各平台分别验证打包资源、ESM、桥接、授权、输入、离线、前后台、系统回收与资源预算；Linux 写明发行版/桌面/WebView，Windows 写明系统/WebView。
- 区分前台、暂停、检查点、恢复与不支持的长期后台行为。系统回收后不继续显示任务运行；已确认状态可恢复，未确认外部副作用不自动重试。

## M4：角色、组装与合作

1. A13 先定义人类理解任务、参与者条件和通过阈值，再检验用途、限制、来源与授权是否可理解。
2. 通过可替换扩展组合模型、工具、数据、状态和 UI；模型/MCP 适配及业务循环不进入内核。多轮、流式和工具调用逐项验证。
3. 先验证发现与联系，再验证能力匹配；身份、能力声明、实际验证和授权分别呈现，不预定 A2A 标准。
4. A14 由不同作者的参与者完成委派、交接和结果归属，明确关联 ID、取消、超时及共享数据边界；重启和迟到结果不串到新任务。
5. 人类能理解分工、进度、失败与待授权状态，并可暂停、取消或接管。

## M5：持续演进与贡献

用真实旧扩展和旧快照演练升级、拒绝、迁移与回退；破坏性变更不静默沿用原契约版本。分发说明来源、完整性、权限变化、失败恢复及卸载数据政策。诊断能定位扩展与版本，不收集秘密或正文；新需求、SDK 升级和平台变更持续接受 A1–A14 的相关反例。

## 支持范围与未决项

长期进程模型、资源预算、SDK 支持窗口与远程包管理仍需实际使用证据。多 Agent 先做应用内合作，远程 A2A 可由后续扩展提供。

**扩展市场门槛：** 当前可信 ESM 与宿主共享 WebView，权限 UI 不构成安全沙箱。面向无法审查代码的普通用户开放市场前，必须完成按扩展隔离执行、原生调用者鉴权、包格式、来源签名与完整性校验，以及安装/更新时的权限变化披露。

## 后续加固

以下项目仍未完成，在对应需求或发布范围变化时评估，不用现有请求库设置推断其成立：

- 直连目标的 DNS 公网地址固定与私网/回环拒绝。
- OS 证书验证器独立执行 OCSP/CRL/根获取时的联网边界；reqwest 的代理、DNS、超时策略不代表该路径。
- 显式代理的 CONNECT/DNS/失败语义；当前只保存代理配置，不经代理发送。
- 授权世代与原生进程世代的失效矩阵、受控 CA 与回执丢失/桥接挂起夹具。
- 全局并发、脱敏诊断保留政策，以及响应中原始令牌的拒绝交付。
