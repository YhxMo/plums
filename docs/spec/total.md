## 职责与基线

本文是公开工程的整体实现计划，维护能力路线、依赖、阶段范围及退出条件；当前执行状态只在 milestone.md 维护。ROADMAP.md 提供阶段导航，HANDOFF.md 记录实际工程状态，ACCEPTANCE.md 定义 A1–A14 的目标验收场景，RESULTS.md 保存已执行证据。范围、依赖或门槛调整时更新本文，不在其他入口复制执行清单。

完成阶段计划归入 `docs/spec/archive/<阶段>-<YYYY-MM-DD>.md`，保留结果与证据入口；本文仅保留简短状态和必要归档链接，不复制历史执行细节。归档默认不加载，只在追溯决策、故障或证据时按需读取。未完成阶段不归档，也不重建全部历史计划。

路线以当前源码和版本化证据为准；历史规划基线保留于 [M1规划归档](archive/M1-planning-2026-10-15.md)。构建与运行结果分别绑定产物及工作区差异。

目标是让新服务、界面、业务及扩展点主要通过公开契约接入和组合。通用机制与扩展业务分别推进；任何示例业务都不是整体完成标准。实验选型不等于长期架构已经冻结。

应用 UI 的能力目标包含整体布局、导航、页面和操作流程的组合与替换，并允许扩展声明新的界面扩展点。颜色主题是其中一个子能力；验收须观察明显不同的交互体验、跨作者接入和生命周期恢复，不能用主题数量或固定聊天布局中的附加控件代替。

阶段状态：M1限定风险范围已[收敛](archive/M1-scope-2026-10-15.md)；M2正在执行，作者入口、组合／恢复、平台样板、[完整交互子阶段](archive/M2-interaction-2026-10-16.md)和[项目收敛与Mac交付](archive/M2-project-consolidation-2026-10-17.md)已有各自限定结果；M2整体未退出，M3–M5未开始。已完成子阶段保留在[阶段归档](archive/)，对应版本及范围从[验证索引](../../evidence/RESULTS.md)查阅。

## 平台优先级与门槛调整

当前围绕宿主窗口、扩展管理与Mac交付收敛：会话顶栏、红绿灯位置、独立管理页、可关闭回退、工作区chrome及欢迎页入口已实现。当前Mac包通过统一命令进入release/mac，旧包集中归档；Android保留此前受验版本，当前源码的分平台剩余项见[当前计划](milestone.md)。源码精简保持公开契约、会话授权和业务状态语义，当前产物与检查见[交付记录](../../evidence/RELEASE-2026-10-17.md)。

当前小阶段为“当前版本双端验收与生产能力准备”，计划已复核并获执行授权：优先补齐已有实现的原生证据并交付同源Mac／Android普通包，复用仍有效的已测基线；紧接准备受限网络与凭据的生产接入设计。真实适配需明确目标与资源范围后实施，模型／MCP和多Agent协作继续依赖该底座。此计划不改变M2整体退出条件。

2026-10-15 起先主攻 Mac＋Android 稳定第一版，最终仍覆盖 macOS、Android、iOS、Windows、Linux。共享 SDK、状态、生命周期和能力探测契约继续面向五端，平台差异经适配层表达。稳定第一版是目标，当前 0.0.4 debug 原型不因此成为稳定产品。

iOS 最小原生风险实验从 M1 退出条件移动至**扩展接口正式稳定之前的硬门槛**，当前不安装 iOS 工具、不开发完整 iOS 产品。门槛移动不是实验通过：资源/ESM/桥接/存储/生命周期仍未验证；若实验推翻契约须修订并重新验收后才能宣布接口稳定。Windows/Linux 完整验收在后续逐平台阶段开展。Android 真机及声明支持配置仍是稳定 Android 第一版的发布条件，模拟器证据不能替代。

M1 可按现有 Mac arm64 与 Android API 36 ARM64 模拟器风险证据、限定反例处理、来源/直接依赖核对和选型限制结论收敛。全量许可证审计和正式分发仍在后续门槛内。

## 阶段内的能力依赖

1. **M2 契约基础与作者入口。** 明确身份、服务/依赖、生命周期、状态/取消、安装升级卸载及数据去留；提供服务、非聊天 UI、无 UI 事件扩展样板。验收要求独立作者能运行和诊断，停用不残留正常注册，清理失败不伪报成功。
2. **M2 组合与恢复。** 最小集合持久化与损坏组合备份/显式恢复入口已限定验收，非敏感配置已按样板需求限定验收，后续按实际需求扩展迁移。基于契约保存扩展集合、配置及提供者选择；定义冲突、缺失、升级迁移和恢复入口。验收要求重启能恢复声明的组合，坏配置保留原数据，提供者替换不串状态。
3. **M2 平台能力与 UI 组合。** 依据实际接入需求推进受限平台能力与观测契约，真实资源适配分别验收。UI 主路径覆盖整体布局、业务导航、页面、操作流程和可递归扩展点；先核对已有视图／组合／导航机制，补齐必要通用契约，再冻结基线验证独立作者接入、动态切换、保存和失败恢复。宿主管理、授权与恢复入口可达，业务编排留在扩展。主题保持可选子能力，视觉质量通过实际关键屏审阅；不以新增配色推进整体 UI 验收。
4. **M3 平台与未知需求。** 各端核对打包资源、ESM、桥接、存储、键盘/触控、离线、前后台、回收与长任务。未实现的机制先实现，已有实现但缺证据的项补验，不将二者混为完成或不存在。
5. **M4 角色卡与 Agent 组装。** 将人类描述与机器协作信息分开设计；身份、能力声明、实际能力与授权分别表达。模型/MCP 等连接器作为扩展，依赖前述网络/凭据及组合契约。以人类理解任务和独立替换证明效果。
6. **M4 协作递进。** 先发现/联系和能力匹配，再委派/交接，最后共享状态边界、失败/取消与人类观察/接管。每步验证不同作者参与者互操作和失败归属，不提前固定重型协作框架或特定 A2A 标准。

## 支持范围与未决项

当前实证限于证据列出的浏览器、Mac arm64 与 Android API 36 ARM64 模拟器。Windows/Linux/iOS 有共享代码基础但缺少对应产品运行证据；Android 真机及其他配置待验。单次后台短任务不证明长期后台，正常重启不证明崩溃恢复。

长期运行时/进程模型、存储与迁移实现、资源预算、首批支持范围、分发顺序、项目许可证、SDK 兼容政策、角色卡/协作格式仍需依证据决策。共享 WebView 不提供恶意扩展隔离；近期不将强沙箱作为可信插件实验的前置门槛。计划变化应更新本文与相关设计，已执行事实只写入证据。
