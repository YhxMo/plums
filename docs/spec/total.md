## 第一性原理与不变量

目标是让未预设的服务、界面、业务和扩展点主要通过新增或组合扩展接入。评价重点是接入、替换、失败恢复和持续演进的成本，以及独立作者能否仅凭公开契约完成工作。

| 原则 | 对实现顺序的约束 | 反例 |
| --- | --- | --- |
| 内核拥有通用机制 | 生命周期、依赖、资源、权限、状态和观测归底座；业务循环、模型协议和卡片解析归扩展 | 为某业务增加私有注册入口或专用内核状态机 |
| 作者面向公开契约 | 默认功能使用同一 SDK；扩展可以继续提供新服务与扩展点 | 必须由维护者逐个接线或透露内部知识 |
| UI 也是扩展能力 | 主题、整体布局、导航、页面、交互均可组合或替换；保留管理与恢复入口 | 只能换色、固定槽位加按钮，或停用后无可用界面 |
| 所有权先于并发 | 注册、任务、数据和取消都能归属参与者；失败清理保持可诊断 | 旧引用继续调用、重复订阅、状态串扰、清理失败报成功 |
| 证据约束声明 | 先定义验收和失败反例，再实现、回归、独立审查；证据绑定源码与平台 | 旧绿测代表新源码、跨编译代表设备运行 |
| 风险先于接口稳定 | 移动资源、桥接、存储与生命周期先实测；按能力探测适配平台差异 | 假设有 Node.js，或桌面扩展可原样运行五端 |
| 人类理解优先 | 角色卡先解释用途和边界，再提供机器协作信息；协作流程留在扩展 | 把卡片自述当可信身份、真实能力或操作授权 |

先形成可检验契约并接受作者与平台反例，再稳定接口。内部重构按用户路径、故障或契约缺口立项，不以文件数量、测试数量、内置业务数量衡量愿景完成。

可信 ESM 与宿主共享 WebView。授权、owner 注入和资源政策约束正常公开调用路径，不证明恶意代码隔离、防界面伪装或不合作代码的强制资源约束。

## 当前基线与进度口径

当前交付包与开发源码存在差异，最新开发增量为阶段 E 提交 `c1624d5`，且缺少完整两端原生重验。具体提交、差异、包来源、命令结果与未验项统一见[工程状态](../../HANDOFF.md#工程基线与门禁)与[证据](../../evidence/RESULTS.md)。因此先做 M2.0，建立后续工作的可追溯基线。

2026-10-17 的全项目架构审查结论：核心运行时依赖单向、无运行时循环，Host 不认识业务；可维护性风险集中在通用外壳认识 Agent 业务、IPC 契约缺少单一来源、少数零余量文件和门禁覆盖缺口。这些风险按下表“计划决策与风险”归入 M2.1/M2.3 的前置工作，执行项见[当前阶段](milestone.md#m20-后的工程前置)，不另立阶段编号。

C5–C6 仅在历史文档中被提及，现有仓库未给出可执行范围与验收；不作为本路线门禁。若恢复这些工作，应先定义问题、单一负责人、失败反例与价值，再按实际依赖排期。

## 平台优先级与门槛调整

先主攻 Mac＋Android 稳定第一版，最终覆盖 macOS、Android、iOS、Windows、Linux。当前 0.0.4 debug 原型不因此成为稳定产品；现有实证限于各报告列出的浏览器、Mac arm64 和 Android API36 ARM64 单配置模拟器。

iOS 资源/ESM/桥接/存储/生命周期的最小原生实验必须在 **M2.4 内、声明稳定 SDK 之前**完成。其目标是检验共享接口，不等于 iOS 产品完整验收。Android 真机与声明支持配置必须在稳定 Android 第一版发布前完成，本路线将首批配置验收安排在 M2.4。Windows/Linux 和更广配置在 M3 逐平台验收；模拟器、真机、浏览器与原生包分别留证。

许可证义务从引入依赖时开始：M2.4 核对首批候选的实际分发依赖与通知，形成签名和可分发准备基线；M3 逐平台核对实际产物；M5 建立持续审计与更新流程。任何正式分发都必须先满足该产物全部许可证义务和签名条件，不能以“后续 M5”延期。

真实秘密、账户外发、设备或新工具的条件只阻塞对应操作。本地实现、编译、假数据与隔离夹具不等待全部资源。具体授权范围到操作前确认，同一已授权范围不重复确认。

## 支持范围与未决项

长期运行时/进程模型、存储、资源预算、首批配置、项目许可证、分发方式和 SDK 支持窗口应按上述证据决策。强隔离仅在不可信或不合作代码的真实需求出现时重新立项。完整协作格式、MCP/A2A 版本和人类接管方式留待 M4 设计。

资源准备可提前：M2.0 需要可用 Mac/Android 工具链与隔离模拟器；M2.3 需要专用测试秘密和受控网络夹具、真实账户及允许用量；M2.4 需要 Android 真机和 iOS 最小环境；M3 需要外部作者、Windows/Linux/iOS 实际环境。缺项记录为对应操作的阻塞，不扩展已有授权。

## 计划决策与风险

| 决策或风险 | 当前选择 | 触发条件与处理 |
| --- | --- | --- |
| 选择与稳定分开 | 保留现有 Tauri/Web/Rust 与可信 ESM；先用平台和作者反例校验 | 风险实验失败则修改契约与基线，不能到阶段编号就自动关闭架构决策 |
| 最小依赖政策 | M2 单活跃提供者、显式替换；M3 再评估多提供者/可选依赖 | 真实作者需要时补通用机制并验证冲突/恢复 |
| 小快照容量 | M2 继续修订检查和容量拒绝，测量正常使用余量 | 达到容量/并发/长会话需求时在 M3 评估分段或数据库，先设计迁移 |
| 平台传输可行性 | TLS 与 Android 原生秘密桥接先做小实验 | 未证实前不承诺生产可用；候选、回退及失败语义由[凭据请求契约](../CREDENTIAL-REQUEST.md)统一维护 |
| 开放性实证 | M2 接入作者与 M3 未知需求分别验收 | 作者或设备不足时记录限定结果，不能改变独立性定义 |
| 分发与演进 | 稳定 SDK、平台支持与正式分发分别声明 | 任何正式分发先完成该产物签名/许可；M5 持续审计不替代首次核对 |
| 外壳认识业务 | 当前外壳持久化与管理诊断直接读取 Agent 格式和服务 | M2.1 前移出外壳并以边界规则锁定；替代组合不提供 `agents` 时外壳仍可启动、管理和恢复 |
| IPC 契约来源 | 命令、参数、状态与错误码在 Rust/TS 两侧手写 | M2.3 新增原生命令前建立单一来源与跨语言契约测试；错误按稳定码映射，不再匹配英文句子 |
| 门禁覆盖 | 边界检查按层覆盖 SDK/宿主/外壳/扩展；TS/TSX Hooks lint 缺失 | 解析器兼容后接入 Hooks lint；边界规则改为允许名单；无法覆盖的范围在开发流程如实记录 |
| 多实例与存储一致性 | 状态写入不会提交他人临时文件，但 revision 比对在多实例下可能丢失更新 | M2.1 决定单实例或文件锁，以双进程交错反例验收；与小快照容量一并评估 |
