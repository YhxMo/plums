## 第一性原理与不变量

目标是让未预设的服务、界面、业务和扩展点主要通过新增或组合扩展接入。项目将开源，面向开发者与普通用户，以普通用户为主：有合适扩展时开箱即用。评价重点是接入、替换、失败恢复和持续演进的成本，以及独立作者能否仅凭公开契约完成工作。

| 原则 | 对实现顺序的约束 | 反例 |
| --- | --- | --- |
| 内核拥有通用机制 | 生命周期、依赖、资源、权限、状态和观测归底座；业务循环、模型协议和卡片解析归扩展 | 为某业务增加私有注册入口或专用内核状态机 |
| 作者面向公开契约 | 默认功能使用同一 SDK；扩展可以继续提供新服务与扩展点 | 必须由维护者逐个接线或透露内部知识 |
| UI 也是扩展能力 | 主题、整体布局、导航、页面、交互均可组合或替换；保留管理与恢复入口 | 只能换色、固定槽位加按钮，或停用后无可用界面 |
| 所有权先于并发 | 注册、任务、数据和取消都能归属参与者；失败清理保持可诊断 | 旧引用继续调用、重复订阅、状态串扰、清理失败报成功 |
| 证据约束声明 | 先定义验收和失败反例，再实现、回归、独立审查；证据绑定源码与平台 | 旧绿测代表新源码、跨编译代表设备运行 |
| 风险先于接口稳定 | 移动资源、桥接、存储与生命周期先实测；按能力探测适配平台差异 | 假设有 Node.js，或桌面扩展可原样运行五端 |
| 人类理解优先 | 角色卡先解释用途和边界，再提供机器协作信息；协作流程留在扩展 | 把卡片自述当可信身份、真实能力或操作授权 |

先形成可检验契约并接受作者与平台反例，再稳定接口。内部重构按用户路径、故障或契约缺口立项，不以文件数量、测试数量、内置业务数量衡量愿景完成。

可信 ESM 与宿主共享 WebView。授权、owner 注入和资源政策约束正常公开调用路径，不证明恶意代码隔离、防界面伪装或不合作代码的强制资源约束。

## 平台范围：先做好 Mac 应用本体

2026-10-21 起只做 **macOS（arm64）**：产品体验、打包应用与开源发布准备都以 Mac 为唯一目标，直到 Mac 版本可作为稳定第一版交给普通用户。当前 0.2.0 debug 原型不因此成为稳定产品；现有实证限于各报告列出的浏览器与 Mac arm64，以及 Android API36 ARM64 单配置模拟器的历史结果。

- **Android 冻结**：代码与 0.2.0 模拟器包保留为历史限定结果。不再作为改动验收、交付或 M2 退出的条件，改动不要求 Android 重验，文档也不得声称 Android 跟随当前源码。恢复 Android 时一次性补齐漂移，不预先维护。
- **iOS、Windows、Linux 未开始**，不预先适配。通用底座仍不得写入 Mac 专属假设，但不为未来平台提前写兼容层。
- **移出 M2 的项目**：Android 真机与声明配置验收、iOS 资源/ESM/桥接/存储/生命周期最小实验。它们成为 M3 的前置门槛：声明任何跨平台支持或 SDK 跨平台稳定之前必须完成。M2.4 的兼容政策只在 Mac 范围声明，并写明“未做 iOS 风险实验，不声明跨平台稳定”。
- **恢复其他平台的条件**：Mac 稳定第一版已交付，且所有者决定开始。M3 起逐平台验收，模拟器、真机、浏览器与原生包分别留证。
- **分发与许可证**：只在 GitHub 开源发布（Releases 提供 Mac 包与源码）。项目许可证为 MIT（根目录 `LICENSE`）；公开发布前须核对随包分发的第三方依赖许可证与通知（义务从引入依赖时开始）。Apple Developer ID 签名与公证不是发布前提：未签名的下载包会被 Gatekeeper 拦截，须在发布说明中写明首次打开的方法；是否购买开发者账号以换取双击即开，由所有者在发布时决定。其他平台在各自阶段核对；M5 建立持续审计与更新流程。

| M3.3 平台条件 A11 | 先完成 iOS 最小实验与 Android 真机/配置（自 M2 移入），Mac 结果持续回归；再按可获得设备推进 Windows、Linux、iOS | 每端从打包资源/ESM/桥接/存储到授权、输入、离线、前后台、回收与长任务分别验收；Linux 明确发行版/桌面/WebView，Windows 明确系统/WebView；iOS 真机结果独立于最小模拟器实验 |
| M3.4 执行与恢复 | 明确前台、暂停、检查点、恢复和不支持的长期后台行为；测量资源预算 | 系统回收不能仍显示任务运行；断网、休眠、强制终止、重开不丢已确认状态；未完成外部副作用不自动重试 |
| M3.5 平台发布声明 | 各实际产物的签名、依赖许可、安装/升级/回退、键盘/触控/辅助技术和资源限制 | 缺设备或未验能力保持未验证；若只发布部分平台，必须明确阶段未完成项和产品支持边界，不能宣称五端通过 |

### M4：人类角色卡、组装与合作

| 工作包 | 先决条件与产出 | 验收与失败处理 |
| --- | --- | --- |
| M4.1 人类理解 A13 | 先设计用途、边界、输入输出、来源、联系条件的理解任务与评分规则，再试卡片；人类描述独立于机器字段 | 实验前冻结参与者条件、题目和通过阈值；人类无需源码解释用途、限制及授权；未通过先修呈现，不靠补机器字段宣称完成 |
| M4.2 可组装 Agent | 基于已验组合/参与者作用域，按真实任务组合模型、工具、数据、状态和交互；模型/MCP 适配均为扩展 | 更换一个提供者无需私改消费者/内核；权限和凭据随 owner，失败/取消与存储可解释；多轮、流式、工具调用按用例逐项加入，不一次承诺全协议 |

| M4.5 人类观察与接管 | 使用可扩展 UI 显示参与者、分工、进度、失败、待授权和接管入口 | 用户理解正在发生什么，能暂停、取消或接管；停用扩展无不可解释残留；不把协作循环固化到内核 |

## 支持范围与未决项

长期运行时/进程模型、存储、资源预算、首批配置、项目许可证和 SDK 支持窗口应按上述证据决策。完整协作格式、MCP/A2A 版本和人类接管方式留待 M4 设计；多 Agent 先做应用内协作，远程 A2A 由扩展后续实现。

**扩展市场门槛。** 最终分发包括扩展市场与本地下载后拖拽导入；主要用户是无法审查代码的普通用户。因此“可信扩展、共享 WebView”只适用于本地自导入阶段。开放市场前必须完成：按扩展隔离执行（独立执行环境与消息桥，原生侧按调用者身份鉴权）、扩展包格式、来源签名与完整性校验、安装/更新时的权限变化披露。该门槛属于 M5.2，不能以权限 UI 代替。

资源准备可提前：M2.0 需要可用 Mac/Android 工具链与隔离模拟器；M2.3 需要专用测试秘密和受控网络夹具、真实账户及允许用量；M2.4 无需外部资源（签名账号可选）；M3 需要外部作者、Android 真机、iOS 最小环境与 Windows/Linux 实际环境。缺项记录为对应操作的阻塞，不扩展已有授权。

## 计划决策与风险

| 决策或风险 | 当前选择 | 触发条件与处理 |
| --- | --- | --- |
| 选择与稳定分开 | 保留现有 Tauri/Web/Rust 与可信 ESM；先用平台和作者反例校验 | 风险实验失败则修改契约与基线，不能到阶段编号就自动关闭架构决策 |
| 最小依赖政策 | M2 单活跃提供者、显式替换；M3 再评估多提供者/可选依赖 | 真实作者需要时补通用机制并验证冲突/恢复 |
| 小快照容量 | M2 继续修订检查和容量拒绝，测量正常使用余量 | 达到容量/并发/长会话需求时在 M3 评估分段或数据库，先设计迁移 |
| 平台传输 | macOS 用 Rust reqwest + 平台验证器；Android 用 Kotlin HTTPS 复用 Keystore 解密，不走 JNI | 两端行为差异以同一组单元与真实调用验收；需要统一实现时再评估 JNI 路线（实验见 M2.3.1 归档）。契约由[凭据请求契约](../CREDENTIAL-REQUEST.md)维护 |
| 开放性实证 | M2 接入作者与 M3 未知需求分别验收 | 作者或设备不足时记录限定结果，不能改变独立性定义 |
| 分发与演进 | 稳定 SDK、平台支持与正式分发分别声明 | 任何公开发布先完成该产物的许可证义务（签名按发布决定）；M5 持续审计不替代首次核对 |
| 业务所有权 | Agent 恢复和诊断已移出通用外壳，无 Agent 组合通过限定回归 | 后续 M2.1/M2.2 作者路径继续验证替代组合，不再让通用层承担业务格式 |
| IPC 契约来源 | Rust 实际命令/DTO 同源导出，TS 类型与导入门禁、稳定状态码已接入 | M2.3 新命令沿用声明/生成/漂移检查，分别核对普通与实验集合；原生平台运行仍独立验收 |
| 门禁覆盖 | 分层允许名单覆盖全部 `src`/`modules`/`extensions`，未归层文件即失败（R2）；TS/TSX 与 Hooks lint 已恢复（R1） | 新目录先登记层再落代码；升级 TypeScript 前确认 typescript-eslint 支持 |
| 多实例与存储一致性 | 桌面单实例（tauri-plugin-single-instance，第二次启动只聚焦已有窗口）；`state.*` 支持 `key` 分片，Agent 会话各占一片，每片沿用 64 KiB 上限与修订检查 | R3 以双实例启动与超过 64 KiB 的多会话保存验收；长期容量或索引需求出现时再评估数据库 |

## 后续加固

以下项目从 M2.3 移出，不阻塞真实路径；在出现对应需求、开放市场或正式分发前重新评估：

- 直连目标的 DNS 公网地址固定与私网/回环拒绝。
