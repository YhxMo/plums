## 阶段依赖与退出条件

主顺序为 M1 → M2 → M3 → M4 → M5；M0 文档基础已建立。平台验证从 M1 开始并持续进入后续阶段，不等到业务成熟才验证移动端。阶段内可在依赖满足后独立推进，不以规划中的工作表示已经启动。

| 阶段 | 依赖与计划产出 | 退出条件与失败判据 |
| --- | --- | --- |
| M1 风险实验与最小契约 | 先关闭已发现的状态恢复、停用传播及焦点缺口，再收敛可信运行时、存储、UI 和平台限制结论 | 桌面及 Android、iOS 早期原生实验、来源/许可证与移动依赖核查有证据；反例有明确处理结果。iOS 暂缓仍是未关闭门槛，不能静默进入 M2；缺少条件时保留开放 |
| M2 小内核与公开 SDK | 依赖 M1 退出；按下节顺序完善最小公共契约、管理/组合/恢复、平台能力、UI 组合及作者样板 | A1、A3–A10、A12 在首批声明平台上有对应证据；独立作者无需修改私有内核即可接入；不兼容、缺失能力和坏组合可解释且可恢复。不能以单一业务成功代替 |
| M3 未知需求与逐平台验收 | 依赖可用 SDK；冻结基线后由独立作者提出并实现未知需求，逐平台补全能力矩阵 | A2 与 A11 分平台验收；若需补内核，记录原基线失败并建立新基线，不能仍称无内核修改通过。真机、模拟器、浏览器分别留证 |
| M4 人类可理解角色卡与多 Agent 合作 | 依赖已验证的参与者作用域、组合、通信、凭据和恢复契约；先完成理解标准及组装，再做跨作者协作 | A13–A14：人类能理解用途与边界；不同作者 Agent 能按声明协议联系、委派、失败/取消及接管；业务编排不进入通用内核 |
| M5 持续演进与贡献 | 依赖实际作者、平台与业务反馈；完善兼容政策、分发、升级、审计和贡献路径 | 有可执行迁移/废弃策略、许可证义务核对和支持声明；每次新需求或升级继续验证开放性，不宣称一劳永逸完成 |

## 阶段内的能力依赖

1. **M2 契约基础与作者入口。** 明确身份、服务/依赖、生命周期、状态/取消、安装升级卸载及数据去留；提供服务、非聊天 UI、无 UI 事件扩展样板。验收要求独立作者能运行和诊断，停用不残留正常注册，清理失败不伪报成功。
2. **M2 组合与恢复。** 基于契约保存扩展集合、配置及提供者选择；定义冲突、缺失、升级迁移和恢复入口。验收要求重启能恢复声明的组合，坏配置保留原数据，提供者替换不串状态。
3. **M2 平台能力与 UI 组合。** 依据接入需求提供受限网络/凭据、文件/OS 授权、资源与观测契约；发展可递归组合的 UI、主题和导航契约。验收要求拒绝/撤权有可解释结果，多作者 UI 可替换和恢复，不通过业务特例绕过边界。
4. **M3 平台与未知需求。** 各端核对打包资源、ESM、桥接、存储、键盘/触控、离线、前后台、回收与长任务。未实现的机制先实现，已有实现但缺证据的项补验，不将二者混为完成或不存在。
5. **M4 角色卡与 Agent 组装。** 将人类描述与机器协作信息分开设计；身份、能力声明、实际能力与授权分别表达。模型/MCP 等连接器作为扩展，依赖前述网络/凭据及组合契约。以人类理解任务和独立替换证明效果。
6. **M4 协作递进。** 先发现/联系和能力匹配，再委派/交接，最后共享状态边界、失败/取消与人类观察/接管。每步验证不同作者参与者互操作和失败归属，不提前固定重型协作框架或特定 A2A 标准。

## 支持范围与未决项

当前实证限于证据列出的浏览器、Mac arm64 与 Android API 36 ARM64 模拟器。Windows/Linux/iOS 有共享代码基础但缺少对应产品运行证据；Android 真机及其他配置待验。单次后台短任务不证明长期后台，正常重启不证明崩溃恢复。

长期运行时/进程模型、存储与迁移实现、资源预算、首批支持范围、分发顺序、项目许可证、SDK 兼容政策、角色卡/协作格式仍需依证据决策。共享 WebView 不提供恶意扩展隔离；近期不将强沙箱作为可信插件实验的前置门槛。计划变化应更新本文与相关设计，已执行事实只写入证据。
