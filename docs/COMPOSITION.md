# 本地组合快照

状态：当前有效（2026-10-18 核实）；M2 限定实现，完整组合升级事务与恢复未完成。

扩展管理的“保存当前组合”显式替换一个本地快照。外壳 `host.shell` 的既有 version 1 配置新增可选 `composition: { schema: 1, enabled: [{ id, version }] }`；未设置时沿用默认启用集合。旧配置无需迁移，未知 schema 和损坏结构拒绝启动且不覆盖原数据。默认启用集合、布局兼容与业务恢复在 `src/application.ts` 接线；`bootShell(application)` 本身不要求 `agents` 服务。`host.shell` 中的其他不透明字段保留原位置，与主题、页面、安装路径共用串行写入和 revision；旧版 Agent 字段由 `agents.local` 迁出后移除。

快照保存 desired 启用意图及精确扩展版本，包括等待权限/依赖的项；不保存瞬时运行状态。提供者由启用集合确定，同名服务冲突拒绝保存或恢复，不重复维护提供者映射。激活失败、清理未完成、停用中的项不能保存为新组合。布局和主题与快照同次保存；安装路径继续由 imports 管理。扩展运行数据仍归扩展状态作用域；非敏感声明配置由独立 configurations 表按扩展 ID 保存，见 [配置契约](EXTENSION-CONFIGURATION.md)，不随组合快照复制。

启动时先检查集合全部 ID、版本和服务冲突；任一不符则不启动该组合，显示诊断并保留原配置，用户仍可进入扩展管理修复和显式重新保存。组合结构损坏时提供备份后重置入口，见下节；底层状态 JSON、未知应用版本或其他配置损坏不在此恢复范围。检查通过后依次启动，激活失败可能留下部分已运行项；显示诊断并继续尝试其他项，不承诺事务恢复或自动回滚。

权限不持久化、不自动授予。声明原生能力的扩展恢复为等待条件，用户在扩展管理确认后才能继续。依赖缺失/循环仍由 Host 显示；视图不可用时沿用可用布局或宿主管理恢复入口。保存成功回执前不更改已保存快照；非提交失败允许重试，未知回执沿用锁存限制，重新加载确认。

卸载手动安装项及移除失效路径时，在同次配置写入中裁剪组合引用；其他项和扩展状态保留。卸载保存失败不改内存快照；后续 Host 撤权失败仍遵循卸载未完成的诊断。正常停用仅改变当前会话，需再次保存才改变下次启动集合。

这是实验 SDK 的最小组合入口，不支持多配置档案、版本范围匹配、升级迁移、凭据保存、崩溃恢复或远程包管理。验证范围见 [组合证据](../evidence/COMPOSITION-2026-10-15.md)。

## 损坏组合的备份与恢复

组合结构校验失败时，用户可以选择“恢复默认组合”。确认前不写入；确认后先以新 `host.recovery.<UUID>` 作用域、revision 0 保存完整原应用配置 value，再读回核对，最后使用原 `host.shell` 修订号仅删除 composition。重复备份名或源修订冲突均拒绝覆盖。备份保存语义值，不承诺保持原 JSON 排版字节；已有扩展数据文件不修改。

备份与原配置更新不是跨文件事务：备份可能成功而原配置未改，回执丢失时实际重置结果也可能未知。任何失败都显示未确认并禁用本会话重试，要求重新加载核对，不伪报成功。成功后仍由用户重新加载，启动默认集合；安装路径、角色/会话和外观保留，扩展授权仍须确认。

备份保留在本地状态目录，不自动清理、不覆盖旧备份；界面显示本次标识。浏览器对应本地状态存储。没有备份列表、自动回滚或通用迁移工具。状态容量上限继续适用；备份写入/校验失败时不尝试重置原配置。证据见 [安全恢复验收](../evidence/COMPOSITION-RECOVERY-2026-10-15.md)。
