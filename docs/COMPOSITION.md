# 本地组合快照

扩展管理的“保存当前组合”显式替换一个本地快照。外壳 `host.shell` 的既有 version 1 配置新增可选 `composition: { schema: 1, enabled: [{ id, version }] }`；未设置时沿用默认启用集合。旧配置无需迁移，未知 schema 和损坏结构拒绝启动且不覆盖原数据。

快照保存 desired 启用意图及精确扩展版本，包括等待权限/依赖的项；不保存瞬时运行状态。提供者由启用集合确定，同名服务冲突拒绝保存或恢复，不重复维护提供者映射。激活失败、清理未完成、停用中的项不能保存为新组合。布局和主题与快照同次保存；安装路径继续由 imports 管理。扩展业务配置与数据仍归扩展状态作用域，未新增通用业务配置 schema。

启动时先检查集合全部 ID、版本和服务冲突；任一不符则不启动该组合，显示诊断并保留原配置，用户仍可进入扩展管理修复和显式重新保存。结构损坏时只提供重新加载入口，需要外部修复隔离配置；尚无可视化配置修复器。检查通过后依次启动，激活失败可能留下部分已运行项；显示诊断并继续尝试其他项，不承诺事务恢复或自动回滚。

权限不持久化、不自动授予。声明原生能力的扩展恢复为等待条件，用户在扩展管理确认后才能继续。依赖缺失/循环仍由 Host 显示；视图不可用时沿用可用布局或宿主管理恢复入口。保存成功回执前不更改已保存快照；非提交失败允许重试，未知回执沿用锁存限制，重新加载确认。

卸载手动安装项及移除失效路径时，在同次配置写入中裁剪组合引用；其他项和扩展状态保留。卸载保存失败不改内存快照；后续 Host 撤权失败仍遵循卸载未完成的诊断。正常停用仅改变当前会话，需再次保存才改变下次启动集合。

这是实验 SDK 的最小组合入口，不支持多配置档案、版本范围匹配、升级迁移、凭据保存、崩溃恢复或远程包管理。验证范围见 [组合证据](../evidence/COMPOSITION-2026-10-15.md)。
