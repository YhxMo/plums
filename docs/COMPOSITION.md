# 本地组合快照

状态：当前有效（2026-10-19 核实）；第 1 级限定实现，完整组合升级事务与恢复未完成。

扩展的启用状态与授权自动记录为一个本地快照：用户启用、停用或授权扩展后，扩展管理在同一串行队列里比对当前状态，有变化才写入，不需要手动保存。外壳 `host.shell` 的既有 version 1 配置含可选 `composition: { schema: 1, enabled: [{ id, version }], granted?: [{ id, version, capabilities }] }`；未设置时沿用默认启用集合，首次改动后开始记录。旧配置无需迁移，未知 schema 和损坏结构拒绝启动且不覆盖原数据。默认启用集合、布局兼容与业务恢复在 `src/application.ts` 接线；`bootShell(application)` 本身不要求 `agents` 服务。`host.shell` 中的其他不透明字段保留原位置，与主题、页面、安装路径共用串行写入和 revision；旧版 Agent 字段由 `agents.local` 迁出后移除。

快照保存 desired 启用意图（包括等待权限/依赖或激活失败的项，下次启动重试），不保存瞬时运行状态。提供者由启用集合确定，同一服务的多个提供者一起保存和恢复；各消费者对提供者的选择由消费者自己的状态保存。本次未能加载的导入项保留原记录，等修复后恢复；已不存在且不是导入项的扩展从下次记录中移除。布局与主题由各自的选择操作保存；安装路径继续由 imports 管理。扩展运行数据仍归扩展状态作用域；非敏感声明配置由独立 configurations 表按扩展 ID 保存，见 [配置契约](EXTENSION-CONFIGURATION.md)，不随组合快照复制。

启动时先恢复授权，再依次启动启用集合中已安装的扩展：不存在的扩展跳过；版本变化不阻止启动。激活失败可能留下部分已运行项；显示诊断并继续尝试其他项，不承诺事务恢复或自动回滚。组合结构损坏时提供备份后重置入口，见下节；底层状态 JSON、未知应用版本或其他配置损坏不在此恢复范围。

授权按扩展 ID 与版本记录，只在版本相同时自动恢复；恢复时只取扩展当前仍声明的能力，并加在应用已授予内置扩展的能力之上（内置扩展可能不改版本就去掉某项能力，例如 `agents.local` 改用记录后不再声明 `state.write`），不会因此报错或收回内置授权；版本变化、替换导入文件或卸载后须重新确认。同一次运行中停用后再启用不再询问已授予的能力。授权只约束公开契约调用，可信 ESM 与宿主共享 WebView，不构成安全沙箱。依赖缺失/循环仍由 Host 显示；视图不可用时沿用可用布局或宿主管理恢复入口。写入失败显示「扩展启用状态未保存」，已保存快照不变，下一次改动再写；未知回执沿用锁存限制，重新加载确认。

卸载手动安装项、替换导入文件及移除失效路径时，在同次配置写入中裁剪组合中的启用与授权记录；其他项和扩展状态保留。卸载保存失败不改内存快照；后续 Host 撤权失败仍遵循卸载未完成的诊断。

这是实验 SDK 的最小组合入口，不支持多配置档案、版本范围匹配、升级迁移、凭据保存、崩溃恢复或远程包管理。

## 损坏组合的备份与恢复

组合结构校验失败时，用户可以选择“恢复默认组合”。确认前不写入；确认后先以新 `host.recovery.<UUID>` 作用域、revision 0 保存完整原应用配置 value，再读回核对，最后使用原 `host.shell` 修订号仅删除 composition。重复备份名或源修订冲突均拒绝覆盖。备份保存语义值，不承诺保持原 JSON 排版字节；已有扩展数据文件不修改。

备份与原配置更新不是跨文件事务：备份可能成功而原配置未改，回执丢失时实际重置结果也可能未知。任何失败都显示未确认并禁用本会话重试，要求重新加载核对，不伪报成功。成功后仍由用户重新加载，启动默认集合；安装路径、角色/会话和外观保留，扩展授权须重新确认。

备份保留在本地状态目录，不自动清理、不覆盖旧备份；界面显示本次标识。浏览器对应本地状态存储。没有备份列表、自动回滚或通用迁移工具。状态容量上限继续适用；备份写入/校验失败时不尝试重置原配置。
