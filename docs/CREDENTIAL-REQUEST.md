# 凭据代用请求契约

状态：实验类型、测试专用参考适配器与 [DeepSeek 协议扩展](DEEPSEEK.md)已有本地实现；[通用绑定与原生凭据管理](CREDENTIAL-BINDINGS.md)已接入 Mac/Android 代码及宿主管理入口。生产 `PlatformAdapter` 仍不提供 `credential.request`，受限传输与请求授权待接通。系统秘密保存/读取/删除与真实外发的实际验收分开记录；接口正式稳定前仍须 iOS 最小验证。

连接器提交序列化载荷并取得响应，只引用自己的非秘密绑定名。平台管理凭据、精确目标和请求政策；扩展构造 JSON 等载荷并解析业务响应。

## 作者接口

扩展 manifest 声明 `capabilities: ['credential.request']`。激活后调用 `ctx.platform('credential.request', { version: 1, binding: 'text', body: 'hello' }, signal?)`。类型 `CredentialRequest`、`CredentialResponse`、`CredentialFailureOutcome` 由 SDK 导出；`platform` 仍返回 unknown，作者按契约校验响应。

请求只接受 version/binding/body；body UTF-8 不超过 4096 字节。不得传 owner、URL、头、方法或原始凭据。调用者身份由 Host 转为 `extension.<id>`，绑定在这个平台 owner 内解析；同名绑定不代表跨扩展授权。绑定配置与普通业务配置分开，别名不是秘密或授权证明。

成功响应为 `{ status, body }`，状态 200–599 且排除 3xx，正文 UTF-8 不超过 8192 字节；HTTP 4xx/5xx 保留给扩展解释，不自动重试。适配器不返回头或凭据；这不能保证远端正文绝不回显秘密，真实适配仍须评估数据泄漏与可信目标。

## 拒绝与取消

Host 先执行声明、授权和生命周期检查。测试适配器再检查能力、授权、owner 绑定、请求结构及大小；发送前失败为 `outcome: 'not-dispatched'`。既有 Host 在进入适配器前的拒绝仍沿用 `not-committed`，作者不能假定所有拒绝只有一种结构。

发送之后的传输失败、取消、撤权、重定向或坏响应为 `outcome: 'unknown'`；统一错误文字，不透传上游错误、请求正文、地址或凭据。unknown 表示远端副作用可能已经发生，不能自动重试；撤权/取消不承诺撤销已发送请求。撤权使当前授权世代失效，重新授权不能恢复旧请求。模拟传输若忽略 abort，等其完成后拒绝迟到响应；未承诺立即终止或超时保证。

真实适配必须禁止自动重定向，不能先跟随后拒绝。当前参考传输只返回合成状态，没有网络，因此 3xx 用例仅验证不向作者交付、不再次分发，不证明任何 HTTP 栈配置。

## 隔离参考适配器

`tests/fixtures/credential-platform.ts` 导出 FakeCredentialPlatform，仅测试引用。构造参数为绑定列表 `{ owner, id, target }` 与合成传输回调；target 必须为 HTTPS 的 `.invalid` 域、无端口/用户信息/查询/fragment。绑定被复制，凭据由适配器生成固定 `fake-only` 字符串，不接受真实凭据输入；没有 fetch、持久化或原生桥接。

回调接收 `{ target, method: 'POST', authorization, body, signal }`，返回合成 `{ status, body }`。适配器是可执行参考模型，回调由测试维护者控制，不是扩展 API、原生实现或强安全沙箱。共享 WebView 依然不能隔离恶意扩展。

真实适配需明确每 owner 绑定创建/撤销、OS 秘密存储、精确目标及 DNS/代理/重定向策略、传输限额和脱敏诊断，并分别在 Mac/Android 留证。本地实现、编译和隔离模拟不以真实账户或完整故障环境为前提；真正操作系统秘密、使用账户或向外部目标发送请求时，须先确认对应资源和操作范围，同一已授权范围不重复确认。现有参考实验不触发这些操作。

## 生产接入

首个交付单元为“一个真实模型连接器通过公开 `text.transform@1` 服务接入现有 Agent 界面，完成一次非流式、单次输入输出”。模型协议、载荷构造、结果解析和模型选择归连接器；SDK/原生平台承担受限传输、绑定、秘密、授权和清理。测试服务只承担命中计数和故障注入，不能替代真实连接器的退出验收。

每个生产绑定明确批准内容类型、固定非秘密请求头和秘密注入方式。当前绑定与原生管理实现见[凭据管理](CREDENTIAL-BINDINGS.md)，请求授权和受限传输按下述契约继续实现。

### 真实接口与公开服务接入

首个实际服务选择DeepSeek官方Chat Completions API，Mac/Android均默认官方目标、先验证直连，并允许管理者显式配置HTTP(S)网络代理；API中转/网关后续独立支持。2026-10-17 查阅的[官方入门](https://api-docs.deepseek.com/)、[Chat Completions](https://api-docs.deepseek.com/api/create-chat-completion)及[思考模式](https://api-docs.deepseek.com/guides/thinking_mode)列出以下需求：

| 项目 | 首个参考接口需求与实现归属 |
| --- | --- |
| 目标与方法 | 精确 `https://api.deepseek.com/chat/completions`，POST；由平台绑定批准，不能由扩展在请求中改写 |
| 媒体类型与固定头 | `application/json`；不沿用其他服务的协议版本头，额外头按实际接口需求批准 |
| 认证 | `Authorization: Bearer …`，原生从绑定的秘密引用注入；扩展只能引用自己的text别名 |
| 载荷 | 扩展序列化 model、max_tokens、单条 user message、`stream: false` 和 `thinking: { type: "disabled" }` 到body；只发送当前文本，不发送历史或角色说明。模型默认deepseek-flash，小输出预算256，模型及输出预算属于扩展普通配置 |
| 响应 | 扩展读取choices[0].message.content并检查finish_reason；只接受完成的文本，截断、工具调用、过滤或坏JSON均不当作完整回复，不向UI交付reasoning_content或原始JSON |

`extensions/connectors/deepseek.js` 已实现上述协议，经隔离假平台验证与现有 Agent 消费者的公开服务接线、错误、取消及切回本地。扩展不加入默认目录、不自动启用；现有普通适配器缺少能力时保持 waiting。通用绑定与原生凭据管理已有限定验证；受限传输、请求授权和真实请求仍待完成。

JSON 载荷仍通过 version/binding/body 提交，封装后的 UTF-8 计入请求 4096 字节、响应 8192 字节限额；超限拒绝，不截断 JSON。连接器使用受控的小输出预算，实际模型的请求/响应须在真实验收中核对。

连接器提供 `text.transform@1`，消费方沿用 `modules/agents/provider.ts` 中的 `ctx.use`/`ctx.task` 路径，传递取消信号。连接器通过自己的ctx调用平台，凭据绑定和credential.request授权归连接器owner；Agent消费者只消费公开文本服务，不代领或转借其平台权限。

沿用先停用旧提供者、再启用新提供者的公开服务替换流程，重复提供者继续拒绝；默认本地服务和不使用凭据能力的既有调用不新增绑定或网络前置条件。切回本地服务保留现有入口与业务数据。`extensions/services/workbench.js` 和 `modules/text-workbench/extension.ts` 也消费同一服务，替换时的授权/外发说明须覆盖这些共享消费者；安装、启用或恢复已存结果不得自动发请求，既有运行/事件入口及本地模式合同保持。

真实接入须同步 `AgentStore.info`、默认角色说明、能力字段和 `src/shell/ShellDialogs.tsx` 的关于文案，准确表达实际服务来源、文本外发和单次调用范围，覆盖 Agent 与共享工作台。业务 owner 保持 agents.local，原本地默认值、已存角色/会话和已确认视觉保持。多轮历史、流式、工具调用、OAuth、MCP 和多 Agent 协作另分阶段。

### 绑定、授权和秘密分开管理

- **绑定记录**由宿主管理入口创建，键为 `(extension owner, binding alias)`，内容为来源/版本、用户可读目标名、规范化精确 HTTPS URL、内容类型、固定非秘密请求头、认证注入策略、秘密引用和绑定修订。扩展只能引用 alias，不能创建绑定、指定 owner、替换政策或读取秘密。非秘密记录不进入普通扩展配置，组合只保存绑定需求，不携带授权或秘密。
- **请求授权**按本次应用进程及 owner 世代保存。管理者展示扩展来源、目标、POST、内容类型、固定头、认证头名称、文本外发和限额，明确确认后才启用，不展示秘密值；绑定存在不等于授权。目标、头/认证政策、秘密或来源变化使原授权世代失效，重新确认；同 ID 重装也不继承旧授权。现有共享 WebView 的 owner 注入约束公开调用路径，不能证明抵御恶意同环境代码。
- **秘密输入**走已接入的宿主原生输入面板，直接进入秘密存储，不经过扩展表单、JS 状态、日志或 source.patch。首次实现只接入专用低权限测试令牌。Mac 使用 Keychain Services 的应用专属项目；Android 使用 Android Keystore 管理的密钥加密令牌密文，密文留在应用私有且排除备份的文件中。Keystore 存密钥，不把任意令牌误称为直接存入硬件。硬件支持单独探测，不作为所有设备的已验证保证。
- **创建回执**须在秘密写入和绑定元数据提交均确认后才显示成功。部分创建保留可诊断的 pending 记录并拒绝请求；秘密写入回执未知时先核对，不重新生成或静默覆盖。删除孤立秘密是管理恢复动作，不交给扩展。
- **撤销**先在请求入口使世代失效并阻止分发，通知在途请求取消，再持久化禁用记录并删除秘密。删除或持久化回执未知时保留禁用/待核对状态，不报已删除；下次启动未核对的绑定不可用。停用释放在途资源但保留绑定，卸载保留显式禁用记录，秘密去留由管理者明确选择；重装不自动复活。进程退出后授权为空，持久绑定不能自动发请求。

Mac Keychain 的项目及访问控制依据 [Apple Keychain Services](https://developer.apple.com/documentation/security/keychain-services)；Android 密钥的保护与使用限制依据 [Android Keystore](https://developer.android.com/privacy-and-security/keystore)。原生适配代码已接入，本地验证未执行系统秘密实际保存/读取/删除；调试临时签名包更换签名后的 Keychain 访问、Android 密钥失效及备份还原必须分平台实测。

### 精确目标和传输政策

绑定只允许一个规范化 HTTPS URL（固定 scheme、host、443 端口、path；首版不接受 userinfo、query、fragment）。绑定创建和每次分发都校验；请求不得拼接路径或添加查询。明确拒绝所有 3xx，不跟随；拒绝证书/主机名错误，不提供“忽略 TLS”或降级 HTTP。锁定的 reqwest 默认特性未开启 TLS，当前回环实验不能直接转为公网实现；后续需单独选择并核查 Mac/Android TLS 后端、根证书来源与许可证。

两端默认公网HTTPS直连，禁用环境/系统自动代理；管理者可明确配置无账号密码的HTTP(S)网络代理，保存为独立route政策，目标仍为原官方API，扩展不能按请求自行选代理。代理配置修改递增绑定修订，后续请求授权须覆盖所选路由；目标证书验证保持。代理传输的CONNECT/DNS及失败行为须单独验证，保存配置不代表代理传输已通过。API中转/网关后续作为独立接入方式支持；不更改全局网络或系统信任设置。直连基线下，目标主机解析结果必须为允许的公网地址，拒绝回环、私有、链路本地和保留地址，包括 IPv6/IPv4 映射形式。校验的地址须约束实际连接，TLS 仍校验原主机名，不能先检查 DNS 再让 HTTP 栈重新解析。自定义 resolver/连接策略必须用 DNS 改写反例验证，不能只凭 URL allowlist 宣布防重绑定。生产能力不复用实验的 localhost 豁免。

每个绑定明确保存 `Content-Type` 和固定非秘密请求头，首个真实接口使用JSON和Bearer，其他服务所需的固定头/认证方式由各自绑定明确批准，既有纯文本实验保持原义。认证注入支持 Bearer或指定头名的原值注入；秘密引用只在原生侧解析，扩展不提交或读取认证头值，认证策略中不保存秘密模板。头名/值验证合法性、大小写归一及重复冲突，固定值和秘密注入值都拒绝 CR/LF；Host、Content-Length、Transfer-Encoding、Connection及其他逐跳/代理头由传输层管理，不可通过绑定覆盖，认证头也适用这些限制且不得占用Content-Type。Content-Type和认证头分别只由各自策略产生，固定头不能再定义同名项。不使用 cookie jar，不开放请求级任意头或扩展自行设置代理。

请求 UTF-8 ≤4096 字节，响应按实际读取累计 ≤8192 字节，校验 Content-Length 与分块，拒绝非法 UTF-8；不隐式解压，超限立即停止读取。HTTP 4xx/5xx 按既有响应交给连接器解释，不自动重试；模型错误解析仍留在扩展，不由平台解析模型JSON。

建议首版总时限 30 秒、连接时限 10 秒（包含在总时限内），覆盖 DNS、TLS、发送、响应头和正文读取；最多每 owner 1 个、全局 4 个请求，满额在分发前拒绝，不增设持久排队。具体值为待实施的资源政策，不是现有 800ms 回环实验的生产保证。原生请求所有权、取消通道和回收必须覆盖停用、撤权与窗口退出。reqwest 支持通过 [redirect policy](https://docs.rs/reqwest/0.13.5/reqwest/redirect/index.html)禁用跟随；配置正确仍需服务端命中计数证明未访问跳转目标。

### 回执和诊断只表达已知事实

原生分发前再次核对 owner 授权、绑定修订及取消标记。进入实际发送边界前拒绝为 not-dispatched；执行派发后，除收到且验证通过的完整响应外，超时、取消、断网、TLS/读取失败、3xx、超限和桥接回执丢失均保守为 unknown。即便失败发生在服务端实际收到之前，只要无法证明未分发，也不缩小为 not-dispatched。完整响应交付前再核对世代，旧请求不能在重新授权后交付。保留 Host 提前拒绝的 not-committed 兼容语义。

桥接永不返回需要前端等待截止与原生独立总时限，不能只用 Promise.race 隐藏仍运行的请求。预约可复用 prepare/execute/cancel 和租期思路；租期只回收未执行预约，执行中的请求靠独立时限结束。未知回执不自动重试，管理者先查看原请求状态；没有服务端幂等承诺时，人工重试也提示可能重复副作用。取消成功只表示本地不再交付和继续等待，不表示服务端撤销。

诊断只保存本地请求 ID、非秘密 owner/alias、绑定修订、阶段、耗时、字节计数、HTTP 状态或分类错误；禁止正文、原始异常、Authorization、秘密、完整目标 URL/查询及响应头。不默认持久化内容预览；环形记录首版最多 100 条，仅当前进程可查看。上游可能回显秘密：首版对完整响应中当前原始令牌的精确匹配拒绝交付，日志同样不记录；这不能识别所有编码或派生泄漏，目标仍须可信，测试令牌保持低权限且可撤销。

### 失败验收

下列场景由 SDK 与平台维护者在隔离资源上实现，未参与实现的审查者核对实际两端包和服务端观察：

| 场景 | 必须拒绝或保留的事实 |
| --- | --- |
| 同名 alias 跨 owner、伪造额外字段、未声明/未授权/已停用 | 分发前拒绝；服务端零命中；其他 owner 的绑定/授权不变 |
| 非法/重复头、覆盖传输或认证头、修改媒体类型/固定头/认证策略 | 拒绝不合法绑定；有效政策修改使旧授权失效；请求只能使用已批准的内容类型、固定头与认证方式，扩展和日志无原始秘密 |
| 取消/撤权与分发竞争、撤权后再授权 | 旧世代不交付；不自动重试；已发送失败为 unknown |
| 创建部分失败、秘密库锁定/拒绝/失效、撤销删除回执丢失 | 不假报创建/删除成功；禁用记录可核对；不降级明文 |
| 目标端口/路径变化、DNS 重绑定、私网解析、TLS 证书错误、代理环境 | 不访问未授权目标；保持系统安全设置；错误脱敏 |
| 3xx 跳转到第二服务、非法 UTF-8、错误 Content-Length、分块超限、慢正文 | 第二服务零命中；限额/总时限生效；派发后 unknown |
| 服务端已成功但回执丢失、桥接永不返回 | 服务端计数与本地 unknown 一致；无隐式重试；原生资源最终释放 |
| HTTP 4xx/5xx、响应回显令牌、原始异常含敏感字段 | 正常 HTTP 响应语义保留；原令牌不交付；日志不含敏感值 |
| 容量满、应用冷启动、Android 密文被恢复而密钥缺失 | 超额分发前拒绝；进程授权不恢复；坏绑定保留并要求重新绑定 |
