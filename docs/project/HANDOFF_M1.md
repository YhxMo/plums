## 两项修复与兼容性

- 原 main：Confirm 等待期间将 write 更新成 read，本次动作仍返回旧 write。#28 在确认后再次比较权限档位，变化返回 `PERMISSION_DENIED`，reason 为 `LEVEL_MISMATCH`。
- 正常更新删除旧密钥已实现；实际缺口是安装记录先更新后，SecretStore 删除失败会丢失旧引用，影响脱敏与卸载。#28 将历史引用和新清单一起持久化，更新及卸载等待全部删除完成；失败使用固定安全错误并保留后续版本更新或重试卸载的依据。错误会说明更新已经提交及当前版本，避免把部分成功说成全部失败。

数据库 schema 2 升至 3，保存引用而不保存密钥值；迁移保留安装、同意和启用状态。旧内核拒绝打开 schema 3 数据库。迁移无法恢复升级前已丢失记录的孤儿密钥引用。

## 已确定的行为

- 无 schema 的孤儿 settings：导入拒绝且不读取文件，`IMPORT_INVALID`、`/settings`、reason `NO_SCHEMA`；更新忽略该残留文件。不能把二者合并成一种处理。
- `recordInstall` 只插入；公开 `validatePackage`、`inspectPackage` 保留，不能当作内部重复删掉。
- inspect 返回当前包自己的权限和依赖，不合并依赖权限；必需依赖缺失时启用拒绝，不自动下载。
- MCP 消失工具会撤销批准；手动添加的 `manual:<name>` 服务默认只读。已安装 connector 按 manifest 与 consent 授权，尚未实现来源档位。路线图中的来源分档、exec、策略层、审计及描述设置接口属于后续设计。
- V8 扩展隔离放 M3，命令隔离交宿主，策略由宿主注册。真实角色卡不提交仓库，测试使用自造夹具。
