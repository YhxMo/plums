# 代码精简结果与保留边界

本记录对应 `090d81e` 之前的代码精简与 2026-10-05 验收；文件数量、入口扫描和性能测量描述当时的基线。后续实现及当前限制见 [交付状态](HANDOFF.md)。

## 目标与范围

清除所有经过使用路径核实的死代码、无效配置和行为等价的重复实现，保持现有用户功能、公开 API、数据兼容和权限保障。本文件同时记录清理范围与逐项执行结果。

覆盖 `packages/core`、`cli`、`sdk`、`host`、`desktop` 的源码及测试，以及 `scripts`、`examples`、样式、原生文件适配器、依赖和构建配置。按小批次实施，不修改真实运行数据。

完成标准是每个候选都有“删除、合并或保留”的证据与验证结果，不以删除数量衡量成果。

## 性能测量

同机 Node.js 26.5.1，以含 1 MiB 随机二进制文件的合成组件测量 `getPackageContents`，预热 5 次后记录 20 次读取。中位数由 17.205 ms 降至 0.368 ms。原实现每次读取执行一次 ZIP 编码与解码；修改后对编码、解码入口计数，25 次读取均为 0。该结果仅代表本次合成夹具，不作为所有组件的性能承诺。

## 明确保留的实现

- 能力入口在确认、异步路径检查和审计后的重复复核，以及各审计时点的密钥刷新：它们检查不同时间的状态，承担防越权职责。
- core 的 `validatePackage`、`inspectPackage`、1.x 动作/MCP 接口、公开 fakes、数据库迁移、历史密钥引用，以及旧 component/assembly 事务恢复。
- 第三方前端与业务运行时的不同隔离边界，core 路径授权与真实文件 Sink 执行时的竞争防护。
- 桌面自写版本比较。`version.test.ts` 要求 `1.0.0-alpha.9007199254740993` 大于 `1.0.0-alpha.9007199254740992`；当前仓库的 semver.gt 对该组合返回 false，不能直接替换。改用库或统一比较规则须先给出保持该断言的方案，或另行决定行为取舍。
- 证据不足的候选先记录保留理由。当前计划不删除功能、不迁移数据、不缩小权限保障。
