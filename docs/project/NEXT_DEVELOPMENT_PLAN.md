## 格式、接口与兼容

**2.0 权限声明**

每条权限共同包含 `id`、`kind`、`target`、`reason`，同一包内 `id` 唯一。

| kind | target | 额外声明 |
|---|---|---|
| `fs` | 逻辑目录名，例如 `workspace` | `operations`：显式列出 `read`、`write`、`list` |
| `exec` | 宿主登记的程序标识，例如 `test` | `cwdRoots`：允许的工作目录根名称 |
| `egress` | 域名或域名＋端口 | 沿用当前 HTTPS、域名匹配及重定向契约 |

操作按声明精确授权；写入权限不隐含读取权限。2.0 首期只支持上述三类能力，1.x 的通用 read/write 动作继续由原接口处理。

**公开接口**

- 新增 `core.runCapability({ extensionId, permissionId, request })`。
- fs 请求包含操作、相对路径；写入额外携带字节数据。根目录由权限声明确定。
- exec 请求包含参数数组及工作目录 `{ root, path }`；程序由权限声明确定，不接受调用方提供任意程序路径、shell 字符串、环境变量或 stdin。
- egress 请求复用现有 `EgressRequest`。
- 新增 `FsSink`、`ExecSink`、审计事件类型，以及对应的记录式实现。读取返回字节，写入返回完成状态，列目录返回名称与条目类型；exec 返回退出码、stdout、stderr。
- 创建内核时注入目录和程序绑定、执行接口、`onAudit`、确认超时。绑定在创建时复制并固定，不提供运行期间重绑定接口；宿主负责让用户明确选择绑定范围。
- `confirm` 改为可选，缺失时默认拒绝需要确认的调用；提供了无效接口时仍在构造阶段报错。

**兼容与版本**

- 提供明确的 1.x、2.0 manifest 和 permission 类型，并保留现有公开导出名称。涉及权限的联合类型要求调用方按格式或能力类别分支处理。
- 1.x 的有效 `runAction` 和 MCP 授权调用保持原行为；2.0 使用新入口，旧授权入口遇到 2.0 明确拒绝，避免误读权限字段。2.0 MCP 权限映射留到后续任务。
- `inspect`、CLI 权限输出展示完整的 2.0 声明。CLI 保留现有命令，不增加真实执行命令或绑定参数。
- 同意记录保存完整权限声明。新增操作、改变能力类型或目标、增加 exec 工作目录范围，都要求重新同意；跨格式更新要求重新同意。
- 数据库格式升至 **4**，保持现有 JSON 存储结构及安装、同意、启用、MCP、历史密钥引用数据；旧内核拒绝打开升级后的目录，不自动改写旧包。
- M2-A 完成后 core、CLI 和运行时版本统一为 **0.2.0**；包默认格式为 **2.0**，支持读取 1.x/2.x。

## 调用、确认与审计规则

调用顺序固定为：请求校验 → 已安装/启用/声明 → 同意 → 目标与操作范围 → 必要确认 → 重新授权和范围检查 → 放行审计 → 调用 Sink → 结果审计。

- **fs**：使用 `/` 分隔的相对路径，拒绝绝对路径、盘符、UNC、`..` 和 NUL。按真实路径及目录边界检查，允许根内符号链接，拒绝符号链接逃逸。写入允许创建或覆盖文件，父目录必须存在；目录创建另行开发。
- **exec**：程序必须已登记，工作目录必须存在且处于声明允许的逻辑根中。参数独立传递，不进行 shell 拼接或解释。
- **确认**：读取和列目录不询问；写入、外发和 exec 每次询问。只有明确的布尔 `true` 放行。缺失、异常、非布尔返回或超时均拒绝；超时后的迟到同意不得执行。
- **等待期间变化**：重新读取权限及同意状态；停用、卸载、权限收缩或路径变化后，不沿用旧授权。请求在等待前复制，防止路径、参数或写入数据被修改。
- **审计**：每次调用生成 callId，记录能力类别、操作、目标、确认与执行结果；不记录文件内容、请求体、参数值、环境变量、stdout/stderr 或密钥值。事件使用密钥脱敏机制。
- **审计失败**：新入口未配置审计，或执行前审计失败时，不调用 Sink；执行后的审计失败必须说明动作已经完成，禁止自动重试。
- 新增 `CAPABILITY_FAILED` 表示 Sink 或审计失败，详情包含 callId、失败阶段和执行状态；不携带底层异常。声明、同意、确认错误继续使用现有错误码，命令非零退出作为执行结果返回。

真实 FsSink 必须在执行时维护目录边界，真实 ExecSink 的命令隔离由宿主负责。本阶段记录式实现不提供实际文件操作或命令隔离。
