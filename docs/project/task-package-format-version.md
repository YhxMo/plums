# 格式版本常量收口任务

状态：待开发，M1 收口后、M2 开工前的小任务。此说明以 2026-10-03 的源码行为为依据。

## 当前行为

`packages/core/src/package/types.ts` 公开导出 `PACKAGE_FORMAT_VERSION = "1.0"` 和 `SUPPORTED_FORMAT_MAJOR = 1`。前者没有内核内部调用，后者用于清单导入兼容性检查。常量存在不代表导出缺少版本字段：导出已经序列化调用方提供的 `manifest.formatVersion`。

清单格式必须是正整数 major 加非负整数 minor。支持 `1.x`；更高 major 返回 `FORMAT_UNSUPPORTED`，path 为 `/formatVersion`。非法格式返回 `MANIFEST_INVALID`。导出保留输入版本及未知字段，受既有密钥脱敏规则约束。

## 建议实现范围

1. 明确 `PACKAGE_FORMAT_VERSION` 为新建包默认使用的信封版本，更新误导性的 JSDoc；它不承担重写已导入清单的职责。
2. 从该常量推导 `SUPPORTED_FORMAT_MAJOR`，保留两个公开导出名称与当前数值，避免两处版本定义漂移。
3. 在新建包示例、测试夹具的默认值中使用常量；显式测试不同版本的夹具继续写明版本。内核目前没有包创建 API，不为使用常量而新增接口。
4. 保持导入、导出契约：支持同 major 的未知字段往返，导出不会把 `1.7` 强制改写成 `1.0`；高 major 继续使用现有错误码与字段路径。

不在此任务中增加格式迁移、角色卡适配器或新的设置项类型。若支持 major 的定义今后需要独立于默认写入版本，再在格式升级任务中明确它们的关系。

## 验收

- 两个公开常量仍可导入，当前分别为 `"1.0"` 与 `1`。
- 用合法 `1.7` 清单和未知字段完成导出再导入，版本与未知字段保留。
- `2.0` 返回 `FORMAT_UNSUPPORTED`、`/formatVersion`；非法版本保持原有 `MANIFEST_INVALID`。
- 构建、现有包格式与公开契约测试通过；全量测试和版本命令通过。复用已有往返用例，新增测试只覆盖尚未验证的公开行为。

完成后单独 PR、独立审阅，再进入 M2 的能力总线设计。
