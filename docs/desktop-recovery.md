# 桌面预览版：兼容与恢复

工作区包版本统一为 **0.1.0** 预览版。SDK 桥 `sdkVersion:"1"/"2"`、共同契约 `commonVersion:"1.0"`、包格式 1.x/2.x、Agent ZIP `bundleVersion:"1.0"` 与业务协议 SemVer 分别演进。

## 兼容承诺

普通 SDK v1/v2 组件在共同契约 1.x 内保留旧贡献、角色、设置、事件、能力、依赖和协议桥。移除旧桥需要新的共同契约 major、迁移说明，以及至少一个稳定版本的提前通知。0.1.0 没有宣布移除旧桥，也没有日历截止日期。依赖旧宿主模型服务的组件仍须显式升级到外装连接器；宿主不恢复模型协议适配。本地入口按当前 Agent 上限与组件执行项单独授权，可与受限运行及策略模式并存。整机权限不会转为受控权限或授予其他组件；本地回调可使用 common 与资源；项目进程入口仍不可用。

创建、导入完整 ZIP 或加入组件时，没有已有选择且只有一个兼容候选的协议需求自动连接；多个候选由用户选择。已有选择与 ZIP 连接意图优先，失效连接不自动重绑；执行底座仍由用户显式选择。连接固定安装身份、声明、制品摘要和需求槽；重启核验当前状态，不自动更换后端。停用、换版、卸载重装或声明变化后的旧连接拒绝执行。`evidence:declared` 表示声明匹配，运行验证工具不会把它升级为第三方行为证明。

同包格式 major 的未知字段和原 `formatVersion`、不透明 payload 继续往返保留。共同 1.x 的未知 JSON 字段保留，但不参与授权。Agent ZIP 只接受已定义的 `bundleVersion:"1.0"`。资源正文不因宿主升级自动转换；不兼容业务格式由作者提供规范和用户明确选择的迁移。

## 本地记录和中断恢复

| 对象           | 持久保存与恢复                                                                                         | 执行边界                                                                           |
| -------------- | ------------------------------------------------------------------------------------------------------ | ---------------------------------------------------------------------------------- |
| 旧 Agent 记录  | 缺省或版本 1 从实际已安装组件生成版本 2 的固定制品记录；保留未知字段、设置、密钥引用、同意、启用和数据 | 发布成功才替换记录；失败显示恢复提示，原始数据保留                                 |
| 版本 2 记录    | 沿用现有组件、连接、后台偏好和策略选择                                                                 | 未支持的记录版本在数据库及事务恢复前拒绝，保留事务日志                             |
| 组合/组件事务  | 对照实际安装版本；已提交操作完成元数据发布，未提交操作保留原组合并清理本次待发布文件                   | 有未完成事务时拒绝执行；不把 journal 当作新授权                                    |
| 资源           | SQLite user_version 1、WAL、CAS、tombstone、资格和固定槽绑定保持；core 数据库版本为 9                  | 未提交事务回滚；已提交 revision 重启可见；未来数据库版本拒绝                       |
| 布局           | 保留稳定声明 id、制品、矩形及可见性；恢复核验当前组件与连接并签发新句柄                                | 缺失、停用、变更或损坏显示诊断，不自动换后端                                       |
| 策略与任务范围 | 持久保留策略偏好和选择                                                                                 | 活动策略租约、文件/网络/资源最大范围、运行句柄、会话和跨组件接管批准重启归零       |
| 任务状态       | 只保存 owner、关联标识、状态、sequence 和执行状态                                                      | 中断且已分发为 unknown；未分发保持 not_started；不恢复进程、正文、事件或自动重执行 |

任务终态正文与回放最多在内存中保留五分钟。旧终态状态元数据最多保留 30 天，并保留每 Agent 最新 256 项、全宿主最新 1024 项；活动任务及五分钟内终态受保护。启动、创建和列表读取时清理超过期限或数量的旧元数据；旧文件按原文件时间确定保留期，重启不会延长已结束记录。记录损坏或未来元数据版本时，在改写任何任务文件前拒绝启动并保留全部原文。记录过期或被清理只使状态不可查询，不表示副作用已回滚，也不允许自动重试；长期业务检查点应由扩展写入已授权资源。

恢复不会降低默认 `task-or-confirm` 策略。选择策略但没有活动租约仍拒绝；匹配当前安装身份与完整声明的旧引擎信任只迁移为对应整机执行项，不授予项目、资源或 fs/exec 范围。MCP 指纹批准和安装同意继续保留，不转换为受限任务授权。unknown/completed 先核实资源或外部结果；取消和恢复均不保证回滚已经执行的文件/命令。

## 执行结果与核实入口

执行状态描述副作用边界，成功或失败描述整个调用的结果；两者分别展示。`completed` 不能当作业务成功，放行审计中的 `not_started` 也不能当作入口实际开始的证据。

| 执行状态      | 含义                                                 | 后续操作                                                               |
| ------------- | ---------------------------------------------------- | ---------------------------------------------------------------------- |
| `not_started` | 记录生成时操作尚未分发到执行方                       | 先刷新状态并确认该调用已结束；修复配置、连接或权限后由用户明确发起重试 |
| `unknown`     | 操作可能已经执行，宿主没有可靠完成结果               | 核实文件、资源修订或外部服务结果；不得自动重试                         |
| `completed`   | 执行方已完成操作，后续复核、审计或结果处理仍可能失败 | 核实已产生的结果，查看失败阶段；不得再次自动执行副作用                 |

可信管理界面的执行记录保留同一 `callId` 的阶段链，展开“查看调用阶段与核实信息”可读取调用标识、阶段、结果和执行状态。反馈给组件作者时提供这些标识；界面不从审计中展示请求体、参数或原始输出。列表的条数上限作用于调用，不截断已读取的单次调用阶段链；审计存储自身的保留上限仍可能使早期阶段不可查询。

“后台与受控任务”中的“刷新任务状态”只重新查询元数据，“如何核实与恢复”解释当前执行状态。需要继续查看已有任务时，明确选择兼容组件并允许接管；接管仍通过既有身份与批准检查。停止不回滚副作用，重启不恢复任务正文，不自动重执行。整机进程停止仍可能遗留脱组后代，限制见[引擎说明](engine.md)。

## 宿主就绪原因

可信管理 API `agentReadinessPlan` 复用启用、连接、底座兼容和本地授权计划，返回 `prepared`、`evidence: "declared"` 及原因列表。原因包含稳定的 `code`、`blocking`、修复入口 `action` 和必要的组件、字段、需求槽或入口标识；不返回配置值、凭据或底层异常。

配置缺失、必需连接未选、组件尚待启用、本地授权或档位不足、项目入口不可用及底座不可用均是准备阻塞。无法完整读取状态时返回 `STATE_UNAVAILABLE` 并保持未就绪。没有业务前端时返回非阻塞的 `RESOURCE_PAGE`，空 Agent 仍可管理资源。该计划不授予权限或提高档位。

`prepared` 只说明当前组件的声明和准备条件，不承诺真实服务可用、任务范围已授予、策略租约有效或实际调用成功。执行入口继续独立复核安装身份、授权、范围、策略和审计。第三方连接器的真实兼容性仍须独立验证。项目入口即使已确认声明也保持 `PROJECT_UNAVAILABLE`，不会引导自动提高到整机。

2026-10-11 的定向状态与原因检查 27 项通过，执行记录与真实任务两个界面项目最终分别通过。执行记录覆盖浅深主题、键盘展开、1180/760/375/320 宽度和请求数据不显示；真实任务覆盖后台选择、刷新后的面板唯一性、接管、停止、unknown 提示及手动刷新。[验证摘要](verification/state-readiness-2026-10-11.json)分别保存首轮与重跑结果。复现时先按[测试说明](ci.md)准备固定运行时并构建，再运行摘要中的测试文件。这些检查不代表完整桌面套件、安装包或项目原生容器已经验收。

## 包更新与卸载中断

core 数据库版本 9 保存独立安装身份与按包划分的生命周期记录。导入、更新和卸载共用跨进程所有权；同包冲突返回 `IMPORT_INVALID`、`reason: LIFECYCLE_BUSY`，重复导入仍使用 `ALREADY_INSTALLED`。不同包不持有跨异步 I/O 的全局数据库写锁。

读取安装列表、读取包详情，或再次操作该包时，会尝试恢复已退出进程留下的操作。活跃进程的所有权不按超时接管；无法确认进程退出时保守拒绝。PID 被复用也可能导致恢复暂时不可用，不通过超时强制抢锁。包操作未完成时不能通过该安装记录授权执行。

更新以文件发布后的数据库事务为提交点；安装身份、前置版本与所有权必须仍然匹配。提交前中断恢复旧文件，提交后保留新文件并清理本次事务的备份。宿主随后根据已恢复的 core 版本恢复组件固定制品。备份和 staging 使用独立事务标识，不删除未知归属的旧备份。

卸载先记录清理意图并等待密钥删除，再将包文件和运行数据移入本次事务的待清理目录。删除安装记录与提交标记在同一数据库事务中完成；中断后继续清理。密钥删除不可逆，卸载恢复不承诺恢复原密钥。已报告的密钥清理失败保留原错误契约与必要引用，允许明确重试。

恢复自身也可重复运行。日志格式损坏或安装身份不匹配时保留证据并拒绝继续，不猜测哪个目录属于当前安装。验收覆盖子进程强制退出，不构成断电、磁盘损坏或远程共享文件系统的持久性保证。版本 8 及更早内核拒绝新数据库；回退仍需使用完整独立备份。

## 备份与回滚

升级或回滚前应备份私有数据；测试仅使用临时自造目录。

关闭宿主并等待全部进程退出后，复制整个私有数据目录作为独立备份；包含公共库、instances、密钥存储、资源数据库及其 WAL、任务元数据和布局。备份含秘密，使用私有本地权限。不要把正在写入的 SQLite 文件或单份 record.json 当作一致备份，也不要通过 Agent ZIP 备份密钥或授权。

未提交事务可由同一稳定宿主恢复到原组合；已提交更新保留当前安装事实并完成元数据发布。安装失败保留源制品和原数据。应用降级只在独立目录使用停机前完整备份和对应旧宿主；不要用旧宿主打开更新后的原数据目录，不拼接新旧数据库或恢复陈旧执行授权。没有承诺自动反向迁移、自动业务正文转换或直接数据降级。

## 导入导出与验证

组件/Agent ZIP 默认不含设置值、密钥、资源正文、任务/布局、引擎信任、同意、MCP 批准或活动执行授权。便携连接选择仅为 intent；导入生成新安装身份，重新检查兼容，组件默认未同意且停用。当前 Agent 的配置与密钥保存在原私有目录，导出不改变它们。

原生验证目标为 macOS 27.0.1 arm64，固定 Node 26.5.1、Electron 44.5.1。更早 macOS、Intel、Windows/Linux 和实际第三方作者未验证。打包的 Info.plist 最低版本为 27.0.1。每次受控程序启动仍探测 Seatbelt；失败拒绝，没有普通权限降级。安装包使用 ad-hoc 本地签名，尚无开发者签名、公证或自动更新。

先 `pnpm build`，然后按[平台符合性](common-contract-conformance.md)运行两种 runtime 与原生套件。原生套件可用 `PLUMS_TEST_APP=/absolute/Plums.app/Contents/MacOS/Plums` 直接启动打包应用；`PLUMS_CONFORMANCE_REPORT_DIR=/absolute/report-directory` 保存独立结果。该环境变量只控制可信测试驱动，不进入业务 SDK。开发树结果不能认证安装包，打包版必须重新验其 broker、固定 Node、原生程序和界面。

兼容范围见[兼容矩阵](common-contract-compatibility.md)，包版本不代表第三方行为已验证。
