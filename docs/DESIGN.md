# 界面设计规范

[UI](UI.md) · [主题颜色](THEMES.md) · [开发流程](DEVELOPMENT.md)

状态：当前有效（2026-10-26 核实）；所有者确定的界面设计标准，适用于外壳与内置扩展的界面，第三方扩展可参照。外壳与内置扩展的界面已按本规范改造，`tests/design-standard.test.ts` 检查颜色取自 Radix、字号、线条、阴影、动效与分隔符；开发用的文本工作台与示例扩展不在检查范围内。

新增或修改界面时逐条对照本规范；具体界面的布局与行为写在 [UI](UI.md)，与本规范冲突时先改界面，再更新 UI 文档。

## 文案

- 面向当前界面的使用者：容易理解，但不过于口语化；长短与功能场景相称；不随意造词，同一事物全应用用同一个名称。
- 不加冗余的解释性文字。界面本身能说明的，不再用一句话重复；必要的背景说明收进说明按钮或放在需要它的那一步。
- 不用中点“·”作分隔符。需要并列时用排版（换行、间距、字重、颜色）区分，或改写成完整的短语。

## 信息与交互

- 先判断信息的优先级，再组织页面：主要内容与主要操作最先看到，次要信息靠后或收起，不让所有元素同等突出。
- 尽量减少需要用户判断才能继续的交互（确认框、二选一、额外设置）。必须让用户选择时，放在用户本来就打算做这个选择的地方，而不是打断别的操作。
- 改动即时生效、只需关上的窗口（设置、关于、Agent 设置、模型连接、记忆等）在右下角放一个“完成”，与标题栏的关闭按钮作用相同；不另配“取消”或“保存”，因为没有可撤回或待保存的内容。窗口切到自带按钮的子页（如服务商表单）时由子页的按钮接管，不再显示“完成”。已经以“添加”“确认”“取消”等按钮结束的窗口不加。
- 少用眉题与标题上方的小标签。只有它提供了主标题没有的分类、上下文或关键信息时才保留；不用与主标题语义重复、只起装饰作用的英文大写小标题。层次优先靠字号、字重、间距和留白建立。

## 颜色

- 所有颜色取自 [Radix UI Colors](https://www.radix-ui.com/colors)，浅色与深色外观分别用对应的浅色、深色色阶，叠在其他颜色上的层用 Alpha 色阶。不使用色阶以外的自定颜色值。
- 按 Radix 的 12 级用途使用：
  - 1–2 级：应用与区块背景；
  - 3–5 级：控件与组件的底色，依次为常态、悬停、按下或选中；
  - 6–8 级：边框与分隔线，6 级用于不可交互的分隔，7 级用于控件边框，8 级用于悬停与焦点；
  - 9–10 级：实色背景，10 级为其悬停；
  - 11–12 级：文字，11 级为次要文字，12 级为主要文字。
- 一套灰阶配一种品牌色：Plums 用中性的 Gray 配 Orange（所有者否决了暖色调的灰阶）；错误、成功等状态色同样取自 Radix 色阶，按上面的级别使用。
- 颜色通过主题变量使用（见[主题颜色](THEMES.md)），不在组件中写死。

## 文字

- 一个界面的文字大小不超过 4 种，最好 3 种；最小 12px。
- 字号不够区分时，用字重、文字颜色（11 级与 12 级）和间距建立层次，不再增加字号。

## 形状、线条与对齐

- 少用圆角与阴影。需要时，圆角与阴影的大小与元素的功能相称：浮层可以有阴影，平铺的内容一般不需要。
- 不用卡片左缘的彩色竖线这类装饰性强调。
- 需要线条或边框时用 0.5px。
- 元素按光学对齐，而不是只按几何边界：图标、文字与容器在视觉上居中、对齐到同一条边。
- 嵌套的圆角取同心圆角：内层圆角 = 外层圆角 − 两者之间的间距（不小于 0）。

## 动效

- 尽量减少元素的动画与过渡。确有必要时，默认用 ease-out、250ms。
- 系统开启“减少动态效果”时直接切换，不播放动画。
