# 确认框文案规范

宿主实现 `Confirm.ask` 时，用户看到的就是这份文案。内核传来的 `ConfirmRequest` 保留 `message`、`host`（仅外发）和 `reason`，并可提供 `subject` 与 `action` 作为独立显示字段。这些字段只用于呈现，不参与授权；缺少时宿主仍可使用 `message`。

## 必须展示

1. 扩展名：是谁要做这件事。
2. 一句话动作：
   - 外发：`「{扩展名}」想把数据发送到 {host}。`
   - 写入：`「{扩展名}」想修改你的数据。`
   - 2.x 文件写入：`「{扩展名}」想写入目录 {逻辑目录名} 内的文件。`
   - 2.x 命令：`「{扩展名}」想运行程序 {登记程序名}。`
   - 通配符目标写成「这个网站的所有子站」，例如 `example.com 这个网站的所有子站`。
3. 目的主机（外发）：用 `host`。只有端口不是 443 时才显示端口。
4. 作者理由：用 `reason`，原样显示，并让用户看得出这是扩展作者写的。

## 不要出现

- 术语：egress、target、write、权限 id、JSON、manifest 等。
- 完整 URL（含路径、查询串、令牌）。只显示主机。

## 按钮

- 两个按钮：「允许」「不允许」。
- 默认焦点在「不允许」。Enter、Escape、关闭窗口、失焦、加载失败及请求取消都等于「不允许」；任务窗口的有效期下拉框是 Enter 的唯一例外，只操作原生选项，不关闭窗口或批准；点空白处不能产生同意。
- Tab/Shift+Tab 按对话框内控件的 DOM 顺序正反循环，包含范围勾选、有效期与按钮，跳过禁用、隐藏、inert 和负 tabindex 控件；焦点外逸时返回「不允许」。勾选项用空格切换；下拉框用方向键选择和 Enter 提交；Allow 上的 Enter 仍拒绝。
- 桌面允许按钮延迟启用，主进程同时检查 600ms 等待时间；允许须主动点击或按空格。安全窗口在独立临时沙箱会话中运行，FIFO 排队，IPC 检查当前主框架发送者和一次性令牌。
- 内核只认字面 `true` 为同意；其他结果、超时、出错都按拒绝。
- 新能力入口默认等待 120 秒，宿主可配置 confirmTimeoutMs；迟到同意不执行。1.x/MCP/分享原有确认行为保持。
- 独立核心的 2.x 兼容默认只读文件和列目录不询问，写入、命令和外发每次询问；桌面所有未被有效任务范围覆盖的能力都单次确认，包括首次读取、到期、撤权以及内部 core 重建后。可信任务范围窗口显示 Agent、逐项操作、服务目标、绑定目录和有效期，允许缩小范围；范围内不重复询问，未选中的读写或联网单次确认，声明外仍拒绝。停止并撤权入口在 Agent 详情可见。内核传来的确认文字经过已知密钥脱敏，不展示文件内容、参数或外发请求体。

## 组件连接提示

- 创建组合时，尚无选择且只有一个兼容候选：`创建后将自动连接 {组件 A} 的 {需求 X} → {组件 B}`。
- 自动连接保存后，管理页以非阻塞状态提示：`已自动连接 {组件 A} 的 {需求 X} → {组件 B}`。
- 已有连接提供「更换」入口，将焦点移至当前需求的提供者选择框；保存失败保留原连接并显示重试入口。
- 自动连接不代替权限同意，组件启用、任务范围与执行确认照常处理。

## Agent 本地授权汇总（可信宿主接口）

`confirmTier` 一次列出当前 Agent 的档位上限、项目目录、额外只读目录，以及所选组件的本地执行档位、获准主机和具体权限。目录来自宿主已绑定的真实目录；其路径只出现在可信管理确认中，不进入审计。按钮沿用「允许」「不允许」，默认拒绝，取消、关闭、超时、异常或非布尔 true 均不写授权。

整机组件须逐项展示：`该扩展可读取和修改本机所有文件（包括 Plums 自身数据和其他 Agent 的密钥）、运行任意程序、访问网络`。上限只是限制，普通组件不会继承本地执行。

本阶段已提供宿主 API 和汇总文案，尚未接入 Agent 权限区或安装/组装页。工具链安装根、隔离配置、缓存与凭据批准文案依赖项目执行服务；此阶段不宣称这些流程已交付。

## 本地入口的确认边界

本地入口的首次执行授权统一由上述 Agent 汇总确认签发。启动和请求只检查已有执行项，不展示逐引擎 `engine-trust` 窗口；缺少授权返回待确认错误。

引擎自己的 `host.confirm` 仍使用普通安全窗口，具体业务策略由外装引擎决定。它只能取得本次业务确认，不能修改 Agent 上限或本地执行项。现有安全窗口的发送者、令牌、延迟启用、FIFO、关闭和取消拒绝机制继续适用。
