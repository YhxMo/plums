# Plums 桌面扩展宿主 v1

桌面提供安装、注册、运行、授权与恢复。角色卡的内容由外装扩展解释；聊天、模型适配、Agent 循环、工具和 MCP 协议不内置。空应用只有 Agent 管理、角色卡、扩展和设置页面。

桌面预览版目标为 macOS 27.0.1 arm64。所有工作区包版本统一为 0.1.0。全仓构建使用 Node **26.5.1**、pnpm 10 和 Xcode Command Line Tools；单独使用 core/CLI 仍支持 Node 22+。

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm test
pnpm desktop:dev
pnpm desktop:package
```

打包脚本从 Node 官方发行目录下载 26.5.1，核对 SHA-256，随应用附带独立 Node，避免 Electron 与隔离库的原生 ABI 混用。Electron 44.5.1、isolated-vm 7.0.1 固定版本。产物位于 `release/Plums-darwin-arm64/Plums.app`、`release/Plums-0.1.0-arm64.dmg`。 使用 `node scripts/package-smoke.mjs release/Plums-darwin-arm64/Plums.app` 在临时数据目录核对主窗口、版本与正常退出，输出一行 JSON。本地应用采用临时签名；开发者签名、公证、自动更新尚未接入。 生成 DMG 前扫描 Resources、ASAR 文件清单及独立 ZIP 内条目，拒绝测试夹具、逃逸/注入实验和未采用的容器 helper；仅允许官方底座的固定 ZIP 路径。该检查的自造清单回归已接入；打包后应运行上述临时目录启动检查。本包采用 ad-hoc 签名且未公证，spctl 实测拒绝；清单单测不能代替打包实测。实验 helper 守卫按名称拦截，不识别文件内容，因此不能识别改名别名。

## 管理界面

管理页顶部保留 Agent、角色卡、扩展和设置四个入口；当前 Agent 选择器和文件导入位于同一外壳。角色卡、扩展页管理公共库库存；服务接入以扩展标签呈现，当前 Agent 的配置、停用、移出集中到详情页。Agent 卡片进入详情页，统一查看组件、权限摘要、工作目录和最近执行记录。公共库显示组件的 Agent 使用名单，并提示已入库的新版本。

Agent 详情按「准备使用」「任务与资源」「权限与恢复」「组件与记录」分区，分区导航会定位内容并移动键盘焦点。导航在页面滚动时保留「停止并撤权」入口，权限区继续提供降低档位、撤销本地执行和独立进程停止；底座恢复与修复入口在权限与恢复区，详情无法读取时仍单独提供底座管理。

「使用前检查」读取可信宿主的 `agentReadinessPlan`，逐项展示缺失配置、连接、启用、本地授权、档位及底座条件。填写配置会直接聚焦缺失字段，查看连接会定位对应需求槽，其他操作定位权限、底座或资源区域。清单更新失败提供重新读取入口，切换 Agent 或重新读取后丢弃旧回复。清单依据是声明与准备条件，不证明外部服务或调用成功，不授予任务范围和权限，也不验证策略租约；项目档位继续不可用。

界面使用本地内联图标与系统字体，以石墨暖灰为主色，柠檬黄标记当前导航、待配置状态及每屏唯一的开始使用入口。保存、创建和导入使用石墨主按钮；角色卡、扩展和连接器分别使用蜜桃、薄荷和天蓝分类色，类别同时用文字说明。设置页的外观下拉框可选择「跟随系统」「浅色」「深色」，默认跟随系统。选择保存在应用级本地配置，重启后恢复；主窗口背景与可信安全确认窗口同步切换，切换外观保持 Agent 运行。外装前端可通过 `prefers-color-scheme` 感知当前外观。

macOS 系统标题栏隐藏，红绿灯与品牌图标、五项导航合入 56px 顶栏；顶栏与页面同色，滚动后才显示细分隔线。空白区域可拖动窗口，按钮与选择器可正常交互；全屏时收回红绿灯的左侧留白。安全确认窗口也保留原生关闭按钮与独立的 36px 拖动区，「允许」使用石墨按钮，不使用柠檬黄行动按钮。

窄视口下顶部操作区重排，四项导航在自身区域横向滚动且文字不折行，页面内容和表单保持可读；原生窗口最小宽度仍为 900px。首次读取数据显示骨架和加载提示，失败提供重新加载入口；刷新时保留已有数据，搜索无结果时保留搜索框。键盘焦点清晰可见，减少动态效果偏好会关闭悬停与按压位移。

默认隐藏组件内容查看与编辑、调用参数 JSON 和原始审计。开启设置页的开发者模式后，公共库和 Agent 详情的每个组件均显示「查看 / 编辑内容」入口；开发者模式不授予组件执行权限。操作分别记录等待状态与错误，一个组件的操作不会禁用其他组件或导入入口。配置、组装、导入和调用错误留在对应弹窗；后台刷新失败单独显示重试入口，已完成的保存不因此被当作失败。成功保存、导入和加入组件时显示短暂反馈；删除、移出、停用和解除目录绑定使用说明后果的管理弹窗。

配置弹窗显示未保存状态，取消或关闭会放弃本次输入。宿主返回 `/settings/<字段>` 错误时，表单解码 JSON Pointer、标记并聚焦字段，关联错误说明，保留输入供重试；错误说明不包含被拒值或密钥明文。集中配置显示未保存的组件数及失败组件，逐个保存后才进入权限确认。已成功保存的组件保持提交状态，后续组件失败或刷新失败不会要求重新输入已保存密钥。

独立安全确认窗口使用临时沙箱会话，不提供管理或 SDK 桥，禁止联网、导航、弹出窗口和系统权限。窗口只接受当前主框架及一次性令牌的答复；默认焦点在「不允许」，Enter、Escape、关闭、失焦、加载失败和请求取消均拒绝；任务有效期下拉框内的 Enter 只操作原生选项，其他位置（包括允许按钮）仍拒绝。Tab/Shift+Tab 遍历全部可用控件并循环，空格切换范围或在就绪按钮上批准，焦点外逸回到拒绝按钮。允许按钮延迟启用，宿主同时检查 600ms 等待时间。请求按 FIFO 呈现，排队请求也可取消；能力入口原有 120 秒预算、权限复核和审计保持。

`desktop:dev` 会在被忽略的 `.build-cache/desktop-dev/` 中准备构建产物及宿主原生依赖链接，开发和打包均由独立 Node 运行 broker。

## 安装和使用

在角色卡、扩展页面导入组件到**公共库**，无需先创建 Agent。统一文件选择与拖拽支持独立 Plums ZIP、角色 JSON、带角色数据的 PNG，以及完整 Agent 组合 ZIP。公共库只保存组件和元信息，不启动代码、不授予权限。

主要流程面向非程序员：导入第三方 Agent ZIP，选择「这是完整的 Agent，直接使用」，导入完成立即弹出配置页。宿主根据组件自己的设置表单集中展示必要设置；模型配置将协议、模型名称、Base URL、API Key 四项直接展示在一起。保存后用独立的宿主安全窗口集中确认权限，并按依赖顺序统一启用已组装组件、打开工作界面。拒绝权限时保留配置页，未填写必要配置时不启用；已经配置并启用的 Agent 点击「开始使用」直接打开。

ZIP 导入也可选择「我还要补充功能，继续组装」：仅将包内组件登记公共库，不创建、不运行 Agent；保留名称、组件选择、默认卡、工作界面以及底座需求与精确选择进入创建流程。缺少依赖的组合 ZIP 仍必须通过所有路径、累计大小、清单和入口检查，只能先收藏组件并补齐；完整安装路径拒绝缺依赖组合。

需要定制时，在 Agent 页面点击「创建 Agent」，命名并按角色卡、扩展分组（服务接入作为扩展标签）选择组件及版本。宿主自动补齐公共库中兼容的必需组件，保留显式选择的版本；缺少兼容组件时说明需要先导入什么，不要求用户理解启用顺序。支持空 Agent、无角色卡或多张角色卡；默认卡和工作界面可留空。创建后进入同一个配置、权限与开始流程。已有 Agent 从详情页点击「编辑组合」，可加入、移出组件、显式更新版本，以及修改名称、默认卡和工作界面。已有组合的加入、移出与版本更新立即保存，名称失焦或回车保存，默认角色卡和工作界面选择变化即保存，并显示「已保存」。保存失败保留名称输入；新建 Agent 的选择仍是草稿，点击「创建 Agent」才提交。无工作界面时进入同一个 Agent 详情页。组件在 Agent 详情页单独停用或移出；公共库只管理库存。

公共库按 SHA-256 保存不可变组件制品。相同制品去重，每个 Agent 固定绑定选定制品；同一 Agent 不允许重复包 id。新导入版本不会自动更新其他 Agent。组件更新统一从公共库选择：先导入新版本，再在详情页或组合编辑器点击「有新版本 · 更新到 vX」，没有文件直更入口。公共库允许先导入缺依赖的组件并显示提示，创建或修改组合时检查必需依赖与版本范围。被 Agent 引用的制品不能直接从公共库删除。

JSON 角色卡仅要求有效对象，不解释业务字段；PNG 按公开规范提取 `chara`、`ccv3` 的 base64 JSON（同时存在时优先 `ccv3`），检查结构、CRC、编码及大小，拒绝没有角色数据的普通图片。原始文件保存在生成的 character 包 `source/card.json` 或 `source/card.png`，payload 为原始 JSON，未知字段保留。宿主提供开发者通用 JSON 编辑器，保持 payload 不透明；角色语义解释、字段表单与业务编辑仍由外装扩展提供。[角色卡规范](https://github.com/malfoyslastname/character-card-spec-v2)、[V3 规范](https://github.com/kwaroran/character-card-spec-v3/blob/main/SPEC_V3.md)

共享的只有组件文件。安装、同意、启用、设置、密钥、MCP 批准和运行数据仍按 Agent 隔离。Agent 记录保存组件摘要绑定；`bundle.zip` 只是导入/导出制品，不是 Agent 存在的前提。旧 Agent 首次打开时从**实际已安装版本**迁移绑定和公共库制品，保留授权、设置、密钥、数据及组合未知字段。提交成功才切换记录格式；失败保留旧数据并在管理页显示恢复提示。

Agent 详情页可绑定、更换或解除组件声明的逻辑目录名（示例使用 `workspace`）、查看执行记录和原始审计（开发者模式），并导出和删除 Agent。`agent-data` 为实例私有目录，不能由用户覆盖；桌面库目录及其父子目录不能作为工作目录授权。工作目录更换或解除绑定会停止相关运行并重新建立 core；解除后不再允许访问该逻辑目录，目录内文件保留。

默认自动解析：先使用系统 DNS；若代理返回保留地址或没有地址，再使用 Cloudflare 加密 DNS 查询真实公网地址。用户仍可明确选择严格系统 DNS 或固定公共加密 DNS。加密查询只把**域名**发送到 Cloudflare，采用固定公共地址和 TLS 验证，不发送组件请求体或凭据。所有模式都拒绝内网、回环、链路本地、保留、映射与过渡地址，重新解析不改变组件授权目标，也不自动重发模型请求。[Cloudflare DoH 接口](https://developers.cloudflare.com/1.1.1.1/encryption/dns-over-https/make-api-requests/dns-json/)

可信宿主的 `SinkFailure` 只接受固定原因及可选 HTTP 状态码。DNS 和请求检查失败报告 `not_started`；已收到的服务拒绝或无效响应报告 `completed`。普通传输异常继续报告 `unknown`，不附远程响应正文或底层异常，也不自动重试。

对 OpenCode Go 请求，宿主附带当前 Agent 的稳定 `x-opencode-session` 标识，并使用自己的 User-Agent；无需手动配置额外请求头。[OpenCode Go 客户端要求](https://opencode.ai/docs/go/#where-can-i-use-it)

运行界面顶部保留 40px 宿主栏，提供返回和停止，并将原生红绿灯移到栏内；返回管理后恢复导航栏位置。薄荷圆点表示运行中，减少动态效果偏好会关闭呼吸动画。返回管理仅隐藏工作视图，调用和事件继续运行，可通过运行中的入口继续；停止会销毁工作视图并取消该 Agent 的运行。SDK 的 `openManager()` 和返回管理菜单也保留运行。原生菜单始终提供返回管理、切换 Agent、停止运行和恢复界面。快捷键为 `Cmd+Shift+M` 和 `Cmd+.`。扩展崩溃/超时只影响自己的子进程；前端崩溃或无响应会撤下工作视图并返回管理。

## 开发者内容查看与编辑

「查看 / 编辑内容」按当前制品完整显示 Manifest、Payload 和文件目录，保留同格式未知字段。公共库入口查看所选 SHA-256 制品，Agent 入口绑定当前实例的固定组件版本；摘要仅作为辅助标识。进入时只读，点击「编辑」才创建或恢复私有本地草稿。Manifest 与 Payload JSON 编辑同步，提供复制、格式化、校验和保存；无效输入保留供修正。

「文件目录」显示全部包内相对路径与大小。「在 Finder 中显示」定位可编辑工作副本，「打开工作副本目录」只打开副本目录；宿主不执行或预览包内 HTML/JS。外部编辑后点击「重新读取」。JSON 编辑与外部 manifest 修改同时存在时，完整保留两份内容，明确选择采用本地 JSON 或外部文件后再保存。运行角色内容来自 manifest.payload，source/card.json、source/card.png 是导入原件，不自动双向同步。关闭弹窗可保留草稿或明确丢弃；保留的草稿与无效输入在重启后可恢复。

新制品保持原 id 和 kind，默认建议下一个 patch，版本必须高于基版；公共库已有同版本不同内容时须更换版本。显式修改 formatVersion 使用现有格式与权限校验。校验覆盖包清单、SDK 声明、入口、路径、数量和大小限制，以及当前 Agent 的组合依赖；应用更新时继续校验已有配置。校验生成固定 ZIP 快照，后续授权与保存使用同一份内容，外部继续编辑不改变该快照。文件读取拒绝符号链接、特殊文件与越界路径，副本及编辑状态使用私有本地权限，检查已保存密钥，草稿不包含 Agent 的配置值、密钥或运行数据。

公共库入口「保存为新版本」只增加不可变制品。从 Agent 入口「保存并更新当前 Agent」经可信窗口同意后复用现有更新、停止运行和恢复机制，只更新该实例，保留其他 Agent 固定版本。原组件已更新或移出时拒绝覆盖并保留草稿；提示分别说明新版本入库和当前 Agent 应用的结果。保存成功后仍保留工作副本，可明确删除副本后关闭。

## 组合包格式

根目录 `agent.json`：

```json
{
  "bundleVersion": "1.0",
  "id": "my-agent",
  "name": "My Agent",
  "version": "1.0.0",
  "character": "components/character.zip",
  "extensions": ["components/workspace.zip"],
  "connectors": ["components/service.zip"],
  "startup": "workspace"
}
```

`character` 可选，引用默认角色卡；`characters` 保存其他角色卡，三个组件列表允许为空。默认卡可以替换或清空。`startup` 是扩展的包 id。组件继续使用 core 的 character/extension/connector 三类格式；可运行组件必须是 2.x。引用必须是 ZIP 内安全相对路径；入口、类别、重复 id、依赖版本在写入前验证。

组合包与所有组件累计限制为 20 MiB 解压内容、1000 个文件/目录条目、255 字符路径。外层嵌套 ZIP 文件的大小也计入预算。路径穿越、符号链接、大小写碰撞、文件/目录冲突被拒绝。整包安装先在新实例 staging 完成，成功才发布；下次启动清理未发布的 staging。组件变更使用持久恢复记录；恢复完成前不运行相关实例。

外层未知字段和附加文件、组件未知字段均保留。导出从 core 的已安装组件重建，执行密钥检查；不带设置值、会话、运行数据或密钥。组成包版本属于发行包，组件版本可由管理页显式更新。

## 桌面声明和 SDK v1

宿主与管理界面共用 `@plumsjs/sdk/settings` 的 `missingRequiredSettings(description)` 判断必填配置缺项。该纯函数接收 core 的 `SettingsDescription`，按密钥配置标记、缺值和空白字符串判断；`false` 与 `0` 是有效值。此入口可在浏览器中使用，无需加载组合包的 Node.js I/O；实际设置仍由 core 校验。

组件在自己的 payload 命名空间登记：

```json
{
  "plumsDesktop": {
    "sdkVersion": "1",
    "runtime": "runtime/main.js",
    "frontend": "ui/index.html",
    "contributes": {
      "commands": [
        { "name": "run", "title": "运行", "inputSchema": { "type": "object" } }
      ],
      "tools": [{ "name": "read", "title": "读取" }],
      "connectors": [{ "name": "request", "title": "请求服务" }]
    }
  }
}
```

只有扩展可提供前端。运行入口为构建后的 ES Module；静态 import 仅支持组件内部相对 JS 文件，不支持 Node、npm、网络 import 或动态 import。运行文件导出 `activate(sdk)`，在其中注册声明的接口；可选 `deactivate()` 在停止时获得最多 500 毫秒的清理机会，崩溃时不能保证调用。初始化阶段不能发起 I/O、委托调用或 MCP 发现。

```js
export function activate(sdk) {
  sdk.register("commands", "run", async (input) => {
    const role = await sdk.character(); // 不透明原始 payload
    const settings = await sdk.settings(); // 无密钥值与引用
    const result = await sdk.capability("files", {
      kind: "fs",
      operation: "read",
      path: input.path,
    });
    await sdk.emit("updated", { completed: true });
    return { role, settings, data: result.data };
  });
}
```

SDK 包 `@plumsjs/sdk` 提供类型、声明验证、组合包创建与验证。运行时 SDK 包含 `register`、`invoke(packageId, kind, name, input)`、`capability(permissionId, request, mcpTool?)`、`character(packageId?)`、`characters()`、`settings`、`emit`、`onEvent(topic, handler)`、`mcpCheck`。SDK v2 的 `protocols.status/invoke` 通过管理窗口选择的固定连接调用提供者，旧 `invoke` 仍只访问声明的具体依赖；两条路径都不能循环；调用深度最多 16，I/O 权限按完整调用链交集授权。事件只投递当前实例已启动的扩展；处理事件时保留发布者调用链，事件不能提高接收方权限。`characters()` 只返回当前 Agent 已启用角色卡的 id、名称和版本；`character(id?)` 读取已启用卡的原始 payload，省略 id 读取默认卡，没有可用默认卡时返回 null，显式读取未启用/其他 Agent 的卡被拒绝。参数不能选择其他实例或覆盖宿主身份。

前端为任意框架的构建后 HTML/CSS/JS。页面使用 `window.plums`：`context()`、`invoke(kind,name,input,packageId?)`、`onEvent(callback)`、`cancel()`、`openManager()`。它只拥有当前实例及当前前端扩展的身份，没有管理 IPC、文件、密钥或直接联网接口。

SDK v2 提供者还可声明隔离面板。主界面按已固定的协议需求调用 `panels.open`，并用 `panels.layout` 指定主界面和面板的工作区比例；布局和业务渲染由外装界面实现，宿主校验边界、不重叠及句柄身份，并保留顶部管理/停止栏。每个面板分别拥有沙箱 `WebContentsView`、临时 Electron 会话和自己的 preload 身份桥，资源只来自本组件已验证快照。直接联网、弹出窗口、跨组件资源、任意外部导航和子框架导航均被拒绝。

`panels.post/onMessage` 是与旧 `emit/onEvent` 分离的限定消息通道，只在同一有效会话的主界面与其已绑定面板之间投递；不向其他面板、其他 Agent 或通用 runtime 事件总线广播。发送者由主进程从 WebContents 和主 frame 固定，组件不能指定来源。`panels.respond` 携带消息凭证进入真实 isolate 调用，I/O 继续按发送者与接收者的权限交集、范围、确认及审计执行。`panels.*` 为宿主生命周期主题，普通 `sdk.emit` 不可冒用。消息正文只进入目标业务界面，并经密钥脱敏，不写入能力审计。

返回管理隐藏全部工作视图并保留会话；关闭子面板取消该面板关联的调用，主界面仍可使用。子面板崩溃/无响应时注销并通知主界面，可重新打开新句柄；主界面崩溃则返回管理。主界面关闭、取消、组件/设置/密钥/目录/绑定变化与宿主重建撤销旧会话，重开产生新身份；主界面 `cancel()` 保留原界面以继续操作，旧子面板全部撤销，普通运行和任务范围取消。等待中的引擎启动批准随来源界面撤销，已经批准运行的引擎按既有生命周期保留。单一前端和无前端资源状态页继续使用。具体声明与大小、版本、速率限制见[面板契约](extension-protocols.md#隔离面板与限定消息)。

每扩展独立 Node 子进程，V8 isolate 默认内存 64 MiB，同步执行预算 5 秒，宿主 RPC 等待不计入预算；进程 RSS 超过 256 MiB或心跳停止会终止。只用复制的 JSON 数据桥接，不把 Node、Electron、isolated-vm Reference/对象交给客体。超时/崩溃后需返回管理重新运行。

启动入口与 activate 共用五秒累计预算，事件与每次调用分别重新计时；重叠 eval 只累计 isolate 实际运行时间。宿主失败交付后，空闲生命周期复核最多延后累计五秒，宿主 RPC 等待暂停该宽限，后续失败不续期；组件捕获错误后永久等待也会恢复失效检查。正常返回保留宿主原错误的 callId、phase 和执行状态，普通取消或退出仍使用原停止语义。

## I/O、安全与审计

前端使用沙箱 WebContentsView、独立非持久 Session、contextIsolation、无 Node 集成。CSP 与网络拦截禁止直接联网、框架嵌套和外部脚本；仅允许自身已验证 HTML 页面的导航和静态资源读取，外部导航、弹窗、浏览器权限拒绝。授权由独立原生窗口显示，包前端不能创建宿主批准。参考 [Electron 安全机制](https://www.electronjs.org/docs/latest/tutorial/security)。

权限只来自组件 manifest。首次启用同意与任务范围分别处理：开始使用时在独立可信窗口选择本次读取、列目录、写入、服务联网权限子集和有效期（默认 15 分钟，可选 1 小时），显示已绑定项目目录；范围内连续执行，未选中的能力需要单次确认。停止、撤权、升级、配置或目录变化后重新批准。桌面未启用任务范围且未被已确认项目/组装覆盖时 read/list/write/HTTPS 均单次询问，单次确认默认 120 秒；缺失、拒绝、超时和非布尔 true 都不执行。确认后、放行审计后重新检查安装/启用、权限、路径、调用链和 MCP 指纹。执行前审计失败不调用 Sink；执行后的失败保留 `callId/phase/executionState`，不能自动重试 unknown/completed。

文件 Sink 通过固定原生辅助进程执行，目录句柄逐级 `openat`、拒绝符号链接及非普通文件，macOS sandbox 限制选定真实根，不能调用任意程序。文件 I/O 20 MiB 上限。已注册受控 ExecSink，逻辑目标由可信管理固定程序和外部读写根；本地 stdio MCP 未注册。

HTTPS 只允许清单域名，检查所有解析地址，连接时固定地址并保留 TLS 主机验证；不自动跟随重定向。支持请求/响应头、取消和有限流式事件（`io.chunk`），请求/响应各 20 MiB、总时限 120 秒。流式事件包含实例、扩展身份；宿主跨数据块脱敏。响应完成后返回汇总结果。持续不结束的 SSE 会到期取消，示例只使用有限响应。

连接器可声明 `credentials: [{permissionId, setting, header, prefix}]`。setting 必须是自己的 x-secret 设置，permissionId 必须是自己的 egress 权限。宿主按绑定注入请求头；普通前端和扩展不能读取密钥明文。桌面端将密钥以明文存入实例私有 `secrets/` 目录，每个引用对应一个文件，目录权限为 0700、文件权限为 0600（POSIX）。写入通过独立临时文件和原子重命名完成，不同引用的并发写入不会相互覆盖。 删除会清理同一引用下合法 UUID v4 名称的未发布临时普通文件；其他引用及未知名称保留，链接或目录拒绝。保存、读取与重启不访问系统钥匙串；设置、数据库、日志和组件导出继续只保留引用或脱敏状态。密钥只在实际请求已授权的服务时由宿主注入，不自动上传或同步。

旧版 `secrets.enc.json` 不自动解密，因此不会触发钥匙串授权。升级后需在配置页重新填写一次原 API Key；旧文件保留，删除对应密钥时也清理其旧密文引用。库中仍保留 `EncryptedSecretStore`，供主动选择加密存储的其他宿主使用。

模型协议全部由可选外装 `model-connector` 实现。宿主注册通用 `service / https / request`，仅管理批准的 HTTPS origin、声明绑定的凭据、任务范围、确认、取消与审计。协议名称和模型名称对宿主没有特殊含义，增加协议只需升级连接器。连接声明与调用见 [SDK v2](sdk-v2.md)。

模型连接器、聊天扩展及完整聊天 Agent 版本为 2.0.0，包 id 保留。连接器配置仍为协议、模型名称、Base URL、API Key 四项；模型名称自由填写，聊天默认关闭工具。连接器保留 Chat Completions、Responses、Anthropic Messages、Gemini 四种文本协议，处理路径、消息、函数工具、鉴权声明与回复解析。宿主不保留内置适配兜底。

多轮历史、工具结果及原生协议块由聊天扩展与连接器处理；原生块仅在绑定指纹匹配时回传。调用输入不能替换保存的协议、模型、地址或凭据。HTTP 拒绝、解析失败保留实际 callId、状态及已完成执行状态，不自动重试。生图、TTS、文件上传和流式展示不在当前支持范围。

旧 1.2.0 Agent 先在现有管理界面显式升级聊天扩展，再升级模型连接器；聊天扩展依赖范围允许这个过渡顺序。升级保留设置、密钥和历史，需重新批准新的服务权限及绑定。未升级的组件显示兼容提示。SDK v1 普通扩展继续运行。

可信引擎采用普通本机进程机制，公共模型连接器完全可选。可信宿主已提供 Agent 汇总授权、档位降低、目录移除和逐组件撤销 API；目录保存真实身份并在管理读取时复核，两个已确认整机入口可分别启动。权限区、导入配置页与已有组装页已接入汇总确认、档位降低、目录移除、组件/整体撤权和进程控制，替换逐引擎信任入口；启动和请求复核已有授权，缺少授权不会自动弹窗。项目配套区展示各入口的真实工具链探测根、配置允许字段结果、已批准主机，以及缓存占用/清空；待确认汇总也展示所选组件的配套结果。配置允许字段可显式读取，独立原子生成模块和凭据批准/撤销已有原生验证；原生项目启动及配置、凭据、工具链、缓存、代理运行时注入仍不可用，项目启动按钮保持禁用。具体执行边界、受控贡献桥、进程组监管和自造示例见 [可信引擎](engine.md)。

整机扩展没有沙箱，可读取和修改本机所有文件（包括 Plums 自身数据和其他 Agent 的密钥）、运行任意程序并访问网络。停止或撤销该入口后，它启动且已脱离其进程组的子进程可能继续运行。该限制在首次汇总确认、权限汇总与整机入口的停止/撤权控件旁展示。

数据库格式为 9，2.x MCP 使用 `checkMcpToolsV2`（必须提供完整列表）、`approveMcpToolsV2` 和 `runDelegatedCapability(...mcpTool)`；指纹包含名称、描述和 inputSchema，工具消失或变化后撤销批准。迁移保留安装、同意、启用、历史密钥引用和旧 MCP 数据；旧动作、旧 MCP 与 extension-only `runCapability` 契约保持。版本 8 追踪本地凭据的当前、历史及待清理引用；旧版本 7 拒绝新库。手动提供凭据须经过可信确认和当前授权复核，预留引用后写入 Agent 密钥存储，撤销先停止相关组件再清理；失败引用保留供卸载重试。批量或源配置凭据选择、进程注入和撤销后配置重建尚未接入，不能据引用账本宣称完整流程可用。

## 应用验证

`pnpm test` 使用最小自造组件夹具验证宿主、SDK、安全边界和 Electron 管理界面；业务扩展实现独立维护。平台协议测试入口为 `pnpm conformance:platform`。

## 组件连接

创建组合、完整 ZIP 导入或加入组件时，没有已有选择且只有一个兼容候选的需求自动连接；多个候选仍由用户选择，必需需求须完成选择后才能创建。ZIP 中的连接意图与已有选择优先，失效连接不自动重绑。Agent 管理页提示“已自动连接 A 的 X → B”，提供“更换”入口，并展示协议版本、功能缺口、停用和更新失效状态。可选功能可解除连接。自动连接不授予权限；配置、同意、启用和任务范围仍分别确认，业务界面不能管理连接或跨 Agent 选择提供者。恢复与导出语义见 [扩展协议](extension-protocols.md)。

## 后台与受控任务

Agent 管理页按组件显示声明的后台开关、真实任务状态、停止及兼容接管授权。Agent 后台任务在关闭/重开前端与切换 Agent 后仍保留；前端归属任务关闭时取消。任务期限与每次权限继续生效。另一个 UI 只有获得管理授权且拥有原所有者的权限与资源资格才能接管，不能借 taskId 获得执行权限。

受控程序区域为逻辑 exec target 选择本机可执行文件及明确的外部读/写根。目录身份和程序摘要固定，变更后重新选择；平台数据不可授权给程序。author SDK 不选择路径或管理程序绑定。Node 26.5.1、只读快照、临时 scratch、直接网络/进程拒绝及独立 supervisor 为当前 macOS arm64 路径。设施不可用拒绝启动。按组件确认的整机本地入口可与 common 路径、资源/短期能力范围和策略租约同时活动，各自授权仍独立复核。旧引擎信任只迁移为对应入口的整机执行项，不授予项目、资源或 fs/exec 确认覆盖。项目系统沙箱与本地回调的 common/资源接入仍待实施。

重启只恢复无正文状态，不恢复调用、回放、接管授权或短期范围。执行结果未知时页面要求先核实，停止等待实际清理完成。可信管理与业务界面始终分离。

## 独立工作界面

可信 Agent 详情页的“工作界面组合”可选主界面与多个并排界面，也可单独打开备用完整前端。每个界面是独立沙箱 WebContentsView，以自身组件需求槽消费已选后端；通用桥不提供业务正文格式。原有提供者面板继续使用协议绑定和限定消息回执。

布局只持久保存固定组件摘要、稳定声明/需求槽、比例矩形和可见性，关闭重开重新签发身份及 handle。缺失、停用、摘要变化、损坏布局或不兼容连接显示可信诊断；显式保存可移除失效选择。重启不恢复权限租约、跨组件接管批准或业务回复。后台接管和策略选择保留独立可信管理入口，业务界面只读 policy.status。

它们不替代公开黑盒互操作或稳定安装包验证。

## 执行底座

设置页和 Agent 详情提供底座管理，显示来源、具体版本、摘要、兼容/缺失状态和引用。用户先检查候选兼容，再显式切换或启停；缺失和恢复阻断状态保留管理入口。应用离线携带独立官方底座 ZIP，不自动安装业务示例。便携 Agent ZIP 保留精确底座选择与需求，缺失时导入到停用修复状态，不授予权限。产品流程、签名格式和验证范围见 [桌面底座管理](foundation-desktop.md)。

项目配套区提供真实自检和可信凭据批准/撤销，失败检查显示通过数且继续禁用项目启动。凭据输入为密码字段，提交时立即清空，确认窗只显示 kind/主机/用途并说明令牌可被扩展读取；值不回显。配置只在用户点击“读取配置允许字段”时安全读取，变化后需重新汇总确认。缓存查询与清空已验证 macOS 原生路径，清空先停止受影响组件。项目 launcher、配置/缓存/工具链/代理/凭据运行时注入尚未完成，管理操作通过不能证明项目运行可用。

等待汇总确认期间增加或移除组件，使旧计划返回 `PERMISSION_DENIED / LOCAL_AUTHORIZATION_CHANGED`；同一组件升级导致旧确认取消并返回 false。两者均不提交迟到授权。停止并撤权在关闭相关界面前保留 taskId，撤销审计关联原任务。
