状态：当前有效（2026-10-24 核实）；0.2.0 默认界面说明，验证范围见证据索引。

## 从添加 Agent 开始

0.2.0 默认显示 Agent 界面。零角色时显示品牌和“导入角色卡／安装扩展”两张引导卡，底部保留“从头添加 Agent”次要入口。已有角色但未选中时，桌面左侧保留列表，右侧只显示居中的低干扰 Plums 图标；角色是否接入模型不影响计数。选中角色后显示会话。手机无角色时显示上下排列的引导卡，已有角色时先显示列表，选中后进入会话。两端均可从“添加”进入添加方式菜单，创建角色、导入角色卡或查看扩展。模型连接器通过扩展接入；MCP 连接器尚未实现。

“从头添加”是一次拼接：填写名称、设定（预填“简洁、友好地回答用户的问题。”，可改可清空）和可选的介绍后，同一页选择模型，并在「组成扩展」中开关组成这个 Agent 的每个扩展：Agent 核心、显示它的界面和所选模型的连接，默认全部开启。任何一项都可关闭，关闭后行内用红字说明后果（Agent 核心或模型连接：它不会回复；界面：不能在这里和它对话）；开启没有模型的连接时提示先添加模型。“管理模型连接”“扩展管理”会先离开添加页，草稿保留。没有模型时仍可保存，并在会话输入卡片中准备草稿、连接模型。添加后在详情的「组成扩展」里继续开关。

Agent 核心（`agents.local`）管理角色与会话；回复只来自每个 Agent 选择的 `chat@1` 模型（内置[模型连接](MODELS.md)提供，可选依赖），协议载荷与回复解析由模型连接器负责。开发构建另有不联网的回显模型并默认启用。无论是否接入模型，会话都保留同一张输入卡片和草稿。未选择模型时，模型按钮写“未选择模型”，输入框提示先选模型；没有可用模型时，该按钮的菜单提供“连接模型”，打开模型连接对话框。界面、Agent 核心或所选模型的连接被关闭时，在卡片内说明原因并提供“开启”。这些状态只阻止发送，仍可编辑文字和添加附件；按钮、回车与表单提交采用同一发送条件，恢复后可直接发送已有草稿。相关回归见 `extension-usage.spec.ts` 与 `agent-flow.spec.ts`。导入角色卡不会改变执行能力或授予访问权限。实验 JSON 卡片需要 `name`，可选 `description`（介绍）、`instructions`（设定）、`avatar` 和 `version: 1`（旧卡片中的 `multiSession` 会被忽略）；没有 `instructions` 的卡片在创建页把介绍预填为设定，直接添加时同样取介绍。

介绍给人看：显示在列表摘要、空会话和详情里，不发给模型。设定只发给模型：每次请求的系统提示词依次是“你是「名字」”、当天日期与时区（只到日，一天内提示词不变，便于服务商缓存）、“只能在收到消息时回复，不能主动发消息或到时提醒”，然后是设定（[instructions.ts](../modules/agents/instructions.ts)）；设定为空时只有前面这几句。拆分前保存的 Agent 在读取时把原介绍同时作为设定，行为不变，之后两者分开修改。支持选择本地文件、粘贴 JSON 或读取应用同源链接；外部链接需先下载文件，原生 CSP 保持原边界。此格式由扩展层解析，不是完整角色卡标准或 A2A 协议。

导入页的「选择模型和扩展」只进入配置步骤，不保存角色；只有最终确认「添加」才创建。返回或取消不改变已有角色。

同源角色卡链接读取拒绝重定向，最多读取 32000 个 UTF-8 字节，10 秒内未完成则报超时；关闭或取消会中止读取，失败保留原输入。文件入口也限制 32000 字节。

## 列表、交互与详情

键盘行为不随窗口宽度切换：桌面指针设备在半屏窗口仍以 Enter 发送、Shift+Enter 换行；触摸设备用发送按钮。附件快捷键 ⌘U／Ctrl+U 只在可见且未被模态窗口遮挡的输入区生效。打包应用不显示仅开发构建可用的诊断入口。

Mac 窗口控制使用系统原生的常规尺寸按钮（不缩小、不自绘），由 macOS 处理关闭、最小化、缩放、全屏、平铺菜单及焦点外观。`titleBarStyle: Overlay` 与 `hiddenTitle: true` 隐藏标题栏背景和文字、内容铺满；`trafficLightPosition`（距左 7pt、距顶 20pt）把按钮放在 68px 导航栏顶部，相邻按钮左缘相距 20pt（系统默认 23pt）。AppKit 在调整大小、全屏进出、平铺与明暗切换时会把间距复原，[window_frame.rs](../src-tauri/src/window_frame.rs) 在窗口事件（调整大小、获得焦点、明暗变化、移动与换屏）后把最小化、缩放按钮放回。导航栏为原生按钮预留顶部 44px，窗口顶部保留 12px 拖动条。窗口透明，只有导航栏透出系统侧栏材质（`windowEffects: sidebar`），上面叠一层浅色 30% 白、深色 4% 白（`--rail-glass`），其余区域铺实底；系统开启“减少透明度”时由 macOS 把材质换成实色。窗口默认 940×640pt，最小 652×600pt（始终三栏：列表 ≥ 208、会话 ≥ 360），不设上限，全屏、平铺与缩放都铺满屏幕；只记住上次的尺寸（官方 window-state 插件，位置交给 macOS，存于应用配置目录的 `.window-state.json`，开发进程与打包应用共用），恢复时不小于最小值、不超出所在屏幕。配置、换算与 HTML 预留区回归见 `window-chrome.test.ts`、`window_frame_tests.rs`、`window-controls.spec.ts` 和 `desktop-layout.spec.ts`；按钮与材质由打包应用验收，结果见 [HANDOFF](../HANDOFF.md)。

桌面没有独立顶栏：最左侧是通栏到窗口顶边的外壳导航栏（Mac 上窗口按钮落在其顶部；该区域和各栏头部都可拖动窗口，头部用 `data-tauri-drag-region="deep"`，其中的文字不挡拖动，按钮与输入框仍可点；没有打开会话时，会话卡片顶部与会话头部同高的一条也可拖动），宽 68px（窗口默认 940×640），顶部先留出红绿灯行再是用户头像（36px 圆形里一个没有表情的空白梅子外形，中性灰：浅色底 `#D9DEE5`、图形 `#8A94A3`，深色底 `#4A4D52`、图形 `#A8AEB7`；贡献主题由窄栏图标色与窗口底色推导。有扩展贡献 `entry: "user"` 的 dialog 视图时它成为按钮，悬停显示该视图名称，内置记忆的是“记忆”，打开时停在“关于我”；没有时只是图像），其下是扩展贡献的工作区，底部是“扩展”与紧接在它下方的“设置”。窄栏不显示文字：每项是 44px 的按钮，悬停 Tooltip 与 `aria-label` 给出名称，当前项带 `aria-current="page"`。图标全为实心单色形状，当前项为 `--selection` 橙色，其余为 `--rail-icon` 灰色，悬停只加一层浅底。工作区图标来自视图契约的 `View.icon`（扩展自带的 SVG，宿主以遮罩绘制并着色，规则见[页面契约](PAGES.md)），内置 Agent 界面同样经此提供对话气泡；缺失或无效时用通用工作区图标。扩展（四格拼块、右上一格为圆）和设置（齿轮）是外壳自己的入口，用同一种绘制方式。明暗切换、关于与开发构建的诊断都在设置中，扩展贡献的弹窗视图（如模型连接）在扩展管理中所属扩展的卡片上打开。右侧栏开关在内容区右上角，各头部为它留出位置；工作区自己设置了标题时，内容区顶部才多出一行标题。手机不显示导航栏，“扩展”与“设置”两个按钮留在顶栏，用同样的图标。导航栏与 Agent 列表共用窗口底色（`--chrome`），中间只隔一条细线；列表右侧是一块浮起的会话卡片（`--chat`），距窗口上、右、下边和列表各 8px，14px 圆角，只有一圈细边加极轻阴影。Agent 列表默认 256px（208–380px）、会话区至少 360px，列表与卡片之间的 8px 间隙是可拖动调整宽度的分隔条，悬停或拖动时显示品牌色细线；详情抽屉宽 288px，窄窗口里覆盖在会话上时只遮住较少的消息。扩展管理和其他工作区同样放在一块四周留 8px 的浮起卡片中：视图根节点标记 `data-frame="own"` 时（`.pane` 规则，见 [src/app.css](../src/app.css)）外壳让出卡片，由视图自己画，右侧栏按钮随之对齐到卡片头部。列表顶部一行是搜索框与添加按钮（无标题行与分段控件）。Agent 详情不占同级栏位，而是从右侧弹出的浮层抽屉（带浮层阴影，位于右侧栏按钮下方）：不遮挡也不锁定会话，可边改设置边对话；窗口宽于 1100px 时会话区让出抽屉宽度，较窄时抽屉覆盖在会话上；Esc、抽屉关闭按钮或导航栏（手机为顶栏）的右侧栏按钮收起。手机上详情为底部弹出层。界面以紧凑尺寸集中信息：会话头部 52px、列表头部 56px，会话消息与输入栏共用同一列边（最宽 600px、两侧至少 24px），列表行 68px、整行通栏、不画分隔线，头像 44px，正文 14px。每行显示头像、名称（14.5px 半粗）、末条消息时间（11.5px）与摘要（12.5px，始终是末条消息或介绍）。头像右下角的状态点按颜色区分：等待回复时为品牌橙并缓慢呼吸（选中行上改用行文字色），在线为绿色，空闲不显示。有未读回复时摘要右侧显示品牌橙数字徽标（选中行反色，超过 99 显示 99+），悬停时与时间一同让位给“…”按钮。等待中切到别的 Agent（手机回到列表），回复到达即计为未读，打开该会话后清除；进入扩展管理隐藏工作区时也停止标记已读，返回后恢复，草稿保留；未读按会话保存的 `lastReadAt` 计算，重启后保留，正在看的会话收到回复不计未读。行按钮的名称就是可见的 Agent 名称，选中行带 `aria-current="true"`；`aria-describedby` 依次读出末条消息（摘要只保留前 120 个字符）、时间与“正在输入”“N 条未读”，状态不只靠颜色表达。行分三档底色：选中为 `--selection` 实色橙配白字（时间与摘要为 86% 白）；未选中的置顶行为 `--row-pinned`；普通行就是列表底色。选中行白字对比约 3.2:1，低于 AA 的 4.5:1，是用户确认的、与微信绿底白字同类的取舍。置顶的 Agent 排在最前、保持原有顺序，其余按最近活跃倒序（各会话 `lastMessageAt` 的最大值，新回复与新会话都会把它提到前面），不另分区或加标题；置顶直接保存为每个 Agent 的 `pinned` 字段。列表行的操作菜单支持鼠标、右键、触屏长按及键盘，包含置顶／取消置顶、重命名、移除；行内“…”按钮在悬停时出现，并在各档底色上都有反馈。删除前确认本地会话的删除范围。

点击角色进入会话。会话头部与消息区同色、不画分隔线，一行内是加粗的名称和当前会话标题小胶囊；胶囊是会话菜单，可切换、新建、重命名和删除会话；超过 8 个会话时菜单顶部有筛选框，打开即可输入（字母不触发菜单的首字跳转），↓ 进入列表。等待回复时只有那个会话不能删除，其他会话照常切换、新建和使用，Agent 详情与添加 Agent 等弹窗也不必等待；同一 Agent 一次只等一条回复，在别的会话里发送时输入栏说明原因，并提供“查看”回到等待中的会话。首条消息给“未命名会话”起名，已重命名的会话保持原名。回复像联系人一样整条送达：等待时名称下方出现一行品牌色副标题“正在输入”与三个依次起伏的圆点（参照微信与 Telegram），消息区不放占位气泡。这一行同时是 polite live region，开始等待时读屏播报一次“名称 正在输入”，回复由消息区的 `role="log"` 读出。右侧只有“…”更多操作菜单（与列表行菜单相同的置顶、重命名、移除）和外壳的右侧栏按钮。空会话居中显示头像、名称和介绍。头像只出现在列表、会话头部（手机）、空会话和详情里，消息旁不放：有图片时显示 27% 圆角的方形图，否则是扁平梅子：13/48 圆角方底、梅子主体、深褐梗、绿叶 `#4E9F55` 和两只眼睛，没有高光、腮红或阴影。主体与方底的颜色按名称散列到青、橙、蓝、粉、紫五组之一，每组有浅色与深色两种方底；配色表是 Agent 界面扩展里的数据（[plum.ts](../src/agents/plum.ts)），不在外壳中。详情里的头像可点开菜单：上传图片…（居中裁成 256×256 的方形、WebP／JPEG 压到约 36K 字符以内，GIF 取首帧）与移除头像；导入角色卡自带 `avatar` 时创建页提示并带入。右侧栏按钮（手机在顶栏）是详情唯一的入口，只开关详情，扩展贡献的侧栏不会接管它。消息不带头像，均以无阴影的 18px 圆角气泡呈现（靠发送者一侧的底角 5px，桌面最宽为消息列的 75%）：Agent 回复为左侧 `--bubble` 色气泡，自己的消息为右侧实色品牌橙 `#F57D4A` 配深色字，桌面与手机同一套无衬线排版；同一发送者的连续消息间隔 4px，换人间隔 12px。自己的消息按输入原样显示；回复按 GitHub 风格 Markdown 排版（`react-markdown` + `remark-gfm`，单个换行仍是换行）：标题、列表、引用、表格（过宽时横向滚动）与行内代码用主题变量着色，代码块悬停或聚焦时右上角出现“复制代码”。原始 HTML 不渲染；图片不加载，只显示“[图片：替代文字]”；只有 `https://` 链接成为链接，悬停显示地址，点击或回车经宿主能力 `link.open` 在默认浏览器打开（浏览器预览为新标签页），应用窗口不跳转，打开失败时提示；其他协议的链接只显示文字。消息区只在停在底部时跟随新消息（[useFollowBottom.ts](../src/agents/useFollowBottom.ts)，参照 assistant-ui 的视口自动滚动设计：浏览器原生 `scrollTo`，“回到底部”的请求持续到真正到达，期间内容增长继续跟上；只有本人向上滚动才离开底部，内容变矮不算；底部判断留 1px，适应 WebKit 在 2 倍屏上的小数滚动。原用的 `use-stick-to-bottom` 弹簧动画在 WebKit 中迟迟停不到底，见其 issue #9、#32）：向上翻看时到达的回复不把视图拉下，底部居中出现圆形“回到最新”按钮，期间有新回复则变为“↓ 新消息”；发送消息总会回到底部，撤销删除、编辑后发送与重新生成完成后也回到最新消息（`chat-follow.spec.ts`），切换会话从末尾开始，系统减少动态效果时直接跳转。相邻消息间隔超过 5 分钟时插入居中的时间文字（今天 `HH:MM`、昨天、`M月D日`、跨年带年份，不带底色），列表行在名称右侧显示末条消息时间。小号操作图标紧凑排在气泡下方，只在悬停或键盘聚焦时显示（最新一条回复也一样，桌面消息区末尾为它留出 36px，停在底部时不被输入栏挡住）：复制、编辑（自己的消息）或重新生成（回复）、删除；右键打开同样的消息菜单，方向键切换、Esc 关闭并把焦点还给该消息。所在会话等待回复时禁用编辑、重新生成和删除，复制始终可用。编辑参照 Telegram：消息文字放进输入栏，上方出现“编辑消息”与原文一行，「×」或 Esc 退出并还原原来的草稿，编辑期间不能添加附件（原消息的附件随编辑保留）；发送后从这条消息起改写，等待期间它和后面的消息先隐藏，停止则原样恢复。重新生成以这条回复之前的消息重新请求。两者都会在回复保存时删掉被改写处之后的消息：除了被替换的那条回复外还会删掉更多消息时，先弹出“删除后续消息”说明条数，选「继续」才发送；完成后提示“已按修改重新发送”或“已重新生成”并带“撤销”，放回改写前的整段对话（回归见 `agent-edit.test.ts`、`chat-edit.spec.ts`）。底部输入栏始终是一张 18px 圆角、只有细边的卡片，与会话卡片同色。桌面收成一行：最左「+」、文字、「切换模型」、圆形「发送」；手机文字单独占上一行，控件在下一行。「切换模型」每个 Agent 一个设置，列表按服务分组并附说明，窄屏截断，按钮前不放图标；所选模型列出思考强度时紧随其后出现「思考 · 默认」按钮，菜单只有「默认/关闭/低/中/高/最大」几项、不带说明（只列该模型支持的档位，不支持的模型不显示该控件而不是置灰；可用档位见[模型连接](MODELS.md#思考强度)，用户可在服务商表单里逐个模型改写），最右是 30px 圆形「发送」按钮（手机 44px），没有可发送内容时为灰底而不是褪色的橙色，处理中换为同尺寸的停止按钮，停止即撤回这次请求：不保存任何内容，提示“已取消，对方不会回复这条消息。”，文字回到输入框；提供者支持附件时才有「+」，菜单只有一项「图片和文件」（桌面带 ⌘U／Ctrl+U 快捷键，输入栏可见且没有弹窗时按下同样打开选择器；进入扩展管理或打开弹窗后不响应），不因所选模型置灰；也可把文件拖到窗口的任何位置（列表、窄栏、会话头部、消息区与输入栏都可以）或粘贴图片：外壳把拖入交给当前工作区发布的 `drop`，拖动经过时整个窗口显示一层提示，会话打开时写明“松开以添加附件到「名称」的会话”，松开即加入该会话的待发送附件；没有 Agent、未选择 Agent、提供者不收附件或正在编辑消息时，提示说明原因并拒绝拖放。扩展管理与弹窗中不转交，拖放被拒绝且没有提示；自带拖放区的弹窗（如安装扩展）先处理自己的拖入。其余没有处理者的位置由外壳拒绝（[file-drops.ts](../src/shell/file-drops.ts)），窗口不会改为打开该文件（回归见 `chat-drop.spec.ts`）。模型不读图片时图片照常添加，发送时在模型一侧换成一行 `ERROR: Cannot read "文件名" (this model does not support image input). Inform the user.`，图片字节不上传；待发送的附件在输入行上方以可移除的标签排列，失败的发送保留它们；桌面上拖入、选择或粘贴附件后焦点回到输入框（另一处正在输入时除外），回车即可发送；只有附件、不写文字也能发送（编辑带附件的消息时同样可以清空文字），这样的消息只显示附件、没有空气泡，菜单不提供复制，编辑栏与列表摘要写作“[文件] 名称”“[图片] 名称”，首条消息为它时会话以第一个文件名命名；发出的消息在气泡上方显示文件标签与图片缩略图，点开预览，手机同一布局；手机与桌面是同一套布局，底部留出安全区。聚焦时外框不变，以光标表示焦点，也不显示快捷键提示。写入派发后进入不可撤回的提交段，显示等待保存并禁用停止；成功回执优先。成功保存后清除对应草稿；失败和提交前取消保留草稿与上次保存的消息。输入与服务回复都在保存前验证字符串类型及 1,000,000 个 UTF-16 代码单元上限；消息逐条存为记录，单条可达数 MB。桌面 Enter 发送、Shift+Enter 换行，输入法组词和确认按键不发送；消息框同时检查 `isComposing` 与 WebKit 的 `keyCode === 229`，确认后再次按 Enter 才发送。手机通过发送按钮提交。

记忆由内置扩展“记忆”（`memory.local`，[契约](EXTENSION-CONTRACTS.md#记忆服务契约)）提供，是「组成扩展」里的一行：名称下写“记得 N 件事”（未过期的、只算这个 Agent 自己记下的）或“还没有记下什么”，关闭后红字写“已关闭：它不会记得以前会话里的事”；点名称打开记忆页并停在这个 Agent，而不是进入扩展管理。记忆页是一个对话框，顶部的“查看谁的记忆”在“关于我”（写给所有 Agent 的资料，只由你填写，所有 Agent 回复你时都会读到）与各个 Agent 之间切换。每条记忆显示内容、时间（有的话）与“从对话中记下”的来源，悬停或聚焦时出现编辑与删除；编辑可改内容、时间和到期时间。过了到期时间（没有到期时间时取时间）的条目移到“已过期”，不再告诉 Agent，说明下次整理时会删掉或改写，也可以删除或补充时间让它重新生效。下方可以添加一条（可选时间与到期时间）。Agent 页显示整理状态：正在整理、有还没整理的对话（带“现在整理”）或失败原因（带“重试”）。底部是整理用的模型：“关于我”页设默认值（跟随各 Agent 自己的模型，或指定一个模型），Agent 页可选“用默认设置”“用它自己的模型”或指定模型；所选模型与这个 Agent 回复用的不在同一个服务时，橙色说明“整理时，「名称」的对话会发送到「服务」”；并说明每次整理会额外调用一次模型、可以选便宜的模型。整理完成后，Agent 界面弹出“「名称」记下了“……”，更新 N 条”之类的提示并带“撤销”。移除 Agent 的确认会写明同时删除它的记忆。

详情只回答“它是谁、由什么组成”：介绍、设定（提供者支持时显示，超过 6 行先折叠；节标题旁的说明写明只发给模型）与「组成扩展」列表。介绍与设定都可就地编辑：鼠标移到文字上时右侧出现铅笔按钮，键盘聚焦时同样出现，触屏常显；保存失败时保留编辑内容并在详情内提示。每行是扩展名称、一句作用说明和开关，关闭只影响这个 Agent 并用红字说明后果；点名称进入扩展管理并选中该扩展。模型、会话、置顶等操作留在使用它们的地方。删除最后一个会话后保留一个新的空会话。每个 Agent/会话拥有独立草稿。

单选使用与菜单同风格的下拉框（[`Select`](../src/components/Select.tsx)，基于 shadcn/ui Select），不用原生 `<select>`：按钮显示当前项，列表可按分组标题列出并附说明；方向键、Home/End、Enter/空格与原生一致，Esc 与系统 Back 只收起列表，不关闭所在弹窗。

弹窗内的长表单（如[模型连接](MODELS.md)的服务商表单）按节分组，节标题下用分隔线隔开；成对的短字段并排，窄于 520px 时合为一列；可选项收进「高级选项」；保存与返回固定在弹窗底部，滚动时始终可见。从服务获取的长列表用可筛选的勾选列表，不用下拉框。

由另一步进入的弹窗在标题左侧提供返回按钮，回到上一步而不是关闭全部：添加方式菜单进入的创建、导入和安装，菜单进入的设置回到发起处，安装预览回到选择文件（预览默认只显示名称、作者、说明与需要的权限，扩展 ID、版本、服务与来源收在可展开的“技术详情”里），服务商表单底部的“返回”回到服务商列表；关闭按钮与 Esc 仍关闭整个弹窗，系统 Back 每次退一步。

普通弹窗打开后，若浏览器自动聚焦关闭按钮，则将初始焦点移到标题；标题不进入 Tab 顺序。焦点循环沿用 Radix；macOS 根据系统设置使用 Tab 或 Option-Tab 遍历控件，反向加 Shift，只有当前焦点作用域处理首尾循环。Ctrl/Command 组合键与输入法组合中的 Tab 不被循环逻辑接管。组词中的 Escape 留给输入法，结束组词后再按 Escape 才关闭最上层弹窗。关闭按钮默认透明无框，悬停显示背景反馈，Tab 聚焦保留橙色焦点环；已聚焦的表单控件和无标题详情弹窗保留原行为。

弹窗通过发起事件记录返回控件，兼容点击后按钮未获焦点的 WebKit 行为；菜单操作返回稳定的菜单按钮，嵌套弹窗分别记录各自发起控件。关闭时优先返回仍连接且可见的发起控件；删除发起控件后，在仍打开的最上层详情弹窗内选择可操作按钮，无弹窗时回到工作区首个可见且启用的按钮，不穿过隐藏区或下层模态。

窗口达到 652px（40.75rem）时保留导航栏、Agent 列表和会话两栏，700–735px 半屏不会切成单页。这个下限由 68px 导航栏、208px 列表、8px 栏间隙、360px 会话和 8px 右留白组成；CSS 与工作区行为使用同一断点；全部布局宽度（表单 520px、两栏 652px、扩展管理 768px、详情并排 1100px）只在 `src/app.css` 的 `--breakpoint-*` 与 `src/components/breakpoints.ts` 中定义，测试保持两处一致。小于 652px 时才在列表和会话之间单页切换，返回按钮回到列表；跨断点及切换 Agent 保留会话草稿。手机会话与桌面是同一套 IM 样式：字号 15px，对方消息不标注名称（头部已有），不显示悬停/右键消息操作，头部左侧带小头像，输入栏见上。详情使用带深色遮罩的模态浮层，焦点保留在浮层内，关闭后返回发起控件。中等宽度将详情浮在工作区侧边。列表、消息和详情分别滚动，触控操作至少 44 CSS px。

Android 开发候选的系统 Back 先收起 IME，再关闭顶层菜单/下拉列表/弹窗、退出管理页回到工作区，最后执行工作区返回；默认 Agent 会话返回列表并聚焦相应角色，未发送草稿保留。工作区根层才交回系统退出。公开入口和当前交付差异见 [Android 系统 Back](ANDROID.md#系统-back)。

## 菜单、外观与扩展管理

`html`、`body`、`#root` 不滚动也不回弹（`overscroll-behavior: none`），各栏自己滚动。角色与会话标题由会话头部显示，顶栏不重复；扩展仍可经 `View.chrome` 显示自己的标题。顶栏不显示运行环境或阶段标签。主题、菜单及侧栏按钮默认透明，悬停和按下显示反馈。

“设置”（桌面在窄栏底部，手机在顶栏）打开应用设置，“扩展”打开扩展管理。应用设置按“名称—操作”的行排列：界面布局与外观主题为分段按钮，颜色模式、管理扩展、关于 Plums 和诊断（仅开发构建）各一个按钮，不使用系统下拉菜单；从设置打开的“关于”可用返回键回到设置。默认界面不显示角色、对话、扩展标签，也不显示工作台/画布选择栏；原实验工作台、画布与逆序服务只在开发构建的目录中，可从诊断启动，再从设置选择；打包默认组合仅有 Agent 核心、模型连接和 Agent 界面。

界面以梅子品牌图标为视觉起点，浅色使用白底橙色图标，深色自动切换为黑底橙色图标（`/brand/plums-dark.png`）。浅色采用`#FFFFFF`主背景、`#F7F7F8`表面、`#EDEDF0`弱表面、`#1A1A1A`主文字；深色采用`#171718`主背景、`#1F1F20`表面、`#252525`卡片、`#2A2A2C`浮层与输入框、`#2D2D2F`弱表面和`#E8E8E8`主文字。两种主题保持`#F57D4A`橙色主操作。窗口底色、会话卡片、气泡、列表三档与窄栏图标另用布局色，取值与推导规则见[主题契约](THEMES.md)。手机与桌面使用同一套配色与无衬线字体，不再另设配色。手动主题贡献以内联变量写入根节点，仍优先于这套默认配色。桌面端采用紧凑的 13–14px 排版与 32–36px 控件高度，紧凑布局（`< 652px`）保持至少 44 CSS px 触控目标。按钮、线性图标、输入、菜单和弹窗共用语义变量。浮层使用 10–12px 圆角，标题、内容和操作区分层；悬停变化背景与细边，键盘操作显示焦点环；输入框、多行输入框与会话输入栏有光标表示焦点，聚焦时不加光环、边框与底色不变（出错时的红框照常）；占位文字单独后移 2px，光标不压在中文首字的笔画上；焦点环只跟随浏览器的 `:focus-visible`，点按或点击后弹窗、菜单归还焦点时不显示，键盘导航时显示（Chromium 与 WebKit 回归见 `focus-ring.spec.ts`）。授权弹窗与通用弹窗打开时焦点落在标题。尊重减少动态效果偏好。

首次外观取系统设置；手动主题、布局和导入扩展的位置经串行 `host.shell` 保存；本地角色/会话由 `agents.local` 存于自身状态。新保存的布局记录 `layoutIntent: explicit`；旧配置仅在布局为 `default`、无显式来源且无已存组合时采用 Agent 起始界面，启动不自动覆写存档，下一次成功保存才提交新偏好。带显式来源、已存组合或其他布局 ID 的偏好继续保留，真实失效仍提供诊断。视图挂载失败时回退到最近可用界面或保留原偏好标识，不写入空布局；解析到空布局按默认界面处理。平台初始化失败在启动提示和对应管理区域显示原因与重新加载指引，只有明确探测为不支持才显示“平台不支持”。写入失败保留已确认状态，未知写入回执要求重新加载后再修改。损坏或未知配置拒绝覆盖。消息恢复仅接受字符串 `user` 或 `agent`，数组等错误角色类型使 `agents.local` 启动失败并保留原数据，不自动转换；应用其余部分照常可用。桌面窗口与 Android 系统栏通过 `shell_set_theme` 同步；Android 系统栏、缺口及键盘 Insets 来自受控模板，详见 [Android 工程](ANDROID.md)。

扩展管理列表的卡片只显示名称、状态、ID 与版本、使用者数量和操作，名称与状态同行、操作在右侧；节标题旁的说明（如按 Agent 开关、文档授权范围）收进说明按钮；点选卡片后，详情先显示扩展用途介绍，再显示使用者、模块位置、服务、权限、资源和任务。扩展管理在窗口宽度达到 768px（48rem）时保留左侧列表与右侧详情，默认 960px 窗口无需额外操作即可阅读介绍；列表最小 280px、详情最小 320px，列宽按扣除间距后的剩余空间分配。低于 768px 时在所选卡片内展开同一详情，缩放保留所选扩展，文字可换行而不横向溢出。工作区侧栏按钮仅在工作区显示，不在管理页控制被隐藏的业务界面；返回工作区保留原侧栏状态和草稿。从 Agent 详情点扩展名称进入时直接选中并滚动到该扩展。安装对话框先提示只导入可信来源的文件，可点按钮选择或拖入单个 .js 文件（触屏不显示拖放提示）（桌面窗口关闭了 Tauri 拖放拦截，交给页面处理）；读取后显示 ID、版本、服务、权限、联网目标与来源哈希，确认导入后保持停用，同 ID 显示为“替换”。开发者仍可按模块路径安装（发布构建中折叠在“开发者”下）：入口加载同源可信 ESM 并保存模块路径；加载代码会执行，加载后仍需单独检查和启用，安装路径与启用意图自动恢复；能力授权按扩展版本保留，版本变化后须重新确认。保存的模块加载失败时保留外壳与数据，管理页允许重试或移除路径；同 ID 重新安装会替换失效路径。能力确认框允许取消或 Escape；确认后才授予并启动。停用后释放资源，清理失败保留诊断并禁止重启。管理页采用固定页头与独立滚动内容：返回键和安装入口保持可达，列表及详情在下方滚动。管理页隐藏不等于停用业务，保留工作区挂载。

## 所有权与公开契约

`ui.agents` 使用公开 `ctx.view` 挂载；`agents.local` 通过普通版本服务 `agents@1` 提供业务，`ui.agents` 以 `ctx.use` 获取，没有给通用内核或 SDK 新增聊天 API，服务契约见[扩展契约](EXTENSION-CONTRACTS.md#agent-服务契约)；提供者未实现可选的 `removeMessage` 时界面不显示删除。默认 UI 读取提供者的公开快照、订阅、操作和来源说明，不访问其私有状态，并保留普通类方法的接收对象。第三方提供者可替换该服务，也可贡献完全不同的 UI。

会话标题、当前 Agent 的扩展所有者和默认详情的真实状态通过当前视图的可选 `View.chrome` 发布。Agent 界面发布了自己的详情，所以扩展的上下文侧栏目前不在这里出现（选择规则与后续方向见[作者指南](SDK-AUTHORING.md#工作区标题与上下文侧栏)）。Agent 详情的「组成扩展」与添加页同样逐行列出提供者、界面（`ui.agents` 经 `ctx.shell.dependencies()` 取得自身名称）、模型连接，点按名称进入扩展管理并选中（悬停显示扩展说明），行尾开关为此 Agent 开启或关闭；回复只来自所选模型，没有可用模型连接时提示选择或添加模型，输入卡片与草稿仍保留。为某个 Agent 关闭界面后会话与输入区照常显示，卡片内提供“开启”操作，恢复前不能发送。节的背景说明（角色卡不授予权限）放在节标题旁的说明按钮里。扩展管理只显示扩展经 `ctx.shell.publishUsers` 公布的使用者，不读取 Agent 数据：可开关的扩展列出全部 Agent，实心带勾为开启、虚线为关闭，点按切换；停用仍有使用者的扩展前弹出确认并列出它们，开关在重新启用后恢复；`WorkspaceChrome.navigation` 仍是 SDK 中的实验字段，外壳暂无消费者。状态所有权与模块入口见 [前端架构](ARCHITECTURE.md#当前前端的状态所有权)。

Agent 界面的组合、弹窗、卡片草稿与后备焦点位于 [src/agents](../src/agents/)。弹窗组件随工作区常驻，关闭仅移除 Dialog，保留创建说明、多会话选择及卡片输入；成功添加后沿用原重置规则。媒体查询在 Hook 内创建和订阅，模块导入不访问 matchMedia。

角色、会话、文本处理与卡片解析位于扩展层；`src/application.ts` 接线默认组合、内置授权与旧数据迁移，通用外壳只保存不透明业务字段。Agent/会话存于 `extension.agents.local`；文本处理工作台通过自身 `ctx.platform` 另存于 `extension.ui.workbench-board`，页面贡献的业务数据归各贡献者管理。每个状态文档受[状态层上限](SDK-AUTHORING.md#状态取消与演进)约束；通用升级迁移尚未实现。置顶直接保存为每个 Agent 的 `pinned` 字段，避免维护第二份 ID 列表。

外壳保留扩展管理、授权与无布局恢复入口。启用提供新视图的扩展时优先选中其视图；用户可在设置切回。`ui.default` 与 `ui.board` 保留公开挂载路径。挂载失败排除该代视图并回退到可用界面；无布局时展示宿主恢复入口；未安装文本工作台实验的组合仅提供扩展管理，不展示该实验的授权启动按钮。无 `agents` 服务的独立组合可照常启动、管理与恢复。共享 WebView 的可信模式不构成防恶意代码或界面伪装的沙箱。

[src/app.css](../src/app.css) 用 Tailwind v4 把 `src/styles.css` 中的语义颜色映射为工具类，并定义 `shadow-panel`／`shadow-raised`／`shadow-float` 三级阴影：常驻卡片、悬浮控件和浮层依次加深。`src/styles.css` 保留颜色变量、主题后备和普通元素样式，供扩展自行渲染的 DOM 继承；默认界面的布局与组件样式都写在 TSX 的工具类里，不再使用 CSS module。

动效只用于说明变化：切换界面时内容侧滑淡入，列表选中底色以弹簧动画滑到新位置，新消息上浮出现，列表项与横幅展开收起，顶栏标题与会话头部交替时淡入淡出，详情从侧边滑入。每个 React 根节点以 `MotionConfig reducedMotion="user"` 遵从系统“减少动态效果”，CSS 动画同时缩短到近乎为零。菜单不做退出动画，避免仍在淡出的旧菜单把重新打开的菜单当作外部点击关闭。

图标源为 `src-tauri/icons/source.png`，`npm run icons` 生成 Mac、Android 与 Web 资源。公开 `ctx.theme` 可贡献这17个语义色和可选的布局色，应用设置选择、停用回退和保存规则见 [主题契约](THEMES.md)。原生窗口/系统栏只跟随明暗模式，未扩展到任意原生颜色。内置CSS为恢复后备；这是实验契约，尚非稳定主题或 Agent SDK。

## 手动安装扩展卸载

扩展管理为手动安装项提供“卸载（保留数据）”，确认框说明依赖等待和数据保留。内置项只停用。成功后从目录和持久化安装路径移除并把焦点返回管理标题；取消返回发起按钮。清理/撤权/保存失败留在确认框，扩展可能已停用，须重试或重载确认；未知保存回执不允许继续写配置。扩展状态与模块文件不删除，同 ID 重装重新授权。

## 组合与提示

启用、停用和授权自动记录，下次启动恢复，不提供手动保存按钮；同一扩展已授予的能力不再重复弹出授权框。写入失败用错误提示说明，不增加弹窗或新的导航层。

操作结果与错误以顶部居中的浮层提示显示，不需要手动关闭：按文字长度停留 3–10 秒后淡出，指针悬停时保持；新消息替换旧消息。删除消息或会话后，提示“已删除消息”或“已删除会话”带一个品牌色“撤销”按钮，停留 8 秒，用指针点它不会把焦点移进提示（否则 WebKit 会聚焦提示项，提示消失时又把焦点拉回原处，关掉刚打开的菜单）；撤销成功显示“已恢复”，会话已有新消息时说明无法撤销（提供者未实现 `undo` 时不显示按钮，回归见 `agent-undo.test.ts`、`chat-undo.spec.ts`）。删除会话仍先确认，确认框说明可以在提示中撤销。打开模态对话框时提示显示在对话框内，不被遮住；对话框内的失败文字自带步骤与后果（如“卸载未完成：…”）。图标按钮的说明用应用内悬停提示而非系统 `title`：指针停留约 0.4 秒或键盘聚焦时出现，离开、按下或 Esc 隐藏，触摸不显示，贴近窗口边缘时留在可见范围内。较长的字段解释放在字段名旁的标准 Popover 说明按钮里：鼠标移上去约 0.15 秒显示、移开即收起，不移动焦点；点击、点按或键盘激活则保持打开并把焦点移进说明，再按一次、Esc 或点别处关闭，Esc 返回按钮焦点（回归见 `feedback.spec.ts`）；弹窗内的 Popover 沿用同一层容器，读屏可读到全文。API Key 输入框默认隐藏，右侧使用 Lucide 的 Eye/EyeOff SVG 切换当前输入的显隐；保存或清空后复位，已保存密钥不回读。会改变操作结果的提醒（如获取列表前会先保存）仍直接显示。需要用户操作的提示（如所选界面不可用的“查看原因”）仍为常驻横幅。坏组合结构由启动错误提示提供“恢复默认组合”，确认说明备份与数据保留；取消回到触发按钮，成功/失败关闭后聚焦重新加载。详见 [组合契约](COMPOSITION.md)。
