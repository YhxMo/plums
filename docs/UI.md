# 默认界面与跨端体验

[架构](ARCHITECTURE.md) · [扩展契约](EXTENSION-CONTRACTS.md) · [设计规范](DESIGN.md) · [验证证据](../evidence/RESULTS.md)

状态：当前有效（2026-10-27 核实）；默认界面的布局与行为。颜色、字号、线条与动效的标准见[设计规范](DESIGN.md)，验证范围见证据索引。

## 添加与导入 Agent

- **欢迎页**：没有 Agent 时会话卡片居中显示梅子线条图标、“还没有 Agent”与两个按钮：添加 Agent（主）、导入角色卡（次）。已有 Agent 但未选中时，右侧只显示居中的 Plums 图标；手机先显示列表。列表顶部的“+”菜单有添加 Agent、导入角色卡…；安装扩展在“扩展”里。
- **添加分两步**：第一步写名称、设定（预填“简洁、友好地回答用户的问题。”）和可选的介绍，有名称后才能“下一步”。第二步选模型并开关组成这个 Agent 的扩展（Agent 核心、界面、记忆、所选模型的连接，按默认组合预先开启）；关闭任一项时行内用红字说明后果。右上角“管理模型连接”（没有模型时为“添加模型连接”）在这一步之上打开连接器自己的页面，多个连接器有页面时先选一个；关闭后回到这一步，已填内容不变。“上一步”与系统 Back 回到第一步并保留内容；只有“添加”才保存。没有模型也能保存，之后在会话里连接模型。
- **导入角色卡**：对话框只负责拿到卡片（选择或拖入文件、读取应用内链接、粘贴内容），“下一步”进入预填好的添加页，照样两步。支持酒馆通用的图片角色卡（PNG tEXt：V3 `ccv3` 优先，其次 V2 `chara`，[card-png.ts](../modules/agents/card-png.ts)）与同样的 V2/V3 JSON：描述与性格合为设定，创作者备注作介绍，带 `extensions.plums` 时以其中的设定与介绍为准，图片裁成方形作头像。实验 JSON 卡片仍可用（`name` 必填，可选 `description`、`instructions`、`avatar`）。链接只读应用同源地址、拒绝重定向；文件与链接都最多 20 MB，链接 10 秒超时，取消会中止读取。导入角色卡不授予任何能力或访问权限。
- **拖到列表**：把角色卡（PNG、JSON）或 Agent 包（`.plums`）拖到 Agent 列表上，显示“松开以导入角色卡或 Agent”，松开即打开导入页并读入；其他类型或多个文件被拒绝并说明原因。
- **介绍与设定**：介绍给人看，显示在列表摘要与详情，不发给模型。设定只发给模型；系统提示词依次是“你是「名字」”、当天日期与时区（只到日，便于服务商缓存）、“只能在收到消息时回复，不能主动发消息或到时提醒”、设定，再加记忆段落（[instructions.ts](../modules/agents/instructions.ts)）。
- **导出角色卡**：存成 512×512 的 PNG（用头像，没有时画默认梅子），可被 Plums 与酒馆导入：V2 `chara` 的 `name`、`description`（设定）、`creator_notes`（介绍），另在 `extensions.plums` 原样保存设定与介绍（[card-export.ts](../modules/agents/card-export.ts)）。不含记忆、会话、模型选择、密钥与组成扩展。经宿主能力 `file.save` 由用户选位置保存（浏览器预览为下载）。
- **导出 Agent 和扩展**：打成 `.plums`（zip，[agent-bundle.ts](../modules/agents/agent-bundle.ts)）：`card.png`、记录格式版本与组成扩展（ID、版本、对这个 Agent 关闭了哪些）的 `agent.json`，以及第三方扩展的 `manifest.json` 与 `main.js`；内置扩展只记 ID 与版本。导出前列出将一并打包的扩展及作者与许可证，提醒代码会交给别人。导入时先把包里的扩展交给扩展管理逐个确认（同 ID 已导入时选“替换”或“保留现有”），安装后保持停用、启用时再授权；然后进入两步添加，按包里的开关预设，缺少或版本不符的扩展保持关闭并说明原因。

## 窗口与布局

- **Mac 窗口按钮**：系统原生常规尺寸，不自绘；`trafficLightPosition` 距左 7pt、距顶 20pt，放在导航栏顶部，相邻按钮左缘相距 20pt（系统默认 23pt）。AppKit 在调整大小、全屏、平铺与明暗切换后会复原间距，[window_frame.rs](../src-tauri/src/window_frame.rs) 在窗口事件后放回。标题栏隐藏、内容铺满；导航栏为按钮预留顶部 44px，窗口顶部有 12px 拖动条，各栏头部与空白会话卡片顶部也可拖动窗口。
- **材质**：窗口透明，只有导航栏透出系统侧栏材质，叠一层浅色 White A5、深色 White A1（`--rail-glass`）；其余铺实底，“减少透明度”时由系统换成实色。
- **尺寸**：默认 940×640pt，最小 652×600pt（始终三栏：列表 ≥ 208、会话 ≥ 360），不设上限，全屏与平铺铺满。只记住上次尺寸（官方 window-state 插件），恢复时不小于最小值、不超出所在屏幕。
- **三栏**：最左是宽 68px、通到窗口顶边的导航栏；中间是 Agent 列表（默认 256px，208–380px，与会话卡片之间 8px 的间隙可拖动调整宽度）；右侧是浮起的会话卡片（距窗口与列表各 8px，14px 圆角，只有细边）。导航栏与列表共用窗口底色（`--chrome`）。扩展管理与其他工作区也放在同样的卡片里；视图声明 `frame: "own"` 时自己画卡片，共用 `--pane-gap` 与 `--pane-header`（[src/app.css](../src/app.css)）。
- **导航栏**：顶部是用户头像（中性灰的空白梅子；有扩展贡献 `entry: "user"` 的 dialog 视图时成为打开它的按钮，内置记忆的是“记忆”，停在“关于我”），其下是扩展贡献的工作区，底部是“扩展”与“设置”。每项 44px，只有图标，悬停提示与 `aria-label` 给出名称，当前项为橙色并带 `aria-current="page"`。工作区图标来自 `View.icon`（扩展自带的单色 SVG，宿主以遮罩着色，规则见[页面契约](PAGES.md)），无效时用通用图标。
- **断点**：窗口不小于 652px 时保持三栏，半屏不切单页；更窄时在列表与会话之间单页切换，返回按钮回到列表，草稿保留。全部布局宽度（表单 520px、两栏 652px、详情并排 1100px）只在 `src/app.css` 的 `--breakpoint-*` 与 `src/components/breakpoints.ts` 中定义，测试保持一致。
- **手机**：不显示导航栏，“扩展”与“设置”在顶栏；会话头部左侧带小头像，消息 16px，不显示悬停与右键消息操作；详情为底部弹出层；触控目标至少 44px，底部留安全区。
- **滚动**：`html`、`body`、`#root` 不滚动也不回弹，列表、消息与详情各自滚动。

## Agent 列表

- 顶部是搜索框与“+”。每行 68px、通栏、不画分隔线：44px 头像、名称、末条消息时间与摘要（末条消息或介绍）。置顶的排在最前，其余按最近活跃倒序；置顶保存为每个 Agent 的 `pinned`。
- 三档底色：选中为 Orange 9 配白字，置顶为 `--row-pinned`，其余为列表底色。选中行白字对比约 3:1，是所有者确认的取舍（与微信绿底白字同类）。
- 头像右下角的状态点：等待回复为橙色并缓慢呼吸，在线为绿色，空闲不显示。有未读回复时摘要右侧显示橙色数字（超过 99 显示 99+）；未读按会话的 `lastReadAt` 计算，重启后保留，正在看的会话不计未读，在扩展管理中也不标记已读。
- 行按钮的名称就是 Agent 名称；`aria-describedby` 读出末条消息（前 120 字）、时间、“正在输入”与“N 条未读”，状态不只靠颜色。
- 行不放“…”：右键或长按打开菜单，依次为置顶、重命名、导出角色卡…、导出 Agent 和扩展…、Agent 设置…，分隔线下是移除（先确认删除范围，并写明会同时删除它的记忆）。键盘用户选中后用会话头部的“…”。

## 会话

- **头部**：与消息区同色，一行内是加粗的名称与会话标题胶囊；胶囊是会话菜单（切换、新建、重命名、删除；超过 8 个会话时顶部有筛选框）。右侧只有“…”菜单（与列表行相同）和外壳的右侧栏按钮。首条消息给“未命名会话”起名；删除最后一个会话后留一个新的空会话。
- **等待回复**：同一 Agent 一次只等一条回复，等待中只有那个会话不能删除，别的会话照常使用；在别的会话里发送时输入栏说明原因并提供“查看”。回复整条送达：名称下出现橙色“正在输入”和三个起伏的圆点，消息区不放占位气泡；这一行是 polite live region，回复由消息区的 `role="log"` 读出。
- **消息**：不带头像，18px 圆角气泡（靠发送者一侧的底角 5px，桌面最宽为消息列的 75%）；回复在左（`--bubble`），自己的在右（Orange 9 配白字）；同一发送者连续消息间隔 4px，换人 12px。消息列最宽 600px。相邻消息间隔超过 5 分钟时插入居中的时间文字。空会话不显示任何内容，第一条消息一发出就出现。
- **回复的 Markdown**：按 GitHub 风格排版（`react-markdown` + `remark-gfm`，单个换行仍换行），代码块可复制；原始 HTML 不渲染，图片不加载（只显示“[图片：替代文字]”）；只有 `https://` 链接可点，经宿主能力 `link.open` 在默认浏览器打开，应用窗口不跳转。
- **跟随滚动**：只在停在底部时跟随新消息（[useFollowBottom.ts](../src/agents/useFollowBottom.ts)）；向上翻看时到达的回复不把视图拉下，底部出现“回到最新”，有新回复时变为“↓ 新消息”。发送、撤销删除、编辑后发送与重新生成完成后回到最新消息；切换会话从末尾开始；减少动态效果时直接跳转。
- **消息操作**：悬停或键盘聚焦时在气泡下方、对齐气泡右缘出现复制、编辑（自己的）或重新生成（回复）、删除；右键打开同样的菜单。等待回复时只能复制。编辑参照 Telegram：文字放进输入栏，上方显示“编辑消息”与原文，× 或 Esc 退出并还原草稿；发送后从这条消息起改写，停止则原样恢复。重新生成以这条回复之前的消息重新请求。两者要删掉更多后续消息时先说明条数并确认；完成后的提示带“撤销”，放回改写前的整段对话。
- **输入栏**：22px 圆角、只有一圈细边的卡片。桌面一行：「+」、文字、「切换模型」、可选的「思考 · 默认」、圆形「发送」；手机文字单独一行。「切换模型」按服务分组；思考强度只列所选模型支持的档位（[模型连接](MODELS.md#思考强度)），不支持时不显示。没有可发送内容时发送键为灰底；处理中换为停止键，停止即撤回：不保存，提示“已取消，对方不会回复这条消息。”，文字回到输入框。桌面 Enter 发送、Shift+Enter 换行，输入法组词与确认按键不发送（同时检查 `isComposing` 与 WebKit 的 `keyCode === 229`）；手机用发送键。
- **模型与发送条件**：未选模型时按钮写“未选择模型”；没有可用模型时菜单提供“连接模型”，打开连接器自己的页面（多个时逐个列出），没有提供页面的连接器时打开扩展管理。界面、Agent 核心或所选模型的连接被关闭时，卡片内说明原因并提供“开启”。这些状态只阻止发送，仍可编辑文字和添加附件。
- **附件**：提供者支持附件时才有「+」（菜单“图片和文件”，⌘U／Ctrl+U）。也可把文件拖到会话卡片或导航栏上，或粘贴图片：拖动经过时显示“松开以添加附件到「名称」的会话”；没有可加入的会话、提供者不收附件或正在编辑时说明原因并拒绝。扩展管理与弹窗中不转交拖放，其余位置由外壳拒绝（[file-drops.ts](../src/shell/file-drops.ts)），窗口不会改为打开该文件。模型不读图片时照常添加，发送时在模型一侧换成一行说明，不上传图片字节。只有附件也能发送；发出的消息在气泡上方显示文件标签与图片缩略图。
- **保存**：写入派发后进入不可撤回的提交段，禁用停止；成功后清除草稿，失败与提交前取消保留草稿。输入与回复在保存前验证为字符串且不超过 1,000,000 个 UTF-16 代码单元；消息逐条存为记录。每个 Agent／会话各有草稿。

## 记忆

记忆由内置扩展“记忆”（`memory.local`，[契约](EXTENSION-CONTRACTS.md#记忆服务契约)）提供，是「组成扩展」中的一行：写“记得 N 件事”或“还没有记下什么”，关闭后红字写“已关闭：它不会记得以前会话里的事”；点名称打开记忆页并停在这个 Agent。

- **记忆页**：顶部“查看谁的记忆”在“关于我”（写给所有 Agent，只由你填写）与各个 Agent 之间切换，旁边一行小字说明谁会读到。每条显示内容、时间与来源，悬停出现编辑与删除。过期条目（过了到期时间，没有到期时间时取时间）不再告诉 Agent，折叠为“已过期 N 条”并可“全部清除”。下方一行可添加，“设置时间”展开时间与到期两项。
- **整理**：Agent 页在列表上方显示整理状态（正在整理、有未整理的对话带“现在整理”、失败原因带“重试”）。底部“整理用的模型”：“关于我”页设默认（跟随各 Agent 的模型或指定），Agent 页可选默认、它自己的模型或指定；与回复不在同一服务时用橙色说明对话会发送到哪个服务。整理完成后提示“「名称」记下了……”并带“撤销”。

## 详情

- 详情只回答“它是谁、由什么组成”：关闭按钮、48px 头像与名字、介绍、设定（超过 6 行先折叠）与「组成扩展」，节标题右侧是“扩展管理”。介绍与设定可就地编辑（悬停或聚焦时出现铅笔），保存失败时保留编辑内容。
- 「组成扩展」逐行是扩展名称、一句作用和开关，关闭只影响这个 Agent 并用红字说明后果；有自己页面的一行（如记忆）带 ›，点名称打开该页，其余进入扩展管理并打开该扩展的详情。
- 头像可点开菜单：上传图片…（居中裁成 256×256，压到约 36K 字符以内，GIF 取首帧）与移除。没有图片时是按名称散列配色的扁平梅子（配色表在 [plum.ts](../src/agents/plum.ts)）。
- 两个入口：菜单里的“Agent 设置…”以居中弹窗（手机为底部弹出层）打开任一行的详情，不切换会话；右侧栏按钮开关当前 Agent 的详情抽屉（宽 288px，窗口宽于 1100px 时会话让出位置，否则覆盖在会话上），扩展贡献的侧栏不接管它。右侧栏今后放什么待定。

## 扩展管理

- **卡片页**：页头是返回、“扩展”、数量与“安装扩展”。下面整页是扩展卡片，自动排成多列（每张至少 240px，默认窗口一行三张，手机一行一张），同一行同高。卡片上只有名称、两行以内的用途和右上角的开关（运行中为开，点按启用或停用，不打开详情）；有 Agent 使用时底部写出数量与名字（如“3 个 Agent：写作助手、代码助手、翻译…”，数量在前，过长以省略号结尾）；只有出问题或过渡中（激活失败、清理未完成、等待条件、停用中）才显示状态。诊断与已卸载扩展保留的连接列在卡片之后。
- **详情窗口**：点卡片任意处（键盘为名称按钮）弹出，标题是扩展名称：状态（运行中绿点、失败红点、其余灰点）、ID、版本与同一个开关，失败原因随后；然后是操作（打开它的页面、配置、卸载）、用途介绍、使用者（可按 Agent 开关时实心带勾为开、虚线为关）、获授权的文档、模块位置、服务、权限、资源与任务。改动即时生效，以“完成”结束，关闭后焦点回到卡片。打开扩展自己的页面（如模型连接）时该页面取代详情，关闭后回到卡片；配置、卸载与停用确认叠在详情之上。从 Agent 详情或提示进入时直接打开对应扩展的详情。
- **停用与使用者**：扩展管理只显示扩展经 `ctx.shell.publishUsers` 公布的使用者，不读 Agent 数据。停用仍有使用者的扩展前先确认并列出它们，重新启用后恢复。
- **安装**：先提示只导入可信来源；可选择或拖入扩展文件夹、扩展包 zip 或单个 `.js`，预览默认只显示名称、作者、说明与权限，ID、版本、服务、联网目标与来源收在“技术详情”。导入后保持停用并把焦点放在新卡片上，同 ID 显示为“替换”。开发者仍可按模块路径安装（发布构建折叠在“开发者”下）。启用需要的能力先确认，可取消；授权按扩展版本保留，版本变化后重新确认。
- **卸载与失败**：手动安装的扩展可“卸载（保留数据）”，内置扩展只能停用；清理、撤权或保存失败留在确认框，须重试或重载。保存的模块加载失败时保留外壳与数据，可重试或移除路径。停用释放资源，清理失败保留诊断并禁止重启。扩展配置见[配置契约](EXTENSION-CONFIGURATION.md)。
- 管理页隐藏不等于停用，工作区保持挂载；工作区侧栏按钮在管理页隐藏，返回后恢复原状态与草稿。

## 设置、菜单与快捷键

- **设置**：两组细边框列表。第一组：颜色（跟随系统／浅色／深色，默认跟随系统，实时随系统明暗切换）、主题（内置或扩展贡献）、界面（已启用的界面）；第二组：诊断工具（仅开发构建）与“关于 Plums”（显示版本）。打包默认组合只有 Agent 核心、记忆、模型连接与 Agent 界面；文本工作台等实验只在开发构建中。
- **应用菜单**：Mac 屏幕顶部的中文菜单承载 ⌘,（设置）、⌘N（新建 Agent）、⌘F（搜索 Agent），并保留编辑、全屏与窗口命令；新建与搜索交给当前工作区（`commands`，见 [SDK 作者指南](SDK-AUTHORING.md)），扩展管理或模态窗口显示时不执行。浏览器预览按同一组键触发同一批命令。键位在 [menu.rs](../src-tauri/src/menu.rs) 与 [app-commands.ts](../src/shell/app-commands.ts) 各一份，测试核对一致。
- **外观来源**：内置浅色与深色取自 Radix Gray 与 Orange，取值在 [src/styles.css](../src/styles.css)，经 [src/app.css](../src/app.css) 映射为 Tailwind 工具类；扩展贡献主题的规则见[主题契约](THEMES.md)。桌面窗口与系统栏经 `shell_set_theme` 同步明暗；Windows、Linux 的窗口底色到对应平台再随系统更新。图标源为 `src-tauri/icons/source.png`，`npm run icons` 生成各平台资源。

## 弹窗、焦点与提示

- **下拉框**：单选用与菜单同风格的 [`Select`](../src/components/Select.tsx)，不用原生 `<select>`；Esc 与系统 Back 只收起列表。
- **长表单**：按节分组，成对短字段并排（窄于 520px 合为一列），可选项收进「高级选项」，保存与返回固定在底部。从服务获取的长列表用可筛选的勾选列表。
- **分步弹窗**：由另一步进入的弹窗在标题左侧有返回按钮，回到上一步；关闭按钮与 Esc 关闭整个弹窗，系统 Back 每次退一步。改动即时生效的窗口以“完成”结束。
- **焦点**：弹窗打开时焦点在标题（标题不进入 Tab 顺序），焦点在弹窗内循环（macOS 按系统设置用 Tab 或 Option-Tab）；组词中的 Escape 留给输入法。关闭时回到仍可见的发起控件（兼容点击后按钮未获焦点的 WebKit）；做完的事让发起控件失去意义时（添加或移除 Agent），焦点落在 Agent 工作区整体。焦点环只跟随 `:focus-visible`；输入框聚焦时外框不变，以光标表示焦点。
- **提示**：操作结果与错误在顶部居中浮层显示，按文字长度停留 3–10 秒，悬停时保持；打开弹窗时提示显示在弹窗内。删除消息或会话后提示带“撤销”（8 秒）；删除会话仍先确认。图标按钮用应用内悬停提示（约 0.4 秒，触摸不显示）；较长的字段解释放在 ⓘ Popover 里（悬停显示，点击保持并把焦点移入，Esc 返回）。需要用户操作的提示（如所选界面不可用的“查看原因”）是常驻横幅。
- **密钥输入**：API Key 输入框默认隐藏，可切换显隐；保存或清空后复位，已保存的密钥不回读。
- **动效**：几乎没有，只保留“正在输入”的圆点、头像状态点与详情抽屉 250ms 的滑入；减少动态效果时取消。

## 组合、保存与恢复

- 启用、停用与授权自动记录，下次启动恢复；同一扩展已授予的能力不再重复询问。手动主题、布局与导入扩展经 `host.shell` 保存，Agent 与会话由 `agents.local` 存于自身状态。写入失败保留已确认状态并提示，未知写入回执要求重新加载后再修改，损坏或未知配置不覆盖。
- 视图挂载失败时回退到可用界面，不写入空布局；无布局时显示宿主恢复入口。平台初始化失败时说明原因与重新加载方法。坏组合结构由启动提示提供“恢复默认组合”（[组合契约](COMPOSITION.md)）。数据角色类型错误时 `agents.local` 启动失败并保留原数据，应用其余部分照常。

## 所有权与公开契约

- `ui.agents` 经公开 `ctx.view` 挂载；`agents.local` 以版本服务 `agents@1` 提供业务，`ui.agents` 用 `ctx.use` 获取，内核与 SDK 没有聊天专用 API（[Agent 服务契约](EXTENSION-CONTRACTS.md#agent-服务契约)）。默认界面只读提供者的公开快照、订阅与操作；提供者未实现可选操作（如 `removeMessage`、`undo`）时界面不显示对应入口。第三方可替换该服务或贡献完全不同的界面。
- 会话标题、扩展所有者与默认详情的状态经当前视图的 `View.chrome` 发布（[作者指南](SDK-AUTHORING.md#工作区标题与上下文侧栏)）；`WorkspaceChrome.navigation` 仍是实验字段、外壳暂无消费者。状态所有权见[架构](ARCHITECTURE.md#前端的状态所有权)。
- Agent 界面的组合、弹窗与草稿位于 [src/agents](../src/agents/)；角色、会话与卡片解析在扩展层，`src/application.ts` 接线默认组合与内置授权，外壳只保存不透明业务字段。
- 外壳始终保留扩展管理、授权与无布局恢复入口。共享 WebView 的可信模式不构成防恶意代码或界面伪装的沙箱。
