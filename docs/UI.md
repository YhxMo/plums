## 工作区与扩展管理

工作区用于运行扩展、阅读结果和切换布局。扩展管理用于检查本地模块、能力、依赖、资源和任务，再启用或停用。桌面并排显示工作区和管理侧栏，分别滚动；窄屏在两个页面间切换，保留已挂载工作区及未提交输入。输入和结果按布局容器的可用宽度并排或纵向排列。诊断中的故障注入按需展开。

界面以白底橙色梅子图标为视觉起点：浅色使用暖白背景、白色卡片和陶土橙操作，深色使用暖炭灰背景、分层表面和柔和橙色操作。统一按钮、输入、选择框、状态标签、间距和文字层级；授权弹窗分为标题、能力列表与操作区，使用 12px 圆角和深色遮罩。触控操作至少 44 CSS px；窄屏重排内容，不整体缩小字体。

顶栏的太阳/月亮按钮切换深浅模式。首次读取系统当前外观；手动选择通过已有 `host.shell` 状态契约与布局一起保存，重启后恢复。保存失败保留当前模式并显示错误；切换不重新挂载工作区，未提交草稿仍在。桌面窗口外观和 Android 系统栏通过应用外壳的 `shell_set_theme` 原生命令同步，该命令只接受 `light` / `dark`，不处理业务数据。iOS 外观适配暂未实现。

颜色变量位于 `src/styles.css`；默认工作台与画布消费同一组语义变量。它们是 M1 默认界面的样式约定，不是稳定主题 SDK；其他布局仍可通过公开视图契约提供自己的样式和交互。图标源为 `src-tauri/icons/source.png`，`npm run icons` 使用锁定 Tauri CLI 生成 Mac、Android 和 Web 资源；其他平台的中间输出只保留在忽略的缓存中。

## 所有权与契约

应用外壳拥有扩展管理、应用内授权、布局选择与恢复提示。工作区的页面、局部导航、表单、结果及订阅由 `ui.default` 或其他布局扩展拥有，通过公开 `ctx.view`、`ctx.use` 和释放契约挂载。宿主和 SDK 不认识文本业务，也不要求聊天导航。

管理操作从 catalog 和 manifest 读取模块身份、版本、能力及服务依赖。能力授权前显示所需访问范围；取消或 Escape 不启用、不授权，关闭后焦点返回发起控件。扩展状态取自 `host.inspect`；清理失败保留诊断并禁止重启。

## 验收与既有覆盖

负责人为应用实现维护者；独立审查由未参与实现的执行者完成。对应 A3、A5–A8、A10 和 A12 的 M1 子集，结果和审查身份记录于验证证据。

| 路径 | 可证伪条件 | 覆盖入口 |
| --- | --- | --- |
| 查看模块 → 授权 → 运行 → 状态 → 停止 → 恢复 | 未确认即授予能力；取消仍启用；停用后资源或任务残留；恢复丢失已保存结果 | `application-flow.spec.ts`；既有宿主与持久化测试 |
| 布局替换、未知扩展、故障恢复 | 布局必须使用私有 API；替换后管理入口丢失；清理失败假报成功 | 既有 `workbench.spec.ts`、`dependency-chain.spec.ts` |
| 桌面、中等宽度、窄屏与键盘 | 普通内容横向溢出；管理页无法返回；授权焦点越出弹窗或丢失 | 新增应用流程测试；实际渲染检查 |
| 深浅模式、草稿与布局持久化 | 切换丢失草稿或结果；保存布局覆盖主题；重启丢失选择；写入失败假报成功 | `theme.spec.ts`；Mac / Android 分别运行验证 |
| Mac 包、Android 包和系统栏 | 浏览器结果替代原生结果；系统栏或键盘遮住操作；设备状态被写到主机目录 | 两端独立原生操作与 Android 工程流程 |

既有服务替换、撤权、取消、写入失败、清理失败和损坏状态测试继续复用。新增测试聚焦授权和跨页完整流程，不重复断言视觉 CSS。iOS、Android 真机和完整 A12 递归组合仍按原阶段边界推进。
