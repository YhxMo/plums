## 最小作者与管理入口

[作者指南](SDK-AUTHORING.md)提供三个可直接加载的 ESM 样板、精确版本规则、状态/取消和演进边界。`Host.uninstall(id)` 仅接受已成功停用（或从未启动）的 disabled 记录；撤销平台授权成功后才移除记录，失败保持可诊断和可重试。状态数据与模块文件保留，同 ID 重新安装须重新授权。不提供热升级、迁移或数据删除。外壳对手动安装扩展提供确认卸载，依次停用/撤权、保存安装路径移除、移除 Host 注册；失败保持诊断并可重试或重载确认，跨重启不再加载已确认移除的路径。

这是 M2 的实验作者入口子阶段；完整 A2/A11/A12 或正式稳定 SDK 尚未验收；后续外壳卸载的两端原生限定结果见证据索引。正式稳定之前仍须完成 iOS 最小原生风险实验。

## 契约覆盖范围

扩展可提供服务、主题、整体布局、导航、页面、交互、业务流程、模型适配、数据处理、外部连接及新的扩展点。消费者面向公开契约交换数据或调用能力，不依赖提供者私有实现。扩展点不能只是一份由内核预先写死的业务工具清单。

| 契约 | 最小语义要求 | 尚待决定的实现 |
| --- | --- | --- |
| 身份与兼容 | 能追溯来源、版本、内容及所需宿主/契约版本；不兼容时给出诊断 | 扩展格式、版本范围、完整性校验及分发方式 |
| 服务与依赖 | 必需依赖就绪后激活；可选依赖缺失可降级；提供者可替换 | 服务标识、类型表达、作用域、多提供者选择方式 |
| 注册与释放 | 每项服务、UI、监听、任务和临时资源有所有者及释放路径 | 上下文与资源句柄形式、清理顺序、截止时间 |
| 扩展点演进 | 插件可声明供其他插件使用的契约，具有版本与兼容规则 | 发现机制、命名冲突处理和协议协商方式 |
| 组合配置 | 可描述扩展、提供者选择、配置及依赖关系，支持保存与复用 | 组合配置与扩展集合的具体格式、分发和迁移 |
| 状态与迁移 | 通用持久化契约有所有权与版本；迁移失败不静默清空原数据 | 存储实现、事务边界、备份恢复与回退政策 |
| 取消与资源 | 任务可取消，运行受声明的能力和资源条件约束 | 超时、配额及可强制执行范围；可信同环境代码可能不合作 |
| 诊断与审计 | 可按扩展定位激活、依赖、权限、任务和清理失败；日志脱敏 | 事件格式、保留策略、审计入口和性能预算 |
| 通信与参与者作用域 | 能区分调用来源、接收方、状态所有权及取消关系，不预设单 Agent | 传输、发现、交接和关联追踪方式；不绑定特定协作协议 |

## 生命周期与失败行为

建议使用下列概念状态讨论行为，不预先冻结枚举或事件名称：

| 状态转移 | 必须明确的行为 |
| --- | --- |
| 已发现 → 检查兼容与依赖 | 来源、版本、所需能力可检查；依赖缺失、循环或冲突不会执行半套业务 |
| 条件未满足 → 等待或拒绝激活 | 诊断指出原因和恢复动作；可选依赖缺失不能被误当必需依赖就绪 |
| 条件满足 → 激活 → 可用 | 本次注册逐项绑定所有者；部分失败撤回本次本地注册，向依赖方暴露一致状态 |
| 可用 → 依赖失效或能力撤销 | 停止受影响的新调用；消费者暂停、失败或降级的规则明确，无悬空引用 |
| 可用 → 停用中 → 已停用 | 阻止新任务，取消或结束在途工作，按依赖顺序释放服务、视图、监听及资源 |
| 清理失败 → 可诊断的未完全停止 | 不显示“已完全卸载”；保留问题归属和恢复路径，必要时提示重启 |
| 已停用 → 卸载 | 代码与配置、用户数据的删除分别处理；删除范围明确，默认保留与删除政策待定 |
| 已停用 → 升级或重新激活 | 先检查兼容、状态迁移和依赖；不把重新激活直接等同于热更新支持 |

依赖失效传播、反向清理顺序、重复停用的幂等性及重复激活不泄漏资源，均需测试。M1 通过受控停用、替换和重新激活验证可替换性，不承诺无中断热替换。

生命周期管理的是可登记、可取消和可释放的资源，不承诺撤销任意外部副作用。插件须说明网络写入、外部文件改动等不可逆操作，以及可提供的补偿或重试策略；审计记录不能替代回滚。

### M1 已实现的失败语义

- 激活失败且清理成功后，下一次启用会创建新作用域并重试；清理失败则保留 `cleanup-failed`，拒绝重新激活，要求重新启动应用。激活超时单独报告为可重试（状态 `failed`），不沿用清理超时的“需重启”文案；清理超时仍要求重启。
- 视图释放支持同步或异步返回。释放抛错、拒绝或停用时超时会保留失败归属；后续停用不能把它改成已完全清理，也不盲目重试未知幂等性的释放函数。
- 普通停用、运行中撤销必需能力，以及同时提供服务和视图的扩展发生视图释放失败时，先将全部受影响作用域标为停用中并关闭工作入口，再触发任何同步取消通知，随后串行释放。事件接收/发送、注册、服务获取、任务及平台调用共用这一边界；已排队但未执行的任务在进入回调前再次检查。激活期间的合法调用仍允许。清理成功的消费者等待依赖，清理拒绝或超时的消费者保留 `cleanup-failed`；提供者替换不能复活清理未完成的链路。
- 业务通过 `ctx.platform` 传入操作取消信号，宿主将其与扩展生命周期信号合并。成功写入回执表示已保存；`AbortError` 或 `outcome: not-committed` 表示未提交。其他写入异常按结果未确认处理，先重新读取状态，再决定重试。
- 浏览器写入在同步提交前检查取消。原生写入在派发 Rust 调用后进入不可取消的提交段；M1 不提供原生在途撤回。此时显示等待回执并关闭业务取消按钮；收到成功回执后即使有取消请求，也不能报告未提交。
- 外壳状态使用 `host.shell`，经 SDK 调用的扩展状态统一使用 `extension.<扩展 ID>`，避免正常契约调用的身份碰撞。此命名空间不是对恶意桥接调用的隔离。
- 浏览器与 Rust 均拒绝未知 schema、无效文档和不匹配修订号，保留原数据；缺少状态与损坏状态分别处理。完整迁移和崩溃恢复仍未实现。

这些规则只描述当前实验 SDK。合作式平台适配器只有在能证明未提交时才可返回 `AbortError` 或 `not-committed`，不能把丢失回执当作取消成功。

## UI 组合与替换

工程目标包括应用自身 UI 的更改。公开机制应同时支持局部组合、整体布局与导航替换，以及插件继续开放新的 UI 扩展点。默认 UI 尽量依此实现；仅能换颜色或固定插槽加按钮不满足目标。

M1 当前通过 `ctx.view` 注册框架无关的挂载/释放函数，通过 `ctx.use` 消费服务。工作台与画布各自拥有页面结构、导航和订阅；切换布局会释放旧视图，业务的已保存状态归 workbench。管理页的显示/隐藏保留工作区挂载，不表示业务已停用，也不触发草稿重建。扩展管理、授权确认及无布局恢复由应用外壳持有；显示内容取自 catalog、manifest 和 `host.inspect`，没有新增业务专用内核入口。

可选 `View.chrome` 由工作区发布稳定快照和订阅，提供当前标题、上下文扩展所有者、默认详情、可选工作区 `back()` 及带实体类型的导航。Host 仅透传元数据；外壳只消费当前视图，在读取、订阅或操作失败时按视图 ID 与 generation 回退，保留管理入口。`back()` 只在工作区有上一层时提供；根层省略，返回后的焦点由工作区恢复。默认 Agent UI 也使用此接口；旧视图无需补充 chrome。接口用法、侧栏选择顺序和实体导航约束见 [作者指南](SDK-AUTHORING.md#工作区标题与上下文侧栏)。

0.0.2 在实际启用前显示所需能力，确认后才授予并启用；取消或 Escape 保持原状态，关闭弹窗后焦点回到发起控件。此为公开正常调用路径的应用内授权体验；共享环境的信任范围仍按下文表述。响应式布局与对应测试见 [默认界面](UI.md)。

[页面路由助手与公开宿主入口](PAGES.md)已接入普通应用源码：可选 View 元数据、ctx.shell、动态页面登记/移除、偏好保存及嵌套视图树。文本处理工作台使用同一套 SDK；具体受验范围按专项证据记录。以下仍需按阶段验证：

- 所有权：视图挂载、路由、焦点、键盘/触控交互与订阅由谁释放；隐藏视图不等于业务已停用。
- 冲突：多个布局、导航或快捷键贡献如何选择、排序与诊断；不以隐式加载顺序决定覆盖。
- 组合：递归扩展点如何发现、声明依赖和阻止循环；替换一个界面提供者如何保留其他组合。
- 持久化：布局配置版本、失效扩展引用与升级迁移怎样恢复，不把打不开的布局当成空配置覆盖。
- 恢复：替换失败或停用后，用户仍能进入可用界面和扩展管理；M1 挂载失败后排除该代视图，再选择可挂载布局；无可用布局时显示宿主恢复入口。只有成功挂载后才提示恢复成功，平台覆盖见证据。
- 适配：不同屏幕、触控、键盘及原生窗口输入路径分别验证，不能只验浏览器截图。

建议为真实授权和安全提示保留明确归属，拒绝扩展经公开契约绕过授权或伪造授权结果。对于与宿主共享环境的可信插件，防界面伪装的强制能力尚未证明，不能宣称具有安全沙箱或可信显示隔离。

## M1 Agent 服务契约

[contract.ts](../modules/agents/contract.ts) 定义扩展层 `agents@1`，归 Agent 扩展所有，不属于 SDK 或通用 Host。提供者通过 `ctx.provide("agents", 1, provider)` 注册，消费者声明 `requires: { agents: 1 }`，通过 `ctx.use` 获取。

提供者公开 `info`（label、version、description）、稳定的 `list()` 快照、`subscribe()` 及取消订阅函数，以及 `create`、`update`、`remove`、`session`、`send`、`cancel`。`update` 支持名称、说明和特别关注。快照包含人类可读说明、能力、来源、状态、特别关注、会话与消息。每次可观察变化发布新的快照，UI 通过订阅读取，不检查私有对象。来源与执行范围由公开说明呈现；UI 调用保留提供者方法的接收对象。

`agents.local` 提供当前本地实现，以 `optional` 声明 `text.transform@1`（没有文本服务时照常启动，发送时提示先在扩展管理中启用；之后启用的第一个服务给尚未设置的 Agent 使用），以 `ctx.providers` 取得全部已启用的文本服务：每个 Agent 保存可选的 `extensions`（开启的扩展 ID，按开启先后排列），回复依次经过其中已启用的服务；新建时只开启最早启用的服务，缺少该字段的旧数据同样默认第一个，全部关闭时拒绝发送并提示开启。停用的扩展保留在列表中，重新启用后恢复；回复途中停用的服务，其在途调用经提供者的 `signal` 取消，结果不保存。`agents@1` 的可选 `extensionChoices()`、`setExtension(id, extensionId, on)` 供界面开关；扩展经 `publishUsers` 的 `uses` 与 `toggle` 公布每个 Agent 开启的服务，扩展管理可按 Agent 开关。写入串行执行，收到成功回执后才发布已保存修改；`busy` 状态和 `canCancel` 不持久化。会话结构修改与移除即时占用对应 Agent，避免与发送交叠。处理取消在排队及派发前检查，迟到结果丢弃；已派发写入进入不可取消提交段，`canCancel: false`，成功回执胜出。停止扩展关闭新修改、取消在途处理并等待已派发保存，依赖恢复后从最近已确认快照创建新实例。

本地提供者在保存前验证文本服务返回值：必须是长度不超过 1,000,000 个 UTF-16 代码单元的字符串（用户输入同限），与恢复校验一致。非法或超长结果不写入，保留原消息与草稿；会话消息分页存储，不受单个状态文档 64 KiB 的限制。

`ui.agents` 消费此服务并贡献 Agent 主视图和 `role-settings` 模态内容视图；外壳通过相同的公开挂载契约显示角色卡设置。外部提供者可与内置提供者同时启用；`ui.agents` 以 `ctx.use` 绑定最早启用的一个，它停用后自动重新绑定下一个。列表、角色卡、会话和交互仍由扩展拥有，其他 UI 无须采用聊天布局。当前每次仅选择一个提供者，尚无跨提供者 Agent 集合或协作编排。

实验角色卡由扩展解析，仅支持文档中的 JSON 子集；不承诺兼容其他角色卡格式。模型适配、MCP、A2A 与长期会话数据迁移留在各自扩展及后续契约中。默认本地提供者与外部提供者一样使用自身扩展状态作用域。

## 可信插件的最低披露与操作要求

可信模式表示用户愿意信任自己安装的代码，不代表插件已认证安全。短期不以恶意代码强隔离作为实现前提，但需满足以下设计要求，并注明哪些由宿主强制、哪些依赖插件配合：

| 项目 | 拟要求 |
| --- | --- |
| 来源与版本 | 安装或升级前能看到来源、版本、能力变化与兼容要求；来源可信判断和更新政策尚未决定 |
| 权限与平台能力 | 披露访问的数据和外部能力，按平台探测并处理拒绝或撤权；提示不等于限制已经强制执行 |
| 凭据作用域 | 尽量提供受限能力而非全局密钥，避免传给无关扩展；日志和组合配置不保存明文密钥 |
| 停用与卸载 | 清理契约可检查，在途工作和外部副作用有说明；用户数据去留明确且可诊断失败 |
| 可观测性 | 能追溯操作的扩展与版本，审计内容脱敏；同进程故障和恶意行为可能影响宿主 |

DI isolate 若仅隔离依赖作用域，就只按该范围表述。进程隔离、操作系统沙箱、网络/文件访问限制和资源强制约束均须分别验证后才能声明。

## SDK 与契约演进

安装身份为小写字母开头、最多 64 个字符，后续允许小写字母、数字、句点与连字符，禁止连续句点；安装阶段提前拒绝平台授权不接受的身份。该规则只约束正常契约路径，不构成共享 WebView 安全沙箱。定向证据见 [导入与身份边界](../evidence/IMPORT-BOUNDARIES-2026-10-15.md)。

公开 SDK 的目标交付包括契约文档、样板和可复现验证路径，让作者独立接入。默认功能也尽量通过相同 SDK，不建立内置扩展专享的业务后门。

演进需说明兼容范围、废弃过渡、依赖版本、配置与数据迁移，以及不支持版本的拒绝方式。具体版本政策尚未决定；未知需求暴露缺口时，先判断是否为可复用能力，再补充通用契约和反例测试。验收按 [验收计划](ACCEPTANCE.md) 分阶段建立证据。

## 后期角色卡与协作契约方向

工程目标明确角色卡首先用于人类了解 Agent，同时作为 A2A 联系媒介；多 Agent 合作为最后期重点。卡片格式解析、协议适配及具体协作循环属于扩展，通用内核不固定特定业务对象或协作协议。

以下是待设计的契约议题，不是现成字段或接口：人类描述与机器信息的一致性，来源、能力边界和联系条件的呈现；身份验证、能力声明核查与授权的区分；跨作者的发现联系、共享状态权限、委派/交接、失败和取消传播；人类查看参与者、分工、进度与接管的界面扩展。

卡片声明不能自动触发信任或授予权限，机器信息不能取代人类可读说明。通信、状态、生命周期及权限契约提供通用基础，协作策略与卡片领域语义由扩展定义。具体协议、格式、兼容和迁移政策须在后期实验后确定。

## 本地组合

外壳使用公开 Host 查询和启停接口保存与恢复单一组合，不扩展 SDK 业务协议。启用集合、提供者冲突、精确版本、权限与状态所有权见 [组合契约](COMPOSITION.md)。

## 非敏感扩展配置

扩展管理支持声明字段编辑、取消焦点返回和保存后应用；操作区采用可换行布局。生命周期、坏值保留与迁移限制见 [配置契约](EXTENSION-CONFIGURATION.md)，限定验证见 [配置证据](../evidence/CONFIGURATION-2026-10-15.md)。

## 凭据代用请求实验

[接口与参考模型](CREDENTIAL-REQUEST.md)仅用于隔离假数据接入，生产能力不可用。扩展引用所属绑定，由平台侧确定目标和凭据；不在普通配置中保存秘密，真实适配及授权仍待独立阶段。

[可选单跳状态迁移助手](STATE-MIGRATION.md)已提供公开 SDK 入口与独立样板：扩展定义业务转换，助手用一次修订号提交保留旧快照；当前不自动迁移默认业务，也不提供通用包升级事务或自动回退。

可选 [固定视图树助手](VIEW-TREE.md) 已完成两作者内部样板与两端限定验收。仅测试外壳组合，默认应用未采用；不代表完整递归主题/导航框架或 Host 自动异步失败回退。

无业务视图事件服务的启停、撤权与恢复限定结果见 [执行边界](EVENT-SERVICE.md)；暂停映射为 stop，新一代重新订阅，不提供后台常驻或持久事件队列。

## 会话内文档只读访问

原生支持探测成功后，扩展声明并获授 document.read。宿主系统选择器建立多个 owner 绑定句柄，扩展通过公开 ctx.platform 列举/读取。Host scope 失效会触发 Platform.release 的临时资源释放并将同一结果纳入清理；保存状态不删除。取消、撤销、预算与失败锁存见 [文档契约](SELECTED-DOCUMENT.md)。仍为可信运行时实验，不构成恶意扩展隔离。

实验 [主题颜色贡献](THEMES.md)已加入 `ctx.theme` 与公开 `Host.themes()`：完整颜色快照、作用域失效撤回、冲突拒绝和应用设置选择/回退。只表达语义颜色，不提供任意CSS或强沙箱；完整A12仍未验收。
