# 扩展契约（实验）

[文档导航](README.md) · [架构](ARCHITECTURE.md) · [验收](ACCEPTANCE.md)

状态：当前有效（2026-10-27 核实）；[实验 SDK](../modules/sdk/index.ts) 与[宿主](../modules/extension-host/host.ts) 的当前契约，不承诺稳定 API 或长期兼容。

扩展可以提供服务、主题、整体布局、导航、页面、交互、业务流程、模型适配、数据处理、外部连接与新的扩展点；消费者只面向公开契约，不依赖提供者的私有实现。身份、精确版本、依赖、多提供者与资源作用域见[作者指南](SDK-AUTHORING.md)；组合与配置见[组合](COMPOSITION.md)、[配置](EXTENSION-CONFIGURATION.md)；状态恢复见[迁移助手](STATE-MIGRATION.md)。

## 生命周期与失败行为

| 状态转移 | 必须明确的行为 |
| --- | --- |
| 已发现 → 检查兼容与依赖 | 来源、版本与所需能力可检查；依赖缺失、循环或冲突时不执行半套业务 |
| 条件未满足 → 等待或拒绝激活 | 诊断指出原因与恢复动作；可选依赖缺失不被误当成必需依赖就绪 |
| 条件满足 → 激活 → 可用 | 注册逐项绑定所有者；部分失败撤回本次注册 |
| 可用 → 依赖失效或能力撤销 | 停止受影响的新调用，无悬空引用 |
| 可用 → 停用中 → 已停用 | 阻止新任务，取消在途工作，按依赖顺序释放服务、视图、监听与资源 |
| 清理失败 → 未完全停止 | 不显示“已完全卸载”；保留归属与恢复路径，必要时提示重启 |
| 已停用 → 卸载 | `Host.uninstall(id)` 只接受已停用或从未启动的记录；撤销授权成功后才移除，失败可诊断、可重试；外壳同时移除安装路径，保留配置与用户状态，同 ID 重装须重新授权 |
| 已停用 → 升级或重新激活 | 重新激活前检查兼容与依赖；版本迁移由扩展显式执行，不是热更新 |

生命周期只管理可登记、可取消、可释放的资源，不承诺撤销任意外部副作用；扩展须说明网络写入、外部文件改动等不可逆操作及其补偿或重试策略。

### 写入与清理的失败语义

- 激活失败且清理成功后，下一次启用创建新作用域重试；清理失败保留 `cleanup-failed`，拒绝重新激活，要求重启。激活超时单独报告为可重试的 `failed`；清理超时仍要求重启。
- 视图释放可同步或异步返回；释放抛错、拒绝或超时保留失败归属，之后的停用不能把它改成已清理，也不盲目重试释放函数。
- 停用、运行中撤销必需能力、或同时提供服务与视图的扩展视图释放失败时，先把受影响的作用域全部标为停用中并关闭工作入口，再触发同步取消通知，随后串行释放。事件、注册、服务获取、任务与平台调用共用这一边界；已排队的任务进入回调前再检查。提供者替换不能复活清理未完成的链路。
- 业务经 `ctx.platform` 传入取消信号，宿主与生命周期信号合并。成功回执表示已保存；`AbortError` 或 `outcome: not-committed` 表示未提交；其他异常按结果未确认处理，先重读状态再决定是否重试。平台适配器只有能证明未提交时才可返回这两种结果，丢失回执不算取消成功。
- 浏览器写入在同步提交前检查取消；原生写入派发后进入不可取消的提交段，此时显示等待回执并关闭取消，收到成功回执后不能报告未提交。
- 外壳状态用 `host.shell`，扩展状态统一用 `extension.<扩展 ID>`，避免正常调用的身份碰撞；这不是对恶意桥接调用的隔离。两端都拒绝未知 schema、无效文档与不匹配的修订号并保留原数据；`state.batch` 的事务与未知结果见[状态规则](SDK-AUTHORING.md#状态取消与演进)。

## 界面组合与替换

- `ctx.view` 注册框架无关的挂载与释放函数，`ctx.use` 消费服务。切换布局释放旧视图，已保存状态归各自扩展；管理页的显示与隐藏保留工作区挂载，不表示业务停用。扩展管理、授权确认与无布局恢复由外壳持有，显示内容取自 catalog、manifest 与 `host.inspect`。
- 可选 `View.chrome` 由工作区发布稳定快照与订阅：标题、上下文扩展所有者、默认详情、可选的 `back()`（只在有上一层时提供）与带实体类型的导航。Host 只透传；外壳只消费当前视图，失败时按视图 ID 与 generation 回退并保留管理入口。用法见[作者指南](SDK-AUTHORING.md#工作区标题与上下文侧栏)。
- 外壳在启用前显示所需能力，确认后才授予并启用，取消或 Escape 保持原状态。[页面路由助手与宿主入口](PAGES.md)提供 View 元数据（含窄栏图标）、`ctx.shell`、动态页面登记与嵌套视图树。
- 界面改动须说明：视图、路由、焦点与订阅由谁释放（隐藏不等于停用）；多个布局、导航或快捷键贡献怎样选择与诊断（不靠加载顺序）；递归扩展点怎样声明依赖、阻止循环；布局配置失效时怎样恢复而不被当成空配置覆盖；替换失败后仍能进入可用界面与扩展管理；不同屏幕与输入路径分别验证。

## Agent 服务契约

[contract.ts](../modules/agents/contract.ts) 定义扩展层的 `agents@1`，归 Agent 扩展所有，不属于 SDK 或 Host。提供者经 `ctx.provide("agents", 1, provider)` 注册，消费者声明 `requires: { agents: 1 }` 并经 `ctx.use` 获取。

- **快照与订阅**：`info`（label、version、description，`attachments` 声明是否收附件）、稳定的 `list()` 快照与 `subscribe()`；每次可观察变化发布新快照，界面只读快照、不检查私有对象，调用时保留提供者方法的接收对象。快照含名称、介绍、可选设定 `instructions`（缺省时详情不显示设定）、来源、状态、置顶、所选模型、按 Agent 关闭的组成部分、会话与消息。
- **操作**：`create`、`update`（名称、介绍、设定、置顶、头像）、`remove`、`session`、`send(id, text, attachments?)`、`cancel`。可选：`removeMessage`（处理中拒绝）；`edit` 以新文字代替自己的一条消息（保留附件）、`regenerate` 以回复之前的消息重新请求——两者只用改写处之前的历史，等待期间快照的 `pending.replaces` 指出被改写的消息，回复保存时才替换它及之后的消息，期间会话有变化则不保存；`undo(id)` 放回最近一次删除的消息或会话、或改写前的对话（只在内存，消息只在会话之后没有变化时放回）；`renameSession`（1–60 字符）；`view(id | null)` 告诉提供者哪个 Agent 的当前会话在屏幕上，其未读即标为已读。
- **消息字段**：可选 `at`（毫秒）；可选 `from` 记录发言者——使用者为 `OWNER`（`"me"`），回复为 Agent 的 ID，缺省时由 `speaker()` 按 `role` 推断。等待回复期间快照带 `pending`。会话的可选 `lastReadAt` 之后的回复为未读。
- **组成部分**：提供者自身、显示它的界面与模型所属的 `chat@1` 连接，用可选 `off` 列表按 Agent 关闭，经 `setOff(id, extensionId, off)` 修改，`connectors()` 列出全部连接（含尚无模型的，带可选的 `manage` 页面 ID）。关闭提供者或所选模型的连接时拒绝发送并保留所选模型，`setModel` 选中模型即重新开启其连接；界面是否显示由界面自己读 `off`。扩展经 `publishUsers`（`service: "chat"`）公布每个 Agent 用的连接，扩展管理可按 Agent 开关：开启未被用的连接时改用它的第一个模型，没有模型时拒绝。
- **模型与思考强度**：回复只来自所选模型（`model` 记提供者扩展 ID 与模型 ID）；新建时默认第一个可选模型，没有可用模型时照常启动、发送时提示。可选 `effort` 经 `setEffort(id, effort | null)` 保存，只接受所选模型 `ModelChoice.reasoning` 列出的档位，发送时仍列出才传给 `reply`。回复途中停用的连接，其在途调用经 `signal` 取消、结果不保存。
- **附件与图片**：`send` 校验并随消息保存附件（有附件时 `text` 可为空，上限见[模型连接](MODELS.md)）。`ModelChoice.vision` 为真才把图片作为 `reply` 的 `images` 传出，否则换成一行 `ERROR: Cannot read "文件名" (this model does not support image input). Inform the user.`；超出最近 3 条的旧图片只换成 `[图片：文件名]`。
- **头像**：可选 `Agent.avatar` 为 `data:image/(png|jpeg|webp);base64,…`，至多 40,000 字符，`update(id, { avatar: null })` 移除，非法值与外部链接拒绝；恢复时损坏的头像被丢弃。
- **并发与保存**：写入串行，收到成功回执才发布修改；`busy` 与 `canCancel` 不持久化。等待回复期间其他会话可切换、新建、改名与删除消息，正在等待的会话不能删除，同一 Agent 不能再发送。取消在排队与派发前检查，迟到结果丢弃；已派发的写入 `canCancel: false`，成功回执胜出。模型返回值与用户输入同样验证为不超过 1,000,000 个 UTF-16 代码单元的字符串，非法时不写入。停止扩展时关闭新修改、取消在途处理并等待已派发的保存。

`agents.local`（“Agent 核心”）是本地实现，以 `optional` 声明 `chat@1` 与 `memory@1`，存储见[架构](ARCHITECTURE.md#agent-数据)。外部提供者可与它同时启用；`ui.agents` 绑定最早启用的一个，停用后自动换到下一个。当前一次只选一个提供者，没有跨提供者的 Agent 集合或协作编排。角色卡由扩展解析，支持的格式见 [UI](UI.md#添加与导入-agent)。

## 记忆服务契约

[memory/contract.ts](../modules/agents/memory/contract.ts) 定义扩展层的 `memory@1`。条目按作用域分开：`person`（关于某人、所有 Agent 共享，即“关于我”）与 `agent`（某个 Agent 关于某人记得的事）；Agent 自身的记忆以后作为新作用域加入。每条可带 `at`（发生时间）与 `until`（不再成立的时间，缺省取 `at`），过了即不再使用。

- **提供者**：`info`、`context({ agent, person, now, timeZone })`（只返回此人的共享资料与这个 Agent 关于此人的记忆，作为提示词段落）、`connect(source)`（读取 Agent 提供者的会话，返回断开函数）、`notify(agent, "saved" | "left" | "on" | "removed")`、`count`、`reports()`、`undo(id)` 与 `subscribe`；有界面的提供者另给 `page.open(agent?)`，没有时界面不显示“打开”。
- **接入**：每个记忆提供者是 Agent「组成扩展」中的一行开关（记在 `off`，默认开启）。发送时只向开启的记忆要段落、只把开启的 Agent 交给它读；回复保存、离开或切换会话、重新开启与移除 Agent 时通知它。重新开启后从当时最后一条消息之后开始记。
- **内置 `memory.local`**（“记忆”）：以 `optional` 声明 `chat@1`，不持有密钥。会话停下 3 分钟、离开或切换会话时，用整理模型读上次整理之后的新消息（只有文字，每条最多 2000 字、每次最多 24000 字取最新部分），连同已有记忆一起请求一次；模型只返回新增、修改、删除的 JSON（参照 mem0 的操作与短编号，相对时间按消息时间换算），结果整批校验，任何一处不合格就整批丢弃、这批消息保持待整理。整理模型默认跟随各 Agent 的模型，可设全局默认或为单个 Agent 指定；不可用时不改用别的模型。首次接入时已有的旧对话不整理。主文档存设置与整理进度，每条记忆是集合 `memories` 的一条记录，一起写入一次 `state.batch`；损坏的条目被忽略、原数据保留。移除 Agent 同时删除它的记忆。

## 平台能力与可选助手

- **凭据**：[凭据代用请求](CREDENTIAL-REQUEST.md)由原生侧确定目标并注入密钥，扩展只引用所属绑定；录入、存储与授权见[凭据绑定](CREDENTIAL-BINDINGS.md)，让用户自建多条连接的扩展声明 `credentialProtocols` 并申请 `credential.connect`。内置[模型连接器](MODELS.md)是参考实现：协议载荷、回复解析与错误脱敏留在扩展，不直接 fetch、不读密钥。
- **`link.open`**：获授权后调用 `ctx.platform("link.open", { version: 1, url })`，交给默认浏览器即返回。`url` 只能是带主机名的 `https://` 地址，不带用户信息，≤ 2048 字符；TS 宿主与 Rust 各自核对授权与地址，WebView 没有自己的打开命令。浏览器预览以 `noopener,noreferrer` 打开新标签页。授权提示为「在浏览器中打开网页链接（仅 https）」。
- **`file.save`**：获授权后调用 `ctx.platform("file.save", { version: 1, name, data })`：`name` 为建议文件名（不含文件夹，≤ 200 字符，只能以 `.png` 或 `.plums` 结尾），`data` 为 base64（解码后 ≤ 32 MB）。Rust 再核对后弹出系统保存面板，确认后写入；浏览器预览改为下载。返回 `{ saved: true | false }`，失败时报“文件没有保存。”。WebView 拿不到所选路径。
- **其他**：[会话内文档只读访问](SELECTED-DOCUMENT.md)（`document.read`）、[单跳状态迁移助手](STATE-MIGRATION.md)、[固定视图树助手](VIEW-TREE.md)、[无业务视图的事件服务](EVENT-SERVICE.md)、[主题颜色贡献](THEMES.md)（`ctx.theme`，只表达语义颜色，不提供任意 CSS）、[公开网络读取](NETWORK-READ.md)。

## 可信扩展的披露要求

可信模式表示用户愿意信任自己安装的代码，不代表扩展已认证安全。下表注明哪些由宿主强制、哪些依赖扩展配合；进程隔离、系统沙箱、网络与文件限制都须分别验证后才能声明。

| 项目 | 要求 |
| --- | --- |
| 来源与版本 | 安装或升级前能看到来源、版本、能力变化与兼容要求 |
| 权限与平台能力 | 披露访问的数据与外部能力，处理拒绝与撤权；提示不等于已强制限制 |
| 凭据作用域 | 提供受限能力而非全局密钥，日志与组合配置不保存明文密钥 |
| 停用与卸载 | 清理可检查，在途工作与外部副作用有说明，数据去留明确 |
| 可观测性 | 能追溯操作的扩展与版本，审计内容脱敏 |

## 身份与演进

- 安装身份以小写字母开头，最多 64 个字符，之后可用小写字母、数字、句点与连字符，禁止连续句点；只约束正常契约路径。
- 默认功能与外部扩展使用同一套 SDK，不设内置扩展专享的后门。演进须说明兼容范围、废弃过渡、依赖版本、配置与数据迁移以及不支持版本的拒绝方式；具体版本政策在第 2 级之后决定（[整体路线](spec/total.md#贯穿约束不堵死不当门槛)）。
