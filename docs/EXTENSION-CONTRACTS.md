## 最小作者与管理入口

[作者指南](SDK-AUTHORING.md)提供三个可直接加载的 ESM 样板、精确版本规则、状态/取消和演进边界。`Host.uninstall(id)` 仅接受已成功停用（或从未启动）的 disabled 记录；撤销平台授权成功后才移除记录，失败保持可诊断和可重试。状态数据与模块文件保留，同 ID 重新安装须重新授权。不提供热升级、迁移或数据删除。外壳对手动安装扩展提供确认卸载，依次停用/撤权、保存安装路径移除、移除 Host 注册；失败保持诊断并可重试或重载确认，跨重启不再加载已确认移除的路径。

## 契约覆盖范围

扩展可提供服务、主题、整体布局、导航、页面、交互、业务流程、模型适配、数据处理、外部连接及新的扩展点。消费者面向公开契约交换数据或调用能力，不依赖提供者私有实现。扩展点不能只是一份由内核预先写死的业务工具清单。

身份、精确版本、必需/可选依赖、多提供者与资源作用域见[作者入口](SDK-AUTHORING.md)；组合与配置见[组合](COMPOSITION.md)、[配置](EXTENSION-CONFIGURATION.md)；状态恢复见[迁移助手](STATE-MIGRATION.md)。长期进程模型、远程分发、兼容窗口及协作协议在[整体路线](spec/total.md)维护。

## 生命周期与失败行为

下表概括生命周期路径；实际状态枚举与管理方法见作者入口：

| 状态转移 | 必须明确的行为 |
| --- | --- |
| 已发现 → 检查兼容与依赖 | 来源、版本、所需能力可检查；依赖缺失、循环或冲突不会执行半套业务 |
| 条件未满足 → 等待或拒绝激活 | 诊断指出原因和恢复动作；可选依赖缺失不能被误当必需依赖就绪 |
| 条件满足 → 激活 → 可用 | 本次注册逐项绑定所有者；部分失败撤回本次本地注册，向依赖方暴露一致状态 |
| 可用 → 依赖失效或能力撤销 | 停止受影响的新调用；消费者暂停、失败或降级的规则明确，无悬空引用 |
| 可用 → 停用中 → 已停用 | 阻止新任务，取消或结束在途工作，按依赖顺序释放服务、视图、监听及资源 |
| 清理失败 → 可诊断的未完全停止 | 不显示“已完全卸载”；保留问题归属和恢复路径，必要时提示重启 |
| 已停用 → 卸载 | 撤销授权后移除宿主记录；外壳移除安装路径，保留配置与用户状态 |
| 已停用 → 升级或重新激活 | 重新激活前检查兼容与依赖；版本迁移由扩展显式执行，不是无中断热更新 |

依赖失效传播、反向清理顺序、重复停用的幂等性及重复激活不泄漏资源，均需测试。当前通过受控停用、替换和重新激活实现可替换性，不承诺无中断热替换。

生命周期管理的是可登记、可取消和可释放的资源，不承诺撤销任意外部副作用。插件须说明网络写入、外部文件改动等不可逆操作，以及可提供的补偿或重试策略；审计记录不能替代回滚。

### 写入与清理的失败语义

- 激活失败且清理成功后，下一次启用会创建新作用域并重试；清理失败则保留 `cleanup-failed`，拒绝重新激活，要求重新启动应用。激活超时单独报告为可重试（状态 `failed`），不沿用清理超时的“需重启”文案；清理超时仍要求重启。
- 视图释放支持同步或异步返回。释放抛错、拒绝或停用时超时会保留失败归属；后续停用不能把它改成已完全清理，也不盲目重试未知幂等性的释放函数。
- 普通停用、运行中撤销必需能力，以及同时提供服务和视图的扩展发生视图释放失败时，先将全部受影响作用域标为停用中并关闭工作入口，再触发任何同步取消通知，随后串行释放。事件接收/发送、注册、服务获取、任务及平台调用共用这一边界；已排队但未执行的任务在进入回调前再次检查。激活期间的合法调用仍允许。清理成功的消费者等待依赖，清理拒绝或超时的消费者保留 `cleanup-failed`；提供者替换不能复活清理未完成的链路。
- 业务通过 `ctx.platform` 传入操作取消信号，宿主将其与扩展生命周期信号合并。成功写入回执表示已保存；`AbortError` 或 `outcome: not-committed` 表示未提交。其他写入异常按结果未确认处理，先重新读取状态，再决定重试。
- 浏览器写入在同步提交前检查取消。原生写入在派发 Rust 调用后进入不可取消的提交段；不提供原生在途撤回。此时显示等待回执并关闭业务取消按钮；收到成功回执后即使有取消请求，也不能报告未提交。
- 外壳状态使用 `host.shell`，经 SDK 调用的扩展状态统一使用 `extension.<扩展 ID>`，避免正常契约调用的身份碰撞。此命名空间不是对恶意桥接调用的隔离。
- 浏览器与 Rust 均拒绝未知 schema、无效文档和不匹配修订号，保留原数据；缺少状态与损坏状态分别处理。`state.batch` 整批提交或整批拒绝（[规则](SDK-AUTHORING.md#状态取消与演进)）。完整迁移和崩溃恢复仍未实现。

这些规则只描述当前实验 SDK。合作式平台适配器只有在能证明未提交时才可返回 `AbortError` 或 `not-committed`，不能把丢失回执当作取消成功。

## UI 组合与替换

工程目标包括应用自身 UI 的更改。公开机制应同时支持局部组合、整体布局与导航替换，以及插件继续开放新的 UI 扩展点。默认 UI 尽量依此实现；仅能换颜色或固定插槽加按钮不满足目标。

当前通过 `ctx.view` 注册框架无关的挂载/释放函数，通过 `ctx.use` 消费服务。工作台与画布各自拥有页面结构、导航和订阅；切换布局会释放旧视图，业务的已保存状态归各自扩展。管理页的显示/隐藏保留工作区挂载，不表示业务已停用，也不触发草稿重建。扩展管理、授权确认及无布局恢复由应用外壳持有；显示内容取自 catalog、manifest 和 `host.inspect`，没有新增业务专用内核入口。

可选 `View.chrome` 由工作区发布稳定快照和订阅，提供当前标题、上下文扩展所有者、默认详情、可选工作区 `back()` 及带实体类型的导航。Host 仅透传元数据；外壳只消费当前视图，在读取、订阅或操作失败时按视图 ID 与 generation 回退，保留管理入口。`back()` 只在工作区有上一层时提供；根层省略，返回后的焦点由工作区恢复。默认 Agent UI 也使用此接口；旧视图无需补充 chrome。接口用法、侧栏选择顺序和实体导航约束见 [作者指南](SDK-AUTHORING.md#工作区标题与上下文侧栏)。

外壳在实际启用前显示所需能力，确认后才授予并启用；取消或 Escape 保持原状态，关闭弹窗后焦点回到发起控件。此为公开正常调用路径的应用内授权体验；共享环境的信任范围仍按下文表述。响应式布局与对应测试见 [默认界面](UI.md)。

[页面路由助手与公开宿主入口](PAGES.md)已接入普通应用源码：可选 View 元数据（含窄栏图标 `icon`）、ctx.shell、动态页面登记/移除、偏好保存及嵌套视图树。开发环境中的文本工作台使用同一套 SDK；打包默认不包含该样板。UI 改动须覆盖以下边界：

- 所有权：视图挂载、路由、焦点、键盘/触控交互与订阅由谁释放；隐藏视图不等于业务已停用。
- 冲突：多个布局、导航或快捷键贡献如何选择、排序与诊断；不以隐式加载顺序决定覆盖。
- 组合：递归扩展点如何发现、声明依赖和阻止循环；替换一个界面提供者如何保留其他组合。
- 持久化：布局配置版本、失效扩展引用与升级迁移怎样恢复，不把打不开的布局当成空配置覆盖。
- 恢复：替换失败或停用后，用户仍能进入可用界面和扩展管理；挂载失败后排除该代视图，再选择可挂载布局；无可用布局时显示宿主恢复入口。只有成功挂载后才提示恢复成功，平台覆盖见证据。
- 适配：不同屏幕、触控、键盘及原生窗口输入路径分别验证，不能只验浏览器截图。

建议为真实授权和安全提示保留明确归属，拒绝扩展经公开契约绕过授权或伪造授权结果。对于与宿主共享环境的可信插件，防界面伪装的强制能力尚未证明，不能宣称具有安全沙箱或可信显示隔离。

## Agent 服务契约

[contract.ts](../modules/agents/contract.ts) 定义扩展层 `agents@1`，归 Agent 扩展所有，不属于 SDK 或通用 Host。提供者通过 `ctx.provide("agents", 1, provider)` 注册，消费者声明 `requires: { agents: 1 }`，通过 `ctx.use` 获取。

提供者公开 `info`（label、version、description）、稳定的 `list()` 快照、`subscribe()` 及取消订阅函数，以及 `create`、`update`、`remove`、`session`、`send`、`cancel`；可选的 `removeMessage(id, sessionId, messageId)` 删除单条已保存消息，处理中拒绝。消息的可选 `at` 记录发送或回复时间（毫秒，旧消息可缺省）。等待回复期间快照带 `pending`（尚未随回复保存的发送内容），界面据此显示“正在输入”。会话的可选 `lastReadAt` 之后的回复为未读，旧会话缺省即全部已读；界面以可选 `view(id | null)` 告诉提供者哪个 Agent 的当前会话正在屏幕上，提供者把其中的未读标为已读，此后到达的回复在同一次保存里即为已读。`update` 支持名称、介绍和置顶。快照包含名称、介绍、来源、状态、置顶、所选模型、按 Agent 关闭的组成部分、会话与消息。每次可观察变化发布新的快照，UI 通过订阅读取，不检查私有对象。来源与执行范围由公开说明呈现；UI 调用保留提供者方法的接收对象。

`agents.local`（界面名称“Agent 核心”）提供当前本地实现，以 `optional` 声明 `chat@1`：回复只来自每个 Agent 所选的模型（`model` 记录提供者扩展 ID 与模型 ID），发送当前会话历史与 Agent 介绍；没有可用模型时照常启动，发送时提示选择模型或先添加模型连接。新建时默认使用第一个可选模型。旧数据中的 `extensions`、`capabilities`、`multiSession` 在恢复时丢弃，所有 Agent 都可有多个会话。组成部分（提供者自身、显示它的界面、模型所属的 `chat@1` 连接）用可选的 `off` 列表按 Agent 关闭，经可选 `setOff(id, extensionId, off)` 修改（`connectors()` 列出全部连接，含尚无模型的），旧数据缺省即全部开启：关闭提供者或模型所属连接时拒绝发送并保留所选模型，`setModel` 选中模型即重新开启其连接；界面是否显示由界面自己读取 `off` 决定，提供者只保存。扩展经 `publishUsers`（`service: "chat"`）的 `uses` 与 `toggle` 公布每个 Agent 使用的模型连接，扩展管理可按 Agent 开关：开启尚未被该 Agent 使用的连接时改用它的第一个模型，没有模型时拒绝并提示先添加。回复途中停用的连接，其在途调用经 `signal` 取消，结果不保存。思考强度用可选 `Agent.effort` 与 `setEffort(id, effort | null)` 保存，只接受所选模型在 `ModelChoice.reasoning`（来自 `chat@1` 的 `ChatModel.reasoning`，缺省即不支持）里列出的档位；发送时仅当当前模型仍列出该档位才作为 `reply` 的可选 `effort` 传给连接，换模型后保留记录但不发送。头像是可选 `Agent.avatar`：`data:image/(png|jpeg|webp);base64,…`，至多 40,000 个字符，经 `update(id, { avatar: string | null })` 设置或移除（`null` 移除，非法值拒绝），`create` 的 `AgentConfig.avatar` 与角色卡的 `avatar` 同样受此限制；外部链接不接受，需要网络图片的扩展先把它下载成字节再编码。恢复时损坏的头像只是被丢弃。消息可带 `attachments`（文本文件或图片，上限见[模型连接](MODELS.md)），`send(id, text, attachments?)` 校验并随消息保存，提供者以 `info.attachments` 声明支持，界面据此显示添加入口；`ModelChoice.vision` 为真才把图片作为 `reply` 的 `images`（历史轮次的 `images`）传给连接，否则换成一行 `ERROR: Cannot read "文件名" (this model does not support image input). Inform the user.`（超出最近 3 条的旧图片只换成 `[图片：文件名]`），界面不因模型而禁用添加。写入串行执行，收到成功回执后才发布已保存修改；`busy` 状态和 `canCancel` 不持久化。等待回复期间，其他会话可以切换、新建、改名（可选 `renameSession(id, sessionId, title)`，1–60 个字符）和删除消息，正在等待的会话不能删除，同一 Agent 不能再发送；会话结构修改与移除即时占用对应 Agent，避免与发送交叠。处理取消在排队及派发前检查，迟到结果丢弃；已派发写入进入不可取消提交段，`canCancel: false`，成功回执胜出。停止扩展关闭新修改、取消在途处理并等待已派发保存，依赖恢复后从最近已确认快照创建新实例。

本地提供者在保存前验证模型返回值：必须是长度不超过 1,000,000 个 UTF-16 代码单元的字符串（用户输入同限），与恢复校验一致。非法或超长结果不写入，保留原消息与草稿；每条消息单独存为一条记录（存储方式见[架构](ARCHITECTURE.md#应用-ui-的扩展边界)）。

`ui.agents` 消费此服务并贡献 Agent 主视图。外部提供者可与内置提供者同时启用；`ui.agents` 以 `ctx.use` 绑定最早启用的一个，它停用后自动重新绑定下一个。列表、角色卡、会话和交互仍由扩展拥有，其他 UI 无须采用聊天布局。当前每次仅选择一个提供者，尚无跨提供者 Agent 集合或协作编排。

实验角色卡由扩展解析，仅支持文档中的 JSON 子集（`version: 1`、`name`、可选 `description` 与 `avatar`）；不承诺兼容其他角色卡格式。模型适配、MCP、A2A 与长期会话数据迁移留在各自扩展及后续契约中。默认本地提供者与外部提供者一样使用自身扩展状态作用域。

## 可信插件的最低披露与操作要求

可信模式表示用户愿意信任自己安装的代码，不代表插件已认证安全。短期不以恶意代码强隔离作为实现前提，但需满足以下设计要求，并注明哪些由宿主强制、哪些依赖插件配合：

| 项目 | 拟要求 |
| --- | --- |
| 来源与版本 | 安装或升级前能看到来源、版本、能力变化与兼容要求；来源可信判断和更新政策尚未决定 |
| 权限与平台能力 | 披露访问的数据和外部能力，按平台探测并处理拒绝或撤权；提示不等于限制已经强制执行 |
| 凭据作用域 | 尽量提供受限能力而非全局密钥，避免传给无关扩展；日志和组合配置不保存明文密钥 |
| 停用与卸载 | 清理契约可检查，在途工作和外部副作用有说明；用户数据去留明确且可诊断失败 |
| 可观测性 | 能追溯操作的扩展与版本，审计内容脱敏；同进程故障和恶意行为可能影响宿主 |

DI isolate 若仅隔离依赖作用域，就只按该范围表述。进程隔离、操作系统沙箱、网络/文件访问限制和资源强制约束均须分别验证后才能声明。

## SDK 与契约演进

安装身份为小写字母开头、最多 64 个字符，后续允许小写字母、数字、句点与连字符，禁止连续句点；安装阶段提前拒绝平台授权不接受的身份。该规则只约束正常契约路径，不构成共享 WebView 安全沙箱。

公开 SDK 的目标交付包括契约文档、样板和可复现验证路径，让作者独立接入。默认功能也尽量通过相同 SDK，不建立内置扩展专享的业务后门。

演进需说明兼容范围、废弃过渡、依赖版本、配置与数据迁移，以及不支持版本的拒绝方式。具体版本政策尚未决定；未知需求暴露缺口时，先判断是否为可复用能力，再补充通用契约和反例测试。验收按 [验收计划](ACCEPTANCE.md) 分阶段建立证据。

## 本地组合

外壳使用公开 Host 查询和启停接口保存与恢复单一组合，不扩展 SDK 业务协议。启用集合、提供者冲突、精确版本、权限与状态所有权见 [组合契约](COMPOSITION.md)。

## 非敏感扩展配置

扩展通过 `manifest.configuration` 声明带默认值的字段，`activate` 读取只读的 `ctx.configuration`；生命周期、坏值保留与迁移限制见 [配置契约](EXTENSION-CONFIGURATION.md)，扩展管理中的编辑行为见 [UI](UI.md#非敏感扩展配置)。

## 平台能力与可选助手

[凭据代用请求](CREDENTIAL-REQUEST.md)已接入原生适配与模型连接器，浏览器预览不可用。扩展引用所属绑定，由原生侧确定目标并注入凭据；存储、录入、授权与未知回执见[凭据绑定](CREDENTIAL-BINDINGS.md)；需要让用户自建多条连接的扩展声明 `credentialProtocols` 并申请 `credential.connect`，见[扩展自建连接](CREDENTIAL-BINDINGS.md#扩展自建连接)。内置[模型连接器](MODELS.md)是参考实现：协议载荷、回复解析和错误脱敏留在扩展，不直接调用 fetch 或读取密钥。

[可选单跳状态迁移助手](STATE-MIGRATION.md)已提供公开 SDK 入口与独立样板：扩展定义业务转换，助手用一次修订号提交保留旧快照；当前不自动迁移默认业务，也不提供通用包升级事务或自动回退。

可选[固定视图树助手](VIEW-TREE.md)供页面路由及开发文本工作台使用；固定树挂载后不能追加子节点，也不承担 Host 自动异步失败回退。

无业务视图事件服务的启停、撤权与恢复限定结果见 [执行边界](EVENT-SERVICE.md)；暂停映射为 stop，新一代重新订阅，不提供后台常驻或持久事件队列。

## 会话内文档只读访问

原生支持探测成功后，扩展声明并获授 document.read。宿主系统选择器建立多个 owner 绑定句柄，扩展通过公开 ctx.platform 列举/读取。Host scope 失效会触发 Platform.release 的临时资源释放并将同一结果纳入清理；保存状态不删除。取消、撤销、预算与失败锁存见 [文档契约](SELECTED-DOCUMENT.md)。仍为可信运行时实验，不构成恶意扩展隔离。

实验 [主题颜色贡献](THEMES.md)已加入 `ctx.theme` 与公开 `Host.themes()`：完整颜色快照、作用域失效撤回、冲突拒绝和应用设置选择/回退。只表达语义颜色，不提供任意CSS或强沙箱；完整A12仍未验收。
