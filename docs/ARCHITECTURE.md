# 架构边界与决策状态

[文档导航](README.md) · [扩展契约](EXTENSION-CONTRACTS.md) · [验收计划](ACCEPTANCE.md)

状态：当前有效（2026-10-18 核实）；记录目标职责与当前模块边界，长期决策见文末 D1–D8。

当前为 0.0.4 debug 实验原型，M1 已限定收敛，M2 按 M2.0–M2.4 子门禁推进：M2.0 已限定重新基线，工程前置与后续平台切片按当前阶段计划推进。默认 Agent、主题、页面组合与原生适配的当前实现和验证范围见[验证索引](../evidence/RESULTS.md)。下文区分目标职责与当前模块边界。

## 目标与边界

目标：本体应支持由插件组合产生未知的服务、UI、业务和新扩展点。内核只承载通用机制，不理解特定 Agent 的业务循环、模型消息协议、角色卡格式或某个示例产品的状态机。公开 SDK 应足以支持贡献者扩展，无需访问私有注册表或修改内核源码。

## 建议的职责划分

| 责任域 | 拟承担的职责与所有权 | 边界与失败行为 |
| --- | --- | --- |
| 小内核 | 加载与生命周期、注册所有权、依赖与组合、持久化及迁移契约、取消与资源管理、可观测性 | 不识别业务对象；激活失败撤回本次部分注册，失败可定位到扩展 |
| 平台适配层 | 平台能力探测、原生调用、前后台事件、文件、权限与凭据作用域 | 明确支持、拒绝、暂不可用或需授权；不把调用失败伪装成功 |
| 扩展宿主与 SDK | 加载兼容检查、扩展上下文、公开扩展点及诊断入口 | 长期运行时和进程模型尚未选定；宿主保证与可信代码自律边界须分别列明 |
| 通用应用外壳 | 承载可替换的主题、布局、导航、页面、交互及扩展管理入口 | 默认 UI 尽量走公开契约；不得要求所有扩展有聊天窗口或正在打开的视图 |
| 插件及其组合 | 提供服务、UI、业务、模型协议、格式解析与新的扩展点 | 拥有自身业务状态；按公共契约声明依赖与清理资源 |

这是一张责任地图，不要求立即拆成五个包或进程。实际模块划分随风险实验调整。通用状态契约约束所有权、持久化与恢复语义；内核不据此保存业务专用数据结构。

## 应用 UI 的扩展边界

目标明确 UI 可通过扩展更改，包含整体布局、导航、页面和交互方式，不限主题或固定插槽。建议默认 UI 与社区扩展共用公开机制，并允许扩展继续提供新的界面扩展点。内核不固定聊天应用布局。

默认布局围绕内容组织、导航和跨端操作设计；扩展可以替换整体 UI，不受默认布局限制。

布局选择及持久化、受控替换和宿主恢复通过公开契约实现。可选页面路由助手复用确定性导航冲突选择与视图树循环检查，支持动态贡献、焦点返回与页面偏好保存，见[页面契约](PAGES.md)。[交稿检查](LOCAL-PROOF.md)提供独立页面接入样板，浏览器与两端普通包已有对应限定结果；完整组合升级、迁移和更广键盘/触控适配按[A12](ACCEPTANCE.md#a12-ui-替换专项路径)继续验证。

0.0.4 的应用外壳拥有扩展管理、应用内授权、布局与外观偏好、恢复入口；默认 Agent 界面、工作台、画布及各自导航通过公开 `ctx.view` 和 `ctx.use` 挂载，不读取宿主私有业务状态。扩展管理使用独立全幅页面，隐藏业务区时保留工作区挂载和草稿；布局扩展按自身容器宽度重排。外壳的通用控件与扩展样式共享两套语义颜色变量，布局和导航仍由扩展替换，详见 [默认界面](UI.md)。

`agents.local` 是扩展层业务提供者，以 `agents@1` 公开快照、订阅、角色与会话操作；`ui.agents`（`src/agents/`）通过 `ctx.use` 消费，再用 `ctx.view` 注册默认界面；服务契约在 `modules/agents/contract.ts`。角色卡解析和文本执行位于扩展模块。`src/application.ts` 组合默认应用：调用业务模块的恢复函数，接线内置扩展与默认启用集合，并保留旧布局的兼容规则；`src/shell/runtime.ts` 的 `bootShell(application)` 编排通用配置解析、安装和组合恢复，`persistence.ts` 串行保存不透明快照字段。通用 Host、ExtensionContext、外壳、扩展管理与 Rust 桥接不读取 Agent 数据格式，也不展示 Agent 关联。公开提供者说明用于呈现实际来源、版本与执行范围，外部提供者无需模仿内置实现。

默认组合使用本地文本服务；[DeepSeek 协议扩展](DEEPSEEK.md)已提供可替换服务的隔离接线，生产传输、秘密读取/注入、发送授权与真实调用按 M2.3 继续，MCP 客户端待实现。外部视图启用后优先选中，工作台、画布和默认 Agent 界面可独立替换；最小启用集合、精确版本与配置快照已实现。复杂多提供者政策、组合升级事务和长期会话存储待实现。`agents.local` 通过自身 `ctx.platform("state.*")` 存于 `extension.agents.local`：主文档是索引（`{ version: 2, agents }`，会话只含元数据与分片名），每个会话的消息存于独立分片 `s-<uuid>`，各自受 64 KiB 上限，单会话超限时拒绝本次保存而不影响其他会话；先写分片再写索引，删除会话时先更新索引再删分片，删除失败只留下无引用分片；分片已提交而索引失败时视同回执未知，锁住后续修改直到重新加载。空会话不写分片，因此索引引用的分片缺失按空会话读取。`version: 1` 的单文档在启动时原地升级，缺少 Agent 列表时按损坏处理、不覆盖。由组合根预授权；旧版 `host.shell.agents` 在首次启动时迁移一次，成功后由组合根移除该字段，移除失败下次启动重试。Agent 数据损坏只让 `agents.local` 进入失败态并在启动提示中列出，外壳、扩展管理与其他扩展照常运行，原数据不覆盖。

建议保留可信授权与安全提示边界，不允许扩展通过公开 API 隐藏必要授权或伪造授权结果。呈现层是否能防止伪装须由实际隔离与 UI 方案证明；同环境可信代码可能仿造界面，不能把这项建议写成已有安全保证。

## 当前前端的状态所有权

`src/App.tsx` 只负责启动结果和加载／恢复界面的选择；`src/shell/Workbench.tsx` 装配各责任域及共享反馈，通过具名 props 传入消费者实际使用的字段。`controllers.ts` 用 Pick 定义组件的 Hook 消费范围；管理页按页头、列表、操作、详情和弹窗组合，不新增 Context。

| 所有者 | 持有的状态与副作用 | 调用边界 |
| --- | --- | --- |
| `src/application.ts` | 默认应用组合、Agent 恢复接线和旧布局兼容 | App 调用无参数 `boot()`；业务格式由 `modules/agents/store.ts` 校验，未安装该业务的组合可保留其不透明数据 |
| `src/shell/runtime.ts` | 通用启动编排、接收应用组合、安装与恢复 | 返回稳定服务与只读启动初值，保留 `CompositionRecovery` 入口 |
| `persisted-state.ts`、`extensions.ts` | 通用偏好解析、目录／手动扩展安装 | 业务字段不透明保留，内置 ID 冲突按注入目录检查，坏数据与导入失败保留归属 |
| `persistence.ts` | 串行快照、revision、未知写入锁存和页面保存队列 | 成功回执后发布偏好；已提交回执胜出，未知结果先重载 |
| `useWorkspace` | 视图选择、挂载释放、按代排除失败视图、恢复到可用布局 | 复用 `createViewSlot` 和公开 Host 生命周期 |
| `useAppearance` | 外观偏好、主题贡献、DOM 与原生外观同步 | 成功保存后更新偏好；贡献缺失保留选择 |
| `useShellNavigation`、授权与弹窗组件 | 管理页、宿主模态入口、发起控件和返回焦点 | 管理返回在工作区可见后恢复焦点 |
| `src/features/extensions/useExtensionManager.ts` | 管理页选中项、失败导入显示、模态入口与返回焦点；按消费者生成窄控制接口 | 组合 extension-actions、扩展状态 Hook 与外壳反馈；安装表单常驻，输入／配置草稿仍归各弹窗 |
| `src/shell/useExtensionState.ts`、`extension-state.ts` | React 持有 imports／configurations／composition，按动作串行读取最新确认值、执行与发布 | 各动作使用局部 draft，不修改 Runtime；保存拒绝保留旧值，部分成功按已确认字段发布 |
| `modules/shell/extension-actions.ts` | 安装、重试、失效路径移除、卸载、组合保存和配置写入的执行顺序 | 不依赖 React，接收 Host 的 Pick 与局部状态接口；确认保存后才改变 draft，保留已确认的部分结果 |
| `src/features/agents/` | AgentWorkspace 组合选中项、会话草稿和详情；AgentDialogs 持有创建表单草稿；useAgentModals 持有弹窗、反馈与发起控件；useRoleCardDraft 持有卡片输入与读取取消 | AgentDialogs 常驻以保留取消后的草稿；focus 选择仍可操作的返回控件，useMediaQuery 订阅视口变化 |
| 各工作区扩展 | 业务选中项、会话、草稿及默认详情开关 | 可选 `View.chrome` 向外壳发布标题和上下文状态 |

布局回退诊断优先使用已注册视图的 owner/label；未注册时读取目录项的可选 `views: { [viewId]: label }` 提示。默认目录和应用组合声明各自视图，通用诊断不维护业务 ID 表；缺少提示仍保留原视图 ID 和管理入口。提示用于定位来源，不授予注册或执行权限。

`src/features/extensions/useExperiments.ts` 拥有文本工作台实验接线；该实验只在开发构建的目录中，没有安装它的组合（包括发布包）不展示恢复启动按钮，管理入口仍可用。

`src/shell/useAsyncAction.ts` 共用忙碌、错误与通知状态。Agent 将 AbortError 显示为停止通知，外壳 `useOperations` 保留 `errorMessage` 错误映射；共用 Hook 不改变两者的反馈语义。

Runtime 的 initial 只作外观、布局、恢复诊断和扩展状态的启动初值；运行中不再读取它作为扩展当前快照。catalog 仍是供加载与诊断消费的稳定目录引用。扩展状态队列串行覆盖整个读／改／保存过程，避免并发动作使用同一旧数组或配置表；persistence 继续串行所有 host.shell 写入和 revision，包括页面与外观；Agent 由其扩展自行串行保存。两个队列各自持有单向依赖，扩展动作通过稳定 save 进入 persistence。

状态只发布已确认的结果，写入拒绝时无需撤回乐观值；未知回执仍由 persistence 锁住后续写入。最终卸载失败时保留实时 imports，同时发布已经确认的 composition 裁剪；路径保存成功后安装失败也保留已确认路径。生命周期、模块目录和扩展数据的原语义保持。

外壳订阅当前视图的 `chrome`，由视图发布标题和默认详情状态。自定义侧栏依次匹配当前实体的扩展所有者、当前工作区所有者，再使用工作区默认详情；同类贡献按 priority 和 ID 确定顺序。自定义侧栏出现时关闭默认 inline 详情；移动端默认详情可用 dialog 呈现，转为桌面后参与互斥。

SDK 的 `errors.ts` 与零依赖 `validation.ts` 提供错误码和字段路径，扩展/主题/组合 ID 规则（`identifier`）与同源判断（`sameOrigin`）只在 `validation.ts` 定义；通用中文错误由外壳 `messages.ts` 映射，业务数据损坏的具体原因由提供者通过 `ContractError.message` 传递，外壳补充数据保留提示而不解析业务字段名。Host 保持字符串诊断接口，由外壳在构造时注入错误格式化回调，在配置、生命周期和清理错误转为字符串前映射；等待原因以结构化 `inspect().wait`（`configuration`/`capability-unavailable`/`permission`/`dependency`/`cycle`）给出，诊断与界面文案只读该结构，`error` 中的英文文本仅供开发日志。已有 Host 调用者继续使用原默认开发诊断。Host 按职责拆分：`definition.ts` 声明校验与加载，`scope.ts` 单次激活的资源作用域，`registry.ts` 服务、视图、主题与事件登记，`context.ts` 构造扩展 `ctx`，`lifecycle.ts` 宿主错误、超时与等待原因，`host.ts` 只保留安装、授权、启停与协调；`host.ts` 不再转发 `loadExtension`。

`chrome` 是可选的框架无关接口。Host 只透传贡献；外壳在消费边界捕获读取、订阅和操作异常，排除失败的视图代并保留管理恢复入口。导航接收方声明实体类型，调用方必须匹配后才传递 ID，避免将 Agent ID 发送给任务等其他工作区。接口和作者示例见 [SDK 作者入口](SDK-AUTHORING.md#工作区标题与上下文侧栏)。

## 原生 IPC 契约

Rust 命令与 wire 类型是 IPC 的来源：[ipc.rs](../src-tauri/src/ipc.rs) 的声明宏同时生成实际函数／serde DTO 和类型元数据；[lib.rs](../src-tauri/src/lib.rs) 的一份清单同时用于 Tauri 注册与编译后导出。构建登记 20 条命令，没有只在测试 feature 中出现的命令。

前端通过 [invokeNative](../src/native/invoke.ts) 调用生成的[契约](../src/native/contract.generated.ts)。命令名、参数、可选字段、响应状态及原生拒绝类型随 Rust 定义导出，调用者不再通过 `invoke<T>` 自行声明响应。AppHandle／State 是原生注入参数，不进入 WebView 参数；命令参数保持 camelCase，实验 Faults 保持既有 snake_case。公共 SDK 不依赖 `src/`，相关声明与生成类型通过编译期兼容样本核对。

`platform_call` 的已确认拒绝返回 `{ code, outcome: "not-committed" }`；状态码由 Rust enum 导出，浏览器与原生适配按同一码映射提示，不匹配英文句子。收到未知错误码或丢失写入回执仍归为 `unknown`，不自动重试；成功写入回执继续胜过派发后的取消。Promise 拒绝对象不被生成入口包装成成功结果。

声明宏只覆盖当前真实 wire 形状；`serde_json::Value` 保持不透明 `unknown`，`&str` 拒绝原因仍是字符串。类型门禁约束正常调用，不替代 Rust 授权／输入校验，也不阻止同一 WebView 中的恶意代码直接调用原生桥接。增加命令与重新生成的方法见[开发流程](DEVELOPMENT.md#修改原生命令)。

## 关键区分

Tauri 原生插件与 Plums 社区动态扩展处于不同层级。前者通过应用原生构建和平台适配集成能力；后者是拟由 Plums SDK 与扩展宿主加载的社区贡献。Tauri 的插件机制不能直接视为 Plums 动态插件系统已经存在。

原生能力如何暴露给动态扩展、哪些贡献需要随应用重新打包、移动端允许何种加载与分发方式，均尚未决定。动态不意味着任意代码下载后在所有平台执行；分发限制需在选型时核对。

## 为后期协作保留通用边界

多 Agent 合作是后期重点，角色卡面向人类理解是绝对重点，也用于 Agent 间联系。前期服务作用域、状态所有权、取消、通信与追踪契约应能区分多个独立参与者，避免假定整个应用只有一个 Agent 或会话；不因此提前实现特定协作编排系统。

建议用通用注册、通信和生命周期契约支持扩展间联系，用明确的状态与权限作用域表达协作边界；发现、匹配、委派、交接与人类接管的领域流程由扩展实现。角色卡格式、模型协议和具体 A2A 标准适配不进入内核；尚未选择特定 A2A 标准或版本。

角色卡拟同时有独立可理解的人类描述与机器协作信息。身份、能力与授权分别验证，不能信任卡片自述就放大权限。呈现与协作验收见 [A13–A14](ACCEPTANCE.md#后期角色卡与多-agent-合作验证方向)。

## 跨平台风险验证

目标覆盖 macOS、Windows、Linux、iOS、Android。共享契约与代码不免除各端适配；不预设 Node.js 可在移动端使用，也不预设桌面扩展能原样迁移。

| 待验证假设 | 拟验证路径 | 失败后的决策方向 |
| --- | --- | --- |
| 候选运行时适配桌面与移动端 | 同一最小扩展在桌面、iOS、Android 验证加载、调用和释放 | 更换运行时、分层执行或声明平台范围；不静默跳过 |
| 前后台切换后生命周期一致 | 真机前台运行、进入后台、系统中断或回收、重新打开 | 明确暂停、检查点恢复和不能承诺持续后台执行的场景 |
| 离线时状态可解释 | 断网启动、执行本地操作、网络服务超时、恢复网络 | 区分本地可用、等待网络及失败；模型推理离线能力不预设 |
| 长任务能够取消或恢复 | 原生环境取消、超时、休眠和强制结束后的恢复 | 收紧资源与执行预算，选原生适配或外部执行方案 |
| 文件访问可表达平台差异 | 用户选择文件、授权拒绝、授权失效、移动端作用域访问 | 使用平台句柄或适配语义；不承诺任意路径和绝对路径可迁移 |
| 共享 UI 能适应目标 WebView | 原生窗口内验证输入、焦点、导航、触控及可访问路径 | 调整前端选型或局部原生实现，保留公开 UI 契约 |

能力探测建议表达可用性、限制与恢复动作，并区分启动时条件和运行中撤权。具体字段与 API 等实验后确定。前后台中断不等于用户停用；持久化状态必须能解释二者的区别。

Android 的原生系统栏与键盘 Insets 由受控 [MainActivity 模板](../native/android/MainActivity.kt) 适配；[外观插件](../native/android/AppearancePlugin.kt) 同步系统栏颜色和图标亮度，两者均不进入扩展宿主。生成工程、构建回调、调试签名及缓存边界见 [Android 工程](ANDROID.md)；复用工具链与下载缓存，Rust 代码生成输出归属当前工作副本。

## 信任与复用边界

采用可信贡献模式，短期不把恶意插件强隔离作为前置条件。若插件与宿主同进程、共享全局环境或得到原生调用能力，其错误和主动行为可能影响宿主和用户数据；来源、审查和权限披露不能消除这些风险。

权限 UI、依赖注入上下文或名为 `isolate` 的机制只代表其实际提供的边界，不能据名称推断安全沙箱。未来若需要运行不可信代码，必须另行验证隔离、权限强制执行及资源约束。近期可执行的信任措施见 [扩展契约](EXTENSION-CONTRACTS.md)。

第三方代码或组件的复用评估需记录具体版本、许可证与依赖义务、Node.js/文件系统/子进程等假设、移动端测试和维护成本。额外组件的复用范围尚未确定；实际引入时须保留必要的许可证与版权声明，现有直接依赖的元数据核对范围见 [M1 实验](M1-EXPERIMENTS.md)。平台技术资料见 [Tauri 2 官方文档](https://v2.tauri.app/)，不能替代 Plums 的验证证据。
