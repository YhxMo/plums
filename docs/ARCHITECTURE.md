# 架构边界与决策状态

[文档索引](../README.md) · [扩展契约](EXTENSION-CONTRACTS.md) · [验收计划](ACCEPTANCE.md)

状态：当前为 0.0.4 / M1 实验。默认 Agent UI、持久化深浅主题与 Android 工程入口已实现；状态输出边界、普通停用/撤权及弹窗焦点修复的版本与覆盖见 [M1 证据](../evidence/RESULTS.md)。M1 已按 Mac 与单配置 Android 模拟器的限定风险范围收敛；M2 整体、五端支持和稳定 SDK 仍未验收。下文区分目标职责与实验选型。

## 目标与边界

目标：本体应支持由插件组合产生未知的服务、UI、业务和新扩展点。内核只承载通用机制，不理解特定 Agent 的业务循环、模型消息协议、角色卡格式或某个示例产品的状态机。公开 SDK 应足以支持贡献者扩展，无需访问私有注册表或修改内核源码。

## 建议的职责划分

| 责任域 | 拟承担的职责与所有权 | 边界与失败行为 |
| --- | --- | --- |
| 小内核 | 加载与生命周期、注册所有权、依赖与组合、持久化及迁移契约、取消与资源管理、可观测性 | 不识别业务对象；激活失败撤回本次部分注册，失败可定位到扩展 |
| 平台适配层 | 平台能力探测、原生调用、前后台事件、文件、权限与凭据作用域 | 明确支持、拒绝、暂不可用或需授权；不把调用失败伪装成功 |
| 扩展宿主与 SDK | 加载兼容检查、扩展上下文、公开扩展点及诊断入口 | 长期运行时和进程模型尚未选定；宿主保证与可信代码自律边界须分别列明 |
| 通用应用外壳 | 承载可替换的主题、布局、导航、页面、交互及扩展管理入口 | 默认 UI 尽量走公开契约；不得要求所有扩展有聊天窗口或正在打开的视图 |
| 插件及其组合 | 提供服务、UI、业务、模型协议、格式解析与新的扩展点 | 拥有自身业务状态；按公共契约声明依赖与清理资源 |

这是一张责任地图，不要求立即拆成五个包或进程。实际模块划分随风险实验调整。通用状态契约约束所有权、持久化与恢复语义；内核不据此保存业务专用数据结构。

## 应用 UI 的扩展边界

目标明确 UI 可通过扩展更改，包含整体布局、导航、页面和交互方式，不限主题或固定插槽。建议默认 UI 与社区扩展共用公开机制，并允许扩展继续提供新的界面扩展点。内核不固定聊天应用布局。

默认布局围绕内容组织、导航和跨端操作设计；扩展可以替换整体 UI，不受默认布局限制。

M1 提供单一布局选择及持久化、受控替换和宿主恢复入口。M2 源码新增可选页面路由助手，复用确定性导航冲突选择与视图树循环检查，支持动态页面贡献、焦点返回与页面偏好保存；作者入口见 [页面契约](PAGES.md)。冻结后的独立页面接入已有浏览器结果，见 [交稿检查](LOCAL-PROOF.md)；完整组合升级、迁移与最终普通原生包继续验收。替换失败时应保留扩展管理和恢复路径；完整恢复、键盘和触控适配需按 [A12](ACCEPTANCE.md#a12-ui-替换专项路径) 验证。

0.0.4 的应用外壳拥有扩展管理、应用内授权、布局与外观偏好、恢复入口；默认 Agent 界面、工作台、画布及各自导航通过公开 `ctx.view` 和 `ctx.use` 挂载，不读取宿主私有业务状态。扩展管理使用独立全幅页面，隐藏业务区时保留工作区挂载和草稿；布局扩展按自身容器宽度重排。外壳的通用控件与扩展样式共享两套语义颜色变量，布局和导航仍由扩展替换，详见 [默认界面](UI.md)。

`agents.local` 是扩展层业务提供者，以 `agents@1` 公开快照、订阅、角色与会话操作；`ui.agents` 通过 `ctx.use`/可选 `withAgents` facade 消费，再用 `ctx.view` 注册默认界面。角色卡解析和文本执行位于扩展模块。`src/shell/runtime.ts` 装配内置组合和串行保存回调，通用 Host、ExtensionContext 与 Rust 桥接不认识 Agent 类型。公开提供者说明用于呈现实际来源、版本与执行范围，外部提供者无需模仿内置实现。

默认组合使用已有文本服务以验证本地执行，尚无语言模型或 MCP 客户端。外部视图启用后优先选中，工作台、画布及默认 Agent 界面仍可独立替换；已实现最小启用集合、精确版本与配置快照；复杂多提供者政策、组合升级事务和长期会话存储未实现。实验角色/会话与外观暂共同存于 `host.shell` 小快照，不把此装配方式冻结为内核数据模型。

建议保留可信授权与安全提示边界，不允许扩展通过公开 API 隐藏必要授权或伪造授权结果。呈现层是否能防止伪装须由实际隔离与 UI 方案证明；同环境可信代码可能仿造界面，不能把这项建议写成已有安全保证。

## 当前前端的状态所有权

`src/App.tsx` 只负责启动结果和加载／恢复界面的选择；`src/shell/Workbench.tsx` 装配各责任域及共享反馈，不持有扩展编辑表单或 Agent 的选中状态。

| 所有者 | 持有的状态与副作用 | 调用边界 |
| --- | --- | --- |
| `src/shell/runtime.ts` | 配置读取校验、扩展装配、组合恢复、串行快照与未知写入锁存 | 保存格式和能力授权语义沿用 `host.shell` 契约 |
| `useWorkspace` | 视图选择、挂载释放、按代排除失败视图、恢复到可用布局 | 复用 `createViewSlot` 和公开 Host 生命周期 |
| `useAppearance` | 外观偏好、主题贡献、DOM 与原生外观同步 | 成功保存后更新偏好；贡献缺失保留选择 |
| `useShellNavigation`、授权与弹窗组件 | 管理页、宿主模态入口、发起控件和返回焦点 | 管理返回在工作区可见后恢复焦点 |
| `src/features/extensions/` | 管理页选中项、安装输入、配置草稿和卸载确认 | 启停、授权和保存仍调用已有公开入口 |
| 各工作区扩展 | 业务选中项、会话、草稿及默认详情开关 | 可选 `View.chrome` 向外壳发布标题和上下文状态 |

外壳订阅当前视图的 `chrome`，不再通过全局 Agent 事件镜像会话标题或默认详情开关。自定义侧栏依次匹配当前实体的扩展所有者、当前工作区所有者，再使用工作区默认详情；同类贡献按 priority 和 ID 确定顺序。自定义侧栏出现时关闭默认 inline 详情；移动端默认详情可用 dialog 呈现，转为桌面后参与互斥。

`chrome` 是可选的框架无关接口。Host 只透传贡献；外壳在消费边界捕获读取、订阅和操作异常，排除失败的视图代并保留管理恢复入口。导航接收方声明实体类型，调用方必须匹配后才传递 ID，避免将 Agent ID 发送给任务等其他工作区。接口和作者示例见 [SDK 作者入口](SDK-AUTHORING.md#工作区标题与上下文侧栏)。

## 关键区分

Tauri 原生插件与 Plums 社区动态扩展处于不同层级。前者通过应用原生构建和平台适配集成能力；后者是拟由 Plums SDK 与扩展宿主加载的社区贡献。Tauri 的插件机制不能直接视为 Plums 动态插件系统已经存在。

原生能力如何暴露给动态扩展、哪些贡献需要随应用重新打包、移动端允许何种加载与分发方式，均尚未决定。动态不意味着任意代码下载后在所有平台执行；分发限制需在选型时核对。

## 为后期协作保留通用边界

多 Agent 合作是后期重点，角色卡面向人类理解是绝对重点，也用于 Agent 间联系。前期服务作用域、状态所有权、取消、通信与追踪契约应能区分多个独立参与者，避免假定整个应用只有一个 Agent 或会话；不因此提前实现特定协作编排系统。

建议用通用注册、通信和生命周期契约支持扩展间联系，用明确的状态与权限作用域表达协作边界；发现、匹配、委派、交接与人类接管的领域流程由扩展实现。角色卡格式、模型协议和具体 A2A 标准适配不进入内核；尚未选择特定 A2A 标准或版本。

角色卡拟同时有独立可理解的人类描述与机器协作信息。身份、能力与授权分别验证，不能信任卡片自述就放大权限。呈现与协作验收见 [A13–A14](ACCEPTANCE.md#后期角色卡与多-agent-合作验证方向)。

## 跨平台风险验证

目标覆盖 macOS、Windows、Linux、iOS、Android。共享契约与代码不免除各端适配；不预设 Node.js 可在移动端使用，也不预设桌面扩展能原样迁移。

| 待验证假设 | 拟验证路径 | 失败后的决策方向 |
| --- | --- | --- |
| 候选运行时适配桌面与移动端 | 同一最小扩展在桌面、iOS、Android 验证加载、调用和释放 | 更换运行时、分层执行或声明平台范围；不静默跳过 |
| 前后台切换后生命周期一致 | 真机前台运行、进入后台、系统中断或回收、重新打开 | 明确暂停、检查点恢复和不能承诺持续后台执行的场景 |
| 离线时状态可解释 | 断网启动、执行本地操作、网络服务超时、恢复网络 | 区分本地可用、等待网络及失败；模型推理离线能力不预设 |
| 长任务能够取消或恢复 | 原生环境取消、超时、休眠和强制结束后的恢复 | 收紧资源与执行预算，选原生适配或外部执行方案 |
| 文件访问可表达平台差异 | 用户选择文件、授权拒绝、授权失效、移动端作用域访问 | 使用平台句柄或适配语义；不承诺任意路径和绝对路径可迁移 |
| 共享 UI 能适应目标 WebView | 原生窗口内验证输入、焦点、导航、触控及可访问路径 | 调整前端选型或局部原生实现，保留公开 UI 契约 |

能力探测建议表达可用性、限制与恢复动作，并区分启动时条件和运行中撤权。具体字段与 API 等实验后确定。前后台中断不等于用户停用；持久化状态必须能解释二者的区别。

Android 的原生系统栏与键盘 Insets 由受控 [MainActivity 模板](../native/android/MainActivity.kt) 适配；[外观插件](../native/android/AppearancePlugin.kt) 同步系统栏颜色和图标亮度，两者均不进入扩展宿主。生成工程、构建回调、调试签名及缓存边界见 [Android 工程](ANDROID.md)；复用工具链与下载缓存，Rust 代码生成输出归属当前工作副本。

## 信任与复用边界

采用可信贡献模式，短期不把恶意插件强隔离作为前置条件。若插件与宿主同进程、共享全局环境或得到原生调用能力，其错误和主动行为可能影响宿主和用户数据；来源、审查和权限披露不能消除这些风险。

权限 UI、依赖注入上下文或名为 `isolate` 的机制只代表其实际提供的边界，不能据名称推断安全沙箱。未来若需要运行不可信代码，必须另行验证隔离、权限强制执行及资源约束。近期可执行的信任措施见 [扩展契约](EXTENSION-CONTRACTS.md)。

第三方代码或组件的复用评估需记录具体版本、许可证与依赖义务、Node.js/文件系统/子进程等假设、移动端测试和维护成本。额外组件的复用范围尚未确定；实际引入时须保留必要的许可证与版权声明，现有直接依赖的元数据核对范围见 [M1 实验](M1-EXPERIMENTS.md)。平台技术资料见 [Tauri 2 官方文档](https://v2.tauri.app/)，不能替代 Plums 的验证证据。
