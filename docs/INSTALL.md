# 安装、升级与回退（macOS）

[文档导航](README.md) · [应用数据目录](ARCHITECTURE.md#应用数据目录) · [开发流程](DEVELOPMENT.md#本地交付目录)

更新日期：2026-10-26。只适用于 Apple Silicon（arm64）的 Mac 包；Intel Mac、Windows、Linux 与手机没有对应的包。开发与实测都在 macOS 27 上，其他系统版本未验证。

## 首次打开

Mac 包使用临时（ad-hoc）签名，没有 Developer ID，也未经 Apple 公证，所以从浏览器或聊天工具下载后，系统会拒绝直接打开（`spctl` 对该包的评估为 rejected）。这是预期行为，不是文件损坏。

1. 把 `Plums.app` 拖进“应用程序”。
2. 双击打开，系统提示无法验证时点“完成”（不要点“移到废纸篓”）。
3. 打开“系统设置 › 隐私与安全性”，滚到“安全性”一节，点 Plums 旁的“仍要打开”，按提示输入密码确认。此后可正常打开。

也可以在终端去掉下载时附加的隔离标记，之后直接双击：

```sh
xattr -dr com.apple.quarantine /Applications/Plums.app
```

只对你信任来源的包这样做。包内附有 `LICENSE` 与 `THIRD-PARTY-NOTICES.txt`（在包上右键“显示包内容”，位于 `Contents/Resources`）。

## 数据与密钥

数据在 `~/Library/Application Support/dev.plums.plums/data`，包括会话、记忆、扩展状态和 API Key。API Key 不进钥匙串：它存在该目录内权限为 0600 的 `credential-secrets.json` 明文文件中，应用界面读不到，但任何能读你用户目录的程序都能读到。不要把这个目录同步到网盘或发给别人。

## 升级

1. 退出 Plums。
2. 用新的 `Plums.app` 替换“应用程序”里的旧版，数据目录不动。
3. 打开。库结构版本较旧时会在打开时原地升级。

升级前建议先复制一份数据目录作备份。

从 0.2.0 升级：0.2.0 用的是改名前的标识，数据在 `~/Library/Application Support/dev.plums.m1/m1-experiment`。新版首次打开时把它整个复制到上面的新目录，旧目录原样保留；复制失败时会弹窗说明并退出，不写新数据，下次打开再试。升级前请先退出 0.2.0：两者标识不同，可以同时运行。

## 回退

换回旧版应用不会回滚数据，而升级后的库旧版不一定能读：遇到未知库版本，旧版会拒绝读写，不会覆盖。因此回退要连同数据一起：

1. 退出 Plums。
2. 换回旧版 `Plums.app`。
3. 把升级前备份的数据目录放回原位。

没有备份时不要回退到更旧的版本；新版本里新增的会话和记忆也不会出现在恢复的备份里。

回退到 0.2.0 是例外：它读的是改名前的旧目录，而升级时那里没有被改动，所以换回 0.2.0 就能看到升级前的数据，只是看不到升级后在新版里新增的内容。

## 卸载

把 `Plums.app` 拖进废纸篓。数据与 API Key 仍留在上面的数据目录里；要彻底清除，退出后删除 `~/Library/Application Support/dev.plums.plums`。

## 已知限制

- 0.2.0 及更早的包是 debug 构建，体积和速度不代表正式版；0.3.0 起是 release 构建。
- release 构建保留了网页检查工具：在窗口里右键可以打开“检查元素”，便于排查扩展问题。它能看到界面里的内容，但看不到 API Key（密钥只在原生层）。
- 没有公证，首次打开需要上面的步骤。
- 屏幕阅读器（VoiceOver）没有做验收，不保证可用。
- 扩展是本地可信代码，与应用在同一个 WebView 中运行，没有安全沙箱，只安装你信任来源的扩展，见[信任边界](../README.md#信任边界)。
- 与模型服务的兼容范围受限：带输出上限的真实调用、长上下文、图片与思考强度在各家服务上的表现没有逐一验证，具体未验项见 [HANDOFF](../HANDOFF.md#未验范围)。
- 单实例：再次启动只会聚焦已打开的窗口。
- 编程类订阅（如 OpenCode Go）不在支持范围内：它们限定给编程工具使用，并要求 Plums 目前发不出的会话头；请使用按量计费的 API。
