## 入口、验证与修改边界

| 保留项                                                            | 依据                                                                                                  | 理由                                                                                           |
| ----------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| core/CLI Node.js 22+；桌面构建 Node.js 26.5.1、pnpm 10、Xcode CLT | 各包 `package.json`、`scripts/package-desktop.mjs`、`scripts/build-host-native.mjs`                   | 原生模块、Electron 和打包运行时需要匹配，CLI 的最低版本不足以代表桌面构建环境。                |
| core、CLI、SDK、host、desktop 与外装组件的职责                    | 各包 `src/index.ts`、`packages/cli/src/main.ts`、`packages/host/src/sdk-bridge.ts`                    | 公开 API 和可信执行边界决定功能接入位置；业务协议可在连接器实现，凭据和真实 I/O 仍由宿主控制。 |
| CLI 的内存密钥和记录式外发限制                                    | `packages/cli/src/main.ts`                                                                            | CLI 成功不证明真实联网或密钥持久化，验收需要区分记录式适配器和实际宿主。                       |
| 先核对实现，再参考文档和路线图                                    | `docs/architecture.md`、`docs/capabilities.md`、`docs/desktop.md`、`docs/sdk-v2.md`、`docs/engine.md` | 规划、独立工作树和未接入文件不能证明主线已有可用能力。                                         |
| 构建、定向测试、桌面打包及两种 smoke                              | 根 `package.json`、`vitest.config.ts`、`scripts/desktop-smoke.mjs`、`scripts/engine-smoke.mjs`        | CLI 和隔离子进程读取 `dist`；原生确认依赖焦点，确认测试与 smoke 必须顺序运行。                 |
| 自造夹具、临时数据、并发、重启、迁移和恢复覆盖                    | core/host 测试、桌面原生测试、smoke 脚本                                                              | 授权和事务错误可能只在等待、跨进程或重启时出现；测试不得接触真实凭据和业务数据。               |
| 性能基准、缓存边界与错误优先级                                    | `docs/performance.md`、core 设置校验和 `install/store.ts`、性能回归测试                               | 时间和内存受环境影响；语句复用不能缓存授权结果，设置变更和密钥刷新必须即时生效。               |
| 公开 API、JSON Pointer、错误脱敏、保留独有断言                    | core 的 `index.ts`、`errors.ts` 和契约测试                                                            | 这些是调用者可观察的兼容行为，不能因内部去重而删除；最终组合须重新验证。                       |
| 生成目录和用户数据不提交、许可边界                                | `.gitignore`、`LICENSE`                                                                               | 构建产物可再生，运行数据和密钥不能进入源码仓库；Apache-2.0 项目不复制 AGPL/GPL 实现。          |

## 必须保持的契约

编号对应 `AGENTS.md`。下表中的 core 路径位于 `packages/core/src/`。

| 编号                                            | 主要依据                                                                                         | 保留理由                                                                                                |
| ----------------------------------------------- | ------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------- |
| 1：不透明 payload、声明权限、未知字段和格式版本 | `package/schema.ts`、`package/export.ts`、格式与包内容测试                                       | 角色内容不能生成权限，往返导出不能丢失第三方字段或改变输入格式。                                        |
| 2：1.x 动作与 MCP 批准                          | `actions/run-action.ts`、`mcp/tools.ts`、`mcp/tools-v2.ts`、MCP 指纹测试                         | 历史格式仍有公开入口；确认后必须复核，工具消失或 schema 变化不能沿用旧批准。                            |
| 3：密钥引用、更新后清理和重试                   | `install/settings.ts`、`install/lifecycle.ts`、`install/store.ts`、密钥清理测试                  | 移除字段后的引用仍须可清理，已提交更新不能被清理错误伪装为未发生，失败不得泄漏密钥。                    |
| 4：ZIP 检查、staging、唯一键与失败隔离          | `package/read-zip.ts`、`package/export.ts`、`install/lifecycle.ts`、并发导入测试                 | 路径冲突可能越界或覆盖文件；失败方不能删除并发成功方或发布半成品。                                      |
| 5：设置预校验与残留设置                         | `install/check-settings.ts`、`install/settings.ts`、设置契约测试                                 | 无 schema 时不读取残留内容；有 schema 时先校验，更新失败保留可用旧版和公开错误区别。                    |
| 6：精确权限、增权重同意与迁移                   | `package/schema.ts`、`capabilities/run-capability.ts`、`install/store.ts`、格式与迁移测试        | write 不隐含 read，未知字段不生成授权；迁移须保留数据和批准，数据库数字不是永久规则。                   |
| 7：请求复制、确认、审计与再次复核               | `capabilities/request.ts`、`run-capability.ts`、`task-scope.ts`、host 的 `host.ts`、权限复核测试 | 异步等待期间状态和目录会变化；桌面重建 core 不能降低策略，任务范围不能超出声明或绕过撤销。              |
| 8：最小审计与真实执行状态                       | `capabilities/run-capability.ts`、`sink-failure.ts`、审计脱敏和失败状态测试                      | 审计不能成为数据外泄出口；unknown/completed 自动重发可能重复产生副作用。                                |
| 9：前端与普通业务 JS 隔离                       | desktop 的 `main.ts`、host 的 `runtime.ts`、`worker.ts`、运行时与前端隔离测试                    | 扩展不能取得管理接口、Node 对象或直接联网，无限循环不能阻断停止和恢复。                                 |
| 10：真实 I/O、凭据绑定和生命周期                | host 的 `io.ts`、原生目录句柄适配器、网络及目录边界测试                                          | 元数据检查不能替代执行时边界；DNS、TLS 和重定向需要约束，配置变化必须停止旧绑定。                       |
| 11：不可变公共库、显式更新和 Agent 隔离         | host 的 `library.ts`、`assembly.ts`、`host.ts` 及相关测试                                        | 入库不等于执行授权，自动替换版本或共享运行数据会改变已审阅内容并串 Agent。                              |
| 12：集中配置、直接使用、继续组装和通用状态页    | host/desktop 的 onboarding 测试、`AgentSetup.tsx`、SDK 设置模块                                  | 非程序员可以导入完整 Agent，空 Agent、无卡或无前端仍须可管理，简化流程不能跳过授权。                    |
| 13：SDK v2 通用 HTTPS 与外装模型协议            | `packages/sdk/src/desktop-v2.ts`、host 的 `connection-service.ts`、连接器协议及连接测试          | 宿主固定目标和凭据，连接器负责协议；旧绑定失效与真实响应校验防止伪造执行状态或跨组件借用凭据。          |
| 14：可信本机引擎的独立授权与监管                | core 的 `install/engine-trust.ts`、host 的引擎模块、引擎及确认窗口测试                           | 普通本机权限不能冒充 isolate 沙箱；启动必须先批准并保存授权，撤权、崩溃与关停要阻止请求和清理后代进程。 |

## 模型和交付规则

| 保留项                                            | 依据                                                                               | 理由                                                                                                             |
| ------------------------------------------------- | ---------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 协议、模型名称、Base URL、API Key；目标随配置绑定 | `examples/model-connector/manifest.json`、`runtime/endpoint.js`、host 连接服务测试 | 用户切换服务商不应修改 manifest 白名单；模型名称自由填写，凭据和授权仍绑定实际目标。                             |
| 文本优先、工具可选、按已验证协议说明兼容范围      | 连接器协议测试、聊天运行时和交互测试                                               | 普通文本模型不一定支持函数工具；四项配置不能自动适配生图、TTS 或所有私有协议，分组和官网目录不属于当前基础要求。 |
| 本地模型密钥不依赖钥匙串                          | `packages/host/src/secrets.ts`、host/desktop 的本地密钥测试                        | 已确定的本地使用流程不需要系统授权弹窗；文件权限、原子写入、引用、脱敏和导出约束仍不可省略。                     |
| 最新宿主与完整 Agent 两份交付，证据另存           | 打包与示例脚本、本地交付要求                                                       | 防止误装旧版本；清理生成副本不能影响源码、运行数据、个人助理依赖和有效验收记录。                                 |

- 将固定数据库数字改为从实现读取。整合主线当前为 schema 5；未完成的服务迁移工作树为 6，不能把该工作树当作主线能力，也不能为保持旧数字而回退迁移。

- 保留普通 core、桌面有限任务范围和本机引擎的不同执行边界；删除会话派工、模型分配、临时日志路径、重复批次计划和已失效的待合并状态。修改规则不代表撤销已实现功能。
- 规则的证据和理由集中在本文件，不写入 `AGENTS.md`；功能性设计与兼容说明仍留在对应文档。
