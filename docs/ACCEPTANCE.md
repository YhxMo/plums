# 可扩展本体验收计划

[文档导航](README.md) · [契约草案](EXTENSION-CONTRACTS.md) · [开发流程](DEVELOPMENT.md)

状态：当前有效（2026-10-17 核实）；下表是整体目标矩阵，不能把 M1 的部分实验视为整项通过。已执行命令与源码版本见 [证据](../evidence/RESULTS.md)；完整未知作者接入、跨平台、升级恢复与后期协作仍未完成；macOS 仅验证 M1 最小原生路径。

核心问题：没预设的新需求能否主要通过新增或组合扩展完成，同时保持声明的安全边界和兼容性？通过几个示例产品或补齐既有缺口，不能证明愿景已经实现；以下矩阵同样需要持续接受新反例。

## 可证伪矩阵

每项执行前指定单一负责人、候选版本和目标平台；缺少条件时记录阻塞，不标记通过。

| 编号与检验目标 | 拟执行场景 | 通过条件 | 可证伪条件 |
| --- | --- | --- | --- |
| A1 公开 SDK 可独立接入 | 未参与内核实现的作者仅用公开文档、SDK 和样板接入扩展 | 能安装、配置、运行、诊断并发布可复现接入说明；不需要私有 API | 必须逐个请维护者修改内核、提供私有注册入口或补内部知识才能运行 |
| A2 未预设需求与内核边界 | 基线冻结后，由独立贡献者提出此前未内置的需求并实现扩展；比较前后内核 | 主要通过新增或组合扩展完成，扩展代码不依赖内核私有实现 | 为该用例硬编码业务分支、偷用私有状态，或只演示已有样例 |
| A3 非聊天 UI | 扩展提供以列表、画布或其他交互为主体的界面，且能继续提供 UI 扩展点 | 核心不要求聊天会话或消息协议；其他扩展可按契约组合 | 只能在聊天框中输出，或新增扩展点必改内核工具槽位 |
| A4 无 UI 的事件驱动 | 不打开业务视图，由声明的事件驱动服务工作；验证启动、暂停及重启 | 在声明执行条件下运行，取消和恢复状态可解释；不依赖视图挂载 | 视图关闭后监听泄漏、业务意外失效，或移动端被回收却显示仍在运行 |
| A5 依赖替换与组合 | 两个作者的提供者实现同一契约；消费者更换提供者并装入组合配置 | 无需改消费者或内核；缺失、循环、版本冲突均可诊断 | 依赖具体实现、隐式加载顺序或全局单例；替换后悬空引用或重复工作 |
| A6 停用与卸载 | 运行中反复激活、停用和卸载扩展，含依赖失效与清理超时 | 本地注册、视图、监听和任务按契约清理；数据去留和外部副作用明确 | 重复回调或残留任务，清理失败却报成功，或声称撤销未撤销的外部操作 |
| A7 持久化、升级与恢复 | 保存状态后重启、升级扩展、制造迁移失败或中断写入，再恢复 | 状态版本与所有权明确；失败保留可恢复数据并给出诊断 | 读取或迁移失败被当作空数据覆盖，升级后无法说明数据去向 |
| A8 能力不可用时降级 | 拒绝或撤销权限、断网、缺少原生能力、资源不足 | 探测到限制，明确拒绝/等待/降级及恢复动作；无假成功 | 只按平台名猜能力、无限重试，或无权限仍绕过契约调用 |
| A9 扩展机制演进 | 升级 SDK/扩展点版本，测试兼容、不兼容和配置迁移组合 | 有可执行兼容策略，拒绝不支持版本，废弃路径可诊断 | 文档宣称兼容但行为变化无迁移，或用业务特例绕过版本判断 |
| A10 信任与凭据边界 | 检查安装/升级披露、凭据作用域、日志脱敏、停用与审计路径 | 声明与实际保证一致；无关扩展不会由公开契约获得全局密钥 | 把 DI isolate/权限 UI 称安全沙箱，日志暴露密钥，或隐瞒宿主共享环境风险 |
| A11 五端实际条件 | 对目标平台分别测试原生启动、扩展加载、存储、文件授权、离线、长任务及前后台 | 每个平台有实际产物/设备证据与能力范围，未覆盖项明确 | 用桌面结果、浏览器模拟或跨编译代替其他平台通过 |
| A12 应用自身 UI 替换 | 依下节完整路径更换默认布局、导航和交互，再停用恢复 | 公开契约可完成明显不同的非聊天体验，恢复路径可用 | 仅换色/加按钮、硬编码聊天布局、需私改内核或停用后界面不可操作 |
| A13 人类理解角色卡 | 按后期方案让人类仅凭描述与可见信息判断 Agent 的用途、能力边界与联系条件 | 人类可读内容完整且与机器协作信息一致；理解标准先定义，声明与验证/授权分开 | 只有机器字段、必须读源码才能理解，或把卡片自述当作身份与授权证明 |
| A14 后期多 Agent 合作 | 按后期方案组合不同作者的 Agent，观察联系、协作、失败和人类参与 | 主要依公开扩展机制完成，状态与权限边界清晰，人类可理解协作进展 | 内核写死某协作循环、单 Agent 全局状态串扰、失败/取消无法归属或人类无法了解正在发生什么 |

若 A2 暴露缺失的通用能力，应先记录该阶段失败与缺口，再按通用契约演进处理并建立新基线；不能补改内核后仍将原实验称为“无内核修改通过”。未知需求不要求无限支持，拒绝或延期须明确原因及能力边界。

## A12 UI 替换专项路径

1. 冻结内核、SDK 与默认 UI 基线，记录真实原生启动和扩展管理入口。
2. 独立扩展通过公开契约替换主题、整体布局、导航、页面及交互；至少形成一种明显不同的非聊天界面，而非保留原布局只加控件。
3. 组合另一个作者的 UI 贡献与递归扩展点，制造布局、导航或快捷键冲突，检查选择、优先级和诊断。具体规则先设计后测试，不预设已经有 API。
4. 保存布局、重启并升级扩展；模拟配置过期、扩展缺失与迁移失败，检查持久化与恢复。
5. 停用或卸载替换扩展，验证视图、路由、监听与输入绑定被清理，恢复到可用界面，且能再次进入扩展管理；清理失败有准确状态。
6. 在原生窗口/设备中分别操作键盘、触控及不同屏幕尺寸，验证焦点、导航和主要任务路径；记录不支持的平台或输入方式。
7. 核对授权和安全提示的真实归属、可绕过范围与公开声明。若无法防伪装，记录限制并收紧保证，不以可信模式宣称强隔离。

## 后期角色卡与多 Agent 合作验证方向

A13–A14 对应已确认的后期重点；具体场景、样本与通过阈值在设计时定义，不将下列建议当作当前交付承诺：

- 人类不读源码或机器字段说明，也能解释 Agent 适合做什么、不能做什么、如何联系、何时需要授权；用实际任务提问检验理解。人类描述与机器信息冲突时有明确处理方式。
- 不同作者的 Agent 发现联系与匹配能力，通过扩展完成委派或交接；卡片不自动获得可信身份与操作权限。
- 共享状态边界、任务失败、超时与取消可定位到参与者；不依赖应用只有一个 Agent 的假设。
- 人类可通过可扩展 UI 查看参与者、分工和进度，按后期选定方案介入或接管；停用相关扩展后没有无法解释的残留协作。

A2A 在此泛指 Agent 间联系协作。没有选择特定协议或标准版本，角色卡也不被默认视作其 Agent Card。酒馆功能不是官方验收产品；只完成该用途不能通过 A13–A14。前期仅检查通用契约是否锁死单 Agent，完整协作实验留在后期阶段。

## 证据记录要求

每条实际执行记录包含以下内容；未执行项不得填写成功结果：

| 字段 | 记录内容 |
| --- | --- |
| 对象与负责人 | 验收编号、工作单、单一负责人、执行者和独立审查者 |
| 版本 | Git 提交与工作区差异；无 Git 时为受验文件集合的内容摘要；宿主、SDK、扩展与配置版本 |
| 平台与产物 | 系统、架构、设备或模拟器、WebView/运行时版本、开发或打包产物标识 |
| 复现 | 前提、固定输入、实际命令或用户操作步骤、预期与反例 |
| 结果 | 执行时间、退出码或实际观察、必要日志/截图位置，明确通过、失败、阻塞、跳过或未验证 |
| 限制 | 未覆盖项、外部依赖、能力边界和与其他平台结果不能互推的部分 |

影响行为的后续变更会使相关旧记录不能证明新版本。文档检查只证明文本结构、链接及表述一致，不证明 SDK、插件机制、UI 或五端能力。
