# 无业务视图事件服务的执行边界

状态：当前有效（2026-10-17 核实）；M2 限定实现，仅前台存活条件有效，不含系统后台与任务持久队列。

本阶段使用已有公开 SDK `on/emit/task/platform` 与 Host 的 `start/stop/grant`。扩展不注册或挂载视图，测试页只负责管理和观察；执行条件是前台 WebView 进程仍存活，不承诺系统后台、系统回收后运行或任务持久队列。

暂停采用 stop：取消本代任务并释放监听；start 创建新一代，重新订阅，业务内存计数重置。不缓存旧上下文或服务引用。撤权经 grant(id,[]) 停止需该能力的扩展，保持 desired 意图并等待授权；重新授予后自动协调恢复。停用会清除 desired，因此停用后单独授权不等于启动。

事件同步派发且无持久化、排队、确认或自动重试。无监听时事件丢弃。异步工作必须登记 ctx.task 并捕获其拒绝；task 提供生命周期 signal，作者仍负责合作取消和外部副作用边界。旧 emit 静默不派发，旧 task/on/platform 不可继续工作。

限定样板声明 state.read，收到 event.submit 后启动受跟踪任务，读取自身状态作用域；不写数据。样板每代最多一个在途任务，忙时返回 busy，由扩展定义业务容量策略，不表示 Host 已有强制资源配额。hold 用于验证取消，任务取消不发送 done；正常完成返回回执。停止后无事件接收，重启不重复订阅。失败应保持可观测，清理失败由 Host 锁存，不能盲目再启动。

验证先建立未授权、忙碌拒绝、取消、旧引用、恢复及清理失败反例。单元使用模拟平台，浏览器使用真实预览适配，两端专项包调用原生 state.read 与授权桥接；各自结果必须单独留证。不以无业务视图等同于无 WebView 或 OS 后台服务。

限定实现见 [独立样板](../tests/fixtures/event-worker.ts)，浏览器与两端实际结果、单元故障注入及未验项见 [验收证据](../evidence/EVENT-SERVICE-2026-10-16.md)。原生取消发生在读取完成后的等待任务；不代表原生读在途撤回。
